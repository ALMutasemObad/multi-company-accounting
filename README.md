# النظام المحاسبي متعدد الشركات

نظام مالي عربي قيد التطوير، مبني كمستودع موحد بأسلوب Modular Monolith. يحتوي المستودع على API باستخدام Express وPrisma، وواجهة React، وعقد OpenAPI مرجعي.

## الحالة الحالية

أصبحت النواة الخلفية تدعم:

- المصادقة الآمنة، CSRF، تدوير الجلسات، قفل الحساب، تسجيل الخروج وإدارة الجلسات، واستعادة كلمة المرور برمز أحادي الاستخدام مع إلغاء الجلسات السابقة.
- تسجيل ذاتي عام ينشئ طلبًا قابلًا للاستئناف، ويتحقق من البريد قبل تجهيز المؤسسة والشركة والمدير الأول ودليل الحسابات ذريًا، مع منع تعداد الحسابات وحد محاولات وسجل أمان.
- الشركات وسياق الشركة والعزل الكامل للبيانات بينها.
- المستخدمين والأدوار والصلاحيات وسجل التدقيق.
- شاشة تشغيلية لسجل التدقيق مع البحث والتصفية حسب المستخدم والإجراء والكيان والتاريخ، وعرض التفاصيل، وتصدير CSV آمن ومسجل تدقيقيًا.
- سجل أمان مستقل للمصادقة وقفل الحسابات والجلسات، مع درجات خطورة، تنبيهات غير مقر بها، مرشحات، وسجل لمن راجع التنبيه.
- السنوات والفترات المالية وإغلاقها وإعادة فتحها.
- التسلسلات الذرية لأرقام المستندات.
- دليل حسابات افتراضي عام للمنشآت الصغيرة يُنشأ تلقائيًا للشركة الجديدة، ويمكن إكماله للشركة القائمة وتخصيص أرقامه وأسمائه وبنيته أو حذف الحسابات غير المستخدمة، مع أنواع الحسابات ومراكز التكلفة.
- عملات مستقلة لكل شركة مع كتالوج مرجعي وإمكانية إنشاء عملات خاصة معزولة، وأسعار صرف مؤرخة ومدققة، واقتراح السعر النافذ تلقائيًا حسب تاريخ المستند.
- دعم مرجعي للريال اليمني `YER`، مع تفعيله للشركة عبر إعدادات العملات بعد تشغيل Seed المرجعيات.
- القيود اليومية اليدوية: المسودة، التعديل، الترحيل، الإلغاء والعكس.
- العملاء وعناوينهم والصناديق والحسابات البنكية وطرق الدفع، مع توليد رموزها المرجعية تلقائيًا وثباتها بعد الإنشاء.
- سندات القبض وتوزيعاتها وترحيلها المحاسبي وإلغاؤها وعكسها.
- فواتير المبيعات والإشعارات الدائنة ببنود وخصومات وضريبة قيمة مضافة، مع الترحيل والعكس وربط التحصيلات بالفواتير وتقارير الأرصدة وأعمار الديون.
- فواتير المشتريات والإشعارات المدينة ببنود مصروفات أو أصول وخصومات وضريبة مدخلات، مع الترحيل والعكس وربط سندات الصرف بالفواتير المفتوحة وتقارير أرصدة الموردين وأعمار الديون.
- الموردون وعناوينهم وحساباتهم الدائنة، مع توليد رموز الموردين ومراكز التكلفة ومعدلات الضريبة والأدوار المخصصة تلقائيًا، وسندات الصرف وتوزيعاتها وترحيلها وإلغاؤها وعكسها.
- لوحة تحكم مالية مرتبطة بالبيانات الفعلية تعرض المقبوضات والمدفوعات وصافي التدفق والمسودات وأحدث النشاطات.
- تقارير مالية حسب نطاق تاريخي تشمل التدفق النقدي الشهري وميزان المراجعة مع تنزيل CSV.
- تقرير دفتر يومية تشغيلي بمرشحات التاريخ ونوع المستند والحالة والحساب والبحث، مع الترقيم والإجماليات المتوازنة وتصدير CSV عربي مدقق.
- المركز المالي وقائمة الدخل مع المقارنة، وفحص المعادلة المحاسبية، وكشف الأستاذ، وتصدير CSV وExcel وPDF عربي.
- واجهة تشغيلية عربية وإنجليزية تشمل لوحة التحكم والتقارير والعملاء والموردين وفواتير المبيعات والمشتريات وسندات القبض والصرف والسنوات والفترات المالية والقيود اليومية ودليل الحسابات ومراكز التكلفة والخزينة وطرق الدفع، مع دعم RTL/LTR والشاشات الصغيرة.
- واجهة إدارية للمستخدمين والبحث والتصفية والترقيم والإنشاء والتعديل والتعطيل، وإسناد الأدوار، وإدارة الأدوار المخصصة وصلاحياتها، ومراجعة الجلسات الشخصية وإلغائها.
- إعدادات الشركة الأساسية وضابط فصل منشئ القيد اليدوي عن مرحّله، مع حماية الأدوار النظامية وإبطال الجلسات المتأثرة وتسجيل جميع التغييرات الحساسة.
- طباعة PDF عربية لسندات القبض والصرف والقيود اليومية وفواتير المشتريات والإشعارات المدينة من لقطة تاريخية ثابتة، مع بصمة SHA-256 وعدّاد إعادة الطباعة وصلاحيات مستقلة وسجل تدقيق.
- `PostingEngine` مركزي يملك إنشاء القيود المرحلة وعكسها، و`TransactionExecutor` موحد بمهلة مشتركة وbackoff+jitter وتصنيف صريح لتعارضات MariaDB/MySQL، مع Idempotency واختبارات تزامن وعزل على المحركين.
- عناصر `ReceivableItem` و`PayableItem` مملوكة لـAR/AP تحمل الرصيد والحالة والنسخة؛ تخصص Treasury القبض والدفع إليها عبر منافذ داخل المعاملة بدل كشف معرفات أسطر الأستاذ.
- وحدة `Tax` مالك وحيد لنسب الضرائب وحسابات المدخلات والمخرجات؛ تستهلكها المبيعات والمشتريات عبر `TaxQuotePort` وحاسبة Decimal واحدة، وتحمي التعديلات بـ`version` متفائلة.
- وحدة `Treasury` مالك وحيد لحسابات الصندوق والبنك وطرق الدفع؛ يستهلك القبض والدفع أدواتها عبر `TreasuryInstrumentPort`، وتحمي التعديلات والتعطيل بـ`version` متفائلة مع عزل الشركة.
- سياق طلب موحد ينقل `deadlineAt` و`AbortSignal` من HTTP إلى المعاملات من دون إعادة ضبط الميزانية، ويمنع النجاح المتأخر، مع مهلات Node صريحة وPrometheus metrics محمية وتنبيهات للـdeadlocks والـdeadlines وOutbox.
- حارس عقد آلي يطابق OpenAPI مع 151 عملية HTTP فعلية، وحدود طلب تعيد أخطاء تحقق آمنة بمعرّف تتبع بدل تحويل مدخلات المصادقة أو JSON غير الصالح إلى خطأ داخلي.
- OpenAPI 1.12.0 عقد JSON تنفيذي موحد: مولد حتمي يغطي أجسام الطلبات الـ77 ومخططات الاستجابة الـ1059 عبر العمليات الـ151، مع أنواع TypeScript وحراس Zod وتحويل BIGINT الآمن وبصمة SHA-256 وفحص CI يمنع التقادم أو رجوع مخطط يدوي موازٍ. يفحص التطبيق أجسام الاستجابة ورموز حالاتها في التطوير والاختبار.
- تعدد لغات مكتمل للواجهة بقواميس عربية وإنجليزية منفصلة ومفاتيح typed، مع حفظ الاختيار وتبديل RTL/LTR وتنسيقات اللغة وبوابة CI تمنع النصوص الصلبة ومفاتيح الإعداد المرئية؛ آلية إضافة لغة وأسماء المرجعيات موثقة في [دليل تعدد اللغات](docs/localization.md)، وقواعد النص والتجاوب الإلزامية في [سياسة محتوى الواجهة والتجاوب](docs/UI_CONTENT_RESPONSIVE_POLICY_AR.md).
- بوابة E2E بـPlaywright/Chromium تغطي التسجيل والتحقق والدخول وتبديل اللغة وإنشاء عملة وسعر صرف وسنة مالية وأول قيد يدوي متوازن، وتعمل على MariaDB وMySQL قبل إصدار الحزمة.
- بوابة متصفح مستقلة تعيد فحص 168 حالة واجهة متجاوبة حتميًا (19 شاشة ونافذتا الفواتير، بالعربية والإنجليزية وعلى 390/768/1440/1920) وتمنع النشر عند تمدد الواجهة أو التفاف البحث والتبويبات أو تسرب نص تشغيلي.

التفاصيل المرحلية الكاملة موجودة في [حالة التنفيذ](docs/implementation-status.md)، وخطة العملات والتسجيل والترجمة والفحص البصري في [خارطة التطوير](docs/product-roadmap.md).

## بنية المستودع

- `apps/api`: خادم Express وخدمات الأعمال ومخطط Prisma والاختبارات.
- `apps/web`: واجهة React/Vite العربية الأولية.
- `packages/contracts`: عقد OpenAPI المرجعي.

## المتطلبات

- Node.js 22 أو أحدث.
- npm.
- MariaDB من XAMPP للتطوير المحلي؛ ويدعم الإنتاج MySQL 8.4 LTS أو MariaDB 10.11 بعد اجتياز البوابة المطابقة.

MariaDB 10.4 في XAMPP مستخدمة للتطوير المحلي. سلسلة الترحيلات والـSeed وجميع اختبارات قاعدة البيانات يتم التحقق منها من قاعدة فارغة على MySQL 8.4.11، وتوجد بوابة مستقلة مطابقة لاستضافة iFastNet على MariaDB 10.11.11 وNode.js 22.23.2.

## التشغيل المحلي باستخدام XAMPP

1. شغّل MySQL/MariaDB من لوحة XAMPP.
2. انسخ `.env.example` إلى `.env` وعدّل بيانات الاتصال وكلمة مرور Seed.
3. ثبّت الاعتماديات:

   ```bash
   npm install
   ```

4. ولّد Prisma Client:

   ```bash
   npm run prisma:generate
   ```

5. طبّق الترحيلات وشغّل البيانات الأولية:

   ```bash
   npm exec -w @mcap/api -- prisma migrate deploy
   npm run prisma:seed -w @mcap/api
   ```

6. شغّل المشروع:

   ```bash
   npm run dev
   ```

- API: `http://localhost:3000`
- الواجهة: `http://localhost:5173`
- فحص الحياة: `GET http://localhost:3000/live`
- فحص جاهزية التطبيق وقاعدة البيانات: `GET http://localhost:3000/ready`
- القياسات التشغيلية عند تفعيل `METRICS_ENABLED`: `GET http://localhost:3000/metrics`

حساب التطوير بعد تشغيل Seed هو `admin@mcap.local`. كلمة المرور تؤخذ من `SEED_ADMIN_PASSWORD` في ملف `.env` المحلي، ولا تدخل Git.

## التسجيل الذاتي واستعادة كلمة المرور والبريد

يكون التسجيل الذاتي مفعّلًا افتراضيًا في التطوير. يعرض رابط «إنشاء حساب وشركة جديدة» رحلة عربية/إنجليزية لا تنشئ أي مستأجر أو مستخدم قبل التحقق من البريد. يوضع رمز التحقق في جزء `#` من الرابط حتى لا يصل إلى سجلات HTTP، ولا يُخزن في قاعدة البيانات إلا كبصمة SHA-256. بعد التحقق تُجهّز الشركة والمدير والدور والصلاحيات ودليل الحسابات، ويُمسح Hash كلمة المرور من طلب التسجيل لأن النسخة المعتمدة أصبحت في سجل المستخدم.

يحفظ بدء التسجيل وإعادة الإرسال حدث `RegistrationVerificationRequested` في `outbox_events` داخل معاملة الطلب نفسها، ثم يرسله عامل داخلي بعد الالتزام مع lease ذري وretry محدود وexponential backoff مع jitter. لا يحتوي الحدث بريدًا أو رمزًا؛ يُشتق رمز ثابت لكل حدث بمفتاح `REGISTRATION_TOKEN_SECRET` مستقل، ولا يبقى في قاعدة البيانات إلا Hash الرمز. لهذا لا يُفقد البريد عند سقوط العملية بعد الالتزام، وتبقى إعادة المحاولة صالحة وآمنة.

في التطوير يحاكي `REGISTRATION_EMAIL_MODE=log` الإرسال من دون طباعة البريد أو رابط التحقق في السجل. عند الحاجة إلى الرابط للاختبار اضبط `REGISTRATION_EMAIL_CAPTURE_PATH` على ملف JSONL محلي محمي. في الإنتاج يفشل التطبيق مبكرًا إذا كان التسجيل مفعّلًا من دون `REGISTRATION_EMAIL_MODE=resend` و`REGISTRATION_EMAIL_FROM` و`RESEND_API_KEY` و`REGISTRATION_AUDIT_PEPPER` و`REGISTRATION_TOKEN_SECRET` عشوائيين مستقلين. يمكن تعطيل الميزة صراحةً عبر `SELF_REGISTRATION_ENABLED=false`. مدة الرابط وحد الطلبات تضبطان عبر `REGISTRATION_TOKEN_TTL_HOURS` و`REGISTRATION_RATE_LIMIT_MAX`، وسياسة العامل عبر متغيرات `OUTBOX_*` في ملف البيئة النموذجي.

تعيد «نسيت كلمة المرور» الاستجابة العامة نفسها سواء كان الحساب موجودًا أم لا، ثم تحفظ `PasswordResetRequested` مع الطلب داخل معاملة واحدة. يرسل العامل الرابط بعد الالتزام؛ لا يخزن الرمز الخام، ويلغي طلب جديد كل الروابط المعلقة الأقدم. الرمز أحادي الاستخدام، وبعد نجاح التغيير تلغى جميع جلسات المستخدم ولا يحدث دخول تلقائي. تضبط الميزة عبر `PASSWORD_RESET_ENABLED` و`PASSWORD_RESET_RATE_LIMIT_MAX` و`PASSWORD_RESET_TOKEN_TTL_MINUTES`. عند تفعيلها في الإنتاج تلزم إعدادات Resend وعنوان المرسل و`REGISTRATION_TOKEN_SECRET` حتى لو كان التسجيل الذاتي معطلًا.

تستخدم E2E ملف JSONL مؤقتًا لالتقاط رسالة التحقق عبر `REGISTRATION_EMAIL_CAPTURE_PATH`. هذا المتغير اختبار فقط، ويرفض محمل الإعدادات تشغيل الإنتاج إذا كان مضبوطًا؛ لا تضفه إلى ملفات بيئة النشر.

## تجهيز شركة جديدة

تدعم النواة هوية مستخدم عالمية مع إسناد وأدوار مستقلة لكل شركة. تُنشأ الشركة الإنتاجية بأمر إداري ذري ومتكرر التشغيل من دون بيانات Demo:

```bash
npm run company:provision
```

تُمرر قيم `PROVISION_*` مؤقتًا من مدير الأسرار، ويجب أن تطابق قيمة التأكيد `CREATE:<ORGANIZATION_CODE>/<COMPANY_CODE>`. لا يغير الأمر كلمة مرور مستخدم موجود عند إسناده إلى شركة إضافية، وينشئ للشركة الجديدة دليل الحسابات الافتراضي دون Demo Seed. أي دمج ناجح إلى `main` ينشر تلقائيًا إلى iFastNet بعد بوابتي MariaDB وMySQL ونسخة إنتاج مشفرة؛ التفاصيل وإعدادات PM2 وNginx موجودة في [دليل التشغيل الإنتاجي](docs/production-operations.md)، ومسار الاستضافة الحالية موثق في [دليل iFastNet cPanel](docs/ifastnet-cpanel-deployment.md).

مهلات HTTP والتطبيق والمعاملة مرتبة من الخارج إلى الداخل، و`/metrics` اختياري ومحمي برمز مستقل في الإنتاج. لا يعني `504` حتمًا أن Commit ذريًا لم يقع عند حافة المهلة؛ تحقق من حالة المستند وأعد الأمر بمفتاح Idempotency نفسه. تفاصيل الضبط والاستجابة للتنبيهات في [دليل المرونة التشغيلية](docs/operational-resilience.md).

## النسخ الاحتياطي والاستعادة

```bash
npm run db:backup
npm run db:restore
```

ينشئ أمر النسخ ملفًا مضغوطًا ومشفرًا مع SHA-256 وبيانات تحقق محاسبية. ترفض الاستعادة الكتابة فوق قاعدة غير فارغة، وتتطلب `RESTORE_CONFIRM=RESTORE:<DATABASE_NAME>`، ثم تقارن الترحيلات والجداول وأعداد الصفوف وإجمالي المدين والدائن مع Manifest. راجع [دليل التشغيل الإنتاجي](docs/production-operations.md) للمتغيرات وإجراء التجربة الدورية.

لتشغيل اختبارات قاعدة البيانات الفعلية، عيّن `RUN_DB_TESTS=true` مع `DATABASE_URL` و`SEED_ADMIN_PASSWORD` صالحين، وطبّق الترحيلات والـSeed وابنِ التطبيق قبل E2E. تحتوي الحزمة الحالية على **241 تحققًا آليًا عبر 62 ملفًا**: 186 اختبار API، و20 اختبار واجهة، و18 اختبار بنية تحتية، و16 حالة Playwright للمصفوفة المتجاوبة، ورحلة E2E كاملة، إضافة إلى تجربتي نجاح وفشل آمن للرجوع داخل سكربت CI. في التحقق المحلي الحالي نجحت اختبارات API الكاملة 186/186 على MariaDB 10.4.32 وعلى MySQL 8.4.11 بعد تطبيق الترحيلات الـ32 من الصفر وتشغيل Seed وDemo Seed في قاعدتين معزولتين، بما فيها مطابقة أجسام الاستجابة ورموز الحالات مع OpenAPI. كما نجحت ترقية المخطط السابق ببيانات ذمم وتخصيصات ونسب ضريبية وحسابات Treasury وطرق دفع فعلية على المحركين. تشمل الحزمة Probe من 16 معاملة متزامنة مقاسة واختبارات تحديثات ضريبية ومرجعيات Treasury متنافسة، ونجحت مصفوفة الواجهة الآلية في تغطية 168 حالة بصرية فعلية. تعيد بوابتا MariaDB 10.11.11 وMySQL 8.4.11 إثبات النسخ والاستعادة قبل اعتماد Artifact.

## ضوابط مهمة

- كل الاستعلامات المالية مقيدة بالشركة المختارة، وتدعمها علاقات مركبة داخل قاعدة البيانات.
- لكل مؤسسة وشركة رمز ثابت، وتجهيز الشركة ومديرها قابل لإعادة التشغيل دون مضاعفة الإسنادات أو الأدوار.
- الرموز المرجعية للعملاء والموردين ومراكز التكلفة وحسابات الصندوق/البنك وطرق الدفع الخاصة ومعدلات الضريبة والأدوار المخصصة يولدها الخادم لكل شركة، ولا يطلبها من المستخدم ولا يسمح بتعديلها؛ بقي رمز الحساب المحاسبي ورمز العملة يدويين لأنهما دلاليان.
- هوية حساب القالب تبقى ثابتة عند تغيير الرمز أو الاسم أو الحساب الأب؛ لذلك لا تضاعف إعادة التطبيق تخصيصات العميل، والحذف النهائي مقصور على الحساب غير المستخدم الذي لا يملك فروعًا.
- يفشل تشغيل الإنتاج مبكرًا إذا غاب HTTPS أو Secure Cookie أو إعداد reverse proxy، وتوفر الخدمة فحص جاهزية قاعدة البيانات وRate Limiting وإغلاقًا سليمًا.
- لوحة التحكم وميزان المراجعة مشتقان مباشرة من السندات والقيود، ولا يخزنان أرقامًا ملخصة كمصدر حقيقة مستقل.
- النطاق التفاعلي الواحد للتقارير لا يتجاوز 366 يومًا، وميزان المراجعة يعتمد القيود المرحلة والمعكوسة لضمان أثر العكس الصحيح.
- الحساب غير النشط أو التجميعي أو غير المسموح بالترحيل إليه لا يقبل قيودًا مرحلة.
- المبالغ وأسعار الصرف تنتقل كنصوص عشرية لتجنب فقد الدقة في JavaScript.
- الترحيل والعكس والعمليات الحرجة تستخدم Optimistic Version وIdempotency.
- الترحيل والعكس وإغلاق الفترات وحجز الأرقام والتسجيل تستخدم منفذ معاملات موحدًا يعيد المعاملة كاملة فقط عند `P2034` أو deadlock/lock-wait المصنف، ولا يعامل `P2002` أو أخطاء الأعمال كعطل عابر.
- الأرقام الضريبية وأرقام الحسابات وIBAN لا تحفظ كنص ظاهر؛ تحفظ اللقطة اللازمة للعرض المقنع فقط في المرحلة الحالية.
- المسودات قابلة للتعديل، بينما المستندات المرحلة لا تعدل ويجري تصحيحها بقيد عكسي.
- لقطة الطباعة للمستند المرحّل غير قابلة للتغيير؛ إعادة الطباعة تتحقق من البصمة ولا تعيد قراءة أسماء الشركة أو الحسابات المعدلة لاحقًا.
