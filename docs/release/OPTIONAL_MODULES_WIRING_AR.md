## النتيجة

استُبدلت قائمة الاستحقاقات المختصرة في `CompanySubscriptionPage` بـ`OptionalModulesCatalog` فعليًا. بقي نموذج OPTIONAL واختيار اعتمادياته وإزالة التوابع والمراجعة والتأكيد والإرسال القائم مسارًا واحدًا. الكتالوج عرض فقط، بلا زر تفعيل أو طلب كتابة أو احتساب مالي جديد.

الغلاف المقبول يحمل هوية المستخدم والشركة ونتيجة الاشتراك والصلاحيات معًا. كل تحميل، بما فيه الدخول للصفحة والعودة إليها والتحديث بعد نجاح أمر الاشتراك، يقرأ `/auth/me` مع `/subscription` والكتالوج عبر الـAPI الحالي. القراءة لا تقبل شركة أو مستخدمًا مختلفًا. أي تغير في مجموعة الصلاحيات أو الوحدات، حتى للحساب والشركة نفسيهما، يبطل الصفحة؛ يحدّث App لقطة صلاحيات السياق المطابق ثم تعاد قراءة الصفحة. تغيير ترتيب المجموعات وحده لا يعيد تركيبها.

عند بدء التحديث يصبح غلاف الكتالوج loading فورًا، وعند فشل القراءة error، وعند حجب السياق unavailable. الاحتفاظ ببيانات الصفحة السابقة في state لا يعرض بطاقات جاهزة. تبقى حماية رقم الطلب والإلغاء وrevision والتركيب حسب السياق مانعة لتأثير الردود القديمة. التحديثات من الخادم منفصلة HTTP وليست لقطة معاملة قاعدة بيانات ذرية؛ لا يدّعي هذا التغيير ضمانًا خادميًا جديدًا.

نُقلت النصوص إلى `optional-modules.ts` وسُجلت في قواميس ar/en/ur/hi، مع تحقق تطابق المفاتيح بالأنواع. يدعم العرض RTL/LTR وخط Devanagari، وبمقاسين محسوبين 16/20px. تبقى مبالغ الرسوم نصوصًا عشرية كما وردت: صفر ليس قيمة مفقودة، وnull ليس عرضًا مجانيًا، والإجمالي والضرائب من مراجعة الاشتراك القائمة.

صححت وثيقة الكتالوج المستوردة: وصف سلوك SUSPENDED/CANCELED بأنه فجوة P0 مسحوب. سياسة SUB-2 المؤرخة تجعل الاستحقاق المؤرخ مصدر الوصول عمدًا؛ لا استنتاج منع أو تفعيل من اسم الحالة. أي سياسة تعطيل مستقبلية تحتاج قرار مالك المجال، ولا تُضاف في React.
