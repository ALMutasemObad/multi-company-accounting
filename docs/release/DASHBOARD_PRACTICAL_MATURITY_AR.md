# نضج لوحة التحكم عمليًا

التاريخ: 2026-09-08

## النطاق والنتيجة

اختُبرت لوحة التحكم محليًا ببيانات تركيبية واعتراضات API معزولة على عرضي 390 و1440 بكسل. لم تُستخدم بيانات حية، ولم تُرسل طلبات كتابة، ولم يحدث دفع أو نشر.

ثبتت فجوة P1 قبل التعديل لمستخدم يملك `dashboard.view` فقط مع توافر الوحدات: كانت اللوحة تعرض ثلاثة اختصارات سريعة (`POS` والمبيعات والمشتريات)، وثلاثة أزرار في نظرة مساحة العمل (الموردون والعملاء والمدفوعات)، وزر التقارير، رغم أن سياسات التنقل القائمة تمنع هذه الوجهات لغياب صلاحيات العرض الخاصة بها.

عولجت الفجوة بإنشاء مساعد محلي يشتق وجهات Dashboard المسموحة من `isNavigationItemVisible` نفسها، بما يشمل شرط الوحدة و`viewPermissionPolicies`. تستخدم الصفحة `useAuthorization` لبناء سياق الوصول، ولا تركب الاختصارات أو أزرار النظرة العامة أو زر التقرير إلا للوجهات المسموحة. كما يرفض handler استدعاء `onNavigate` لأي وجهة غير موجودة في مجموعة `allowedViews`، فلا تعتمد الحماية على الإخفاء وحده.

## السلوك المتحقق

- مستخدم `dashboard.view` فقط يرى المؤشرات والمخطط والنشاط، ولا يرى أي وجهة تشغيل لا يستطيع فتحها.
- الصلاحية الفردية تبقي الوجهة المقابلة قابلة للاكتشاف: `sales_invoices.view` يظهر اختصار المبيعات، و`suppliers.view` يظهر الموردين فقط، و`reports.cash_flow.view` يظهر زر التقرير.
- وجود الصلاحية دون module entitlement لا يكفي لإظهار الوجهة.
- حالة التحميل ظاهرة، وفشل التحميل الأولي ينتقل إلى لوحة خطأ قابلة لإعادة المحاولة، ثم يعرض التقرير بنجاح.
- الفلاتر ذات نطاق تاريخ مقلوب تعطل زر التحديث ولا ترسل طلبًا؛ النطاق الصحيح يرسل `dateFrom` و`dateTo` المحددين.
- عُرضت أربعة مؤشرات، وشهرا حركة نقدية، وصفّان من النشاط التركيبي، مع عدم وجود overflow على مستوى الصفحة عند 390 و1440.
- جمعت الاختبارات جميع الطلبات غير `GET` وأثبتت أن عددها صفر في الرحلات المختبرة.

## الأدلة

- Baseline قبل الإصلاح: اختبار `dashboard.view` فقط فشل لأن عدد الاختصارات السريعة كان 3 بدل 0، وعدد أزرار النظرة العامة 3 بدل 0، وزر التقرير 1 بدل 0.
- `apps/web/src/dashboard-navigation.test.ts`: أربع حالات لوحدة السياسة، تشمل القراءة فقط، الصلاحيات الفردية، شرط الوحدة، والمحافظة على السلوك الكامل للمستخدم المخول.
- `tests/visual/dashboard-practical-maturity.spec.ts`: ست رحلات عملية؛ التحميل/الخطأ/إعادة المحاولة/الفلاتر/المؤشرات/المخطط/النشاط، وحدود القراءة فقط، واكتشاف الوجهات الفردية، على كلا العرضين.
- بوابات التسليم: unit وweb/e2e typechecks وPlaywright المركز وweb build وUI contract و`git diff --check` و`git show --check`.

## ما لم يُختبر

- لم تُشغّل قاعدة بيانات أو API حقيقيان؛ التقرير وبيانات الاعتماد تركيبية داخل Playwright.
- لم تُغير أو تُختبر عقود API أو schema أو OpenAPI أو ملفات الترجمة أو الاعتمادات.
- لم تُختبر دقة الأرقام المحاسبية المصدرية؛ اختبرت الواجهة عرض الاستجابة، الفلاتر، حالات التشغيل، وحدود التنقل فقط.
- لم تُختبر وجهات خارج الاختصارات السريعة الثلاثة الحالية، والتقارير، والموردين والعملاء والمدفوعات لأنها ليست أسطح تنقل من Dashboard ضمن النطاق الحالي.

لا توجد فجوة P0/P1 أخرى مؤكدة ضمن ملفات المهمة بعد المعالجة.
