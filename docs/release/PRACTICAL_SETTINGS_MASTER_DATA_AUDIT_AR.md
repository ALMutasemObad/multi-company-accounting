# التدقيق العملي للإعدادات والبيانات المرجعية — الموجة الثالثة

تاريخ التدقيق: 2026-09-08. أُجري الفحص على نسخة محلية معزولة من النظام المحاسبي وبيانات Visual QA التركيبية فقط، بلا أسرار أو بيانات حية أو طلبات كتابة. استُبعدت مصروفات الموظفين صراحة من النطاق.

## النطاق وطريقة الإثبات

فُحصت بالعربية على 390×844 و1440×900 الرحلات التالية: إعدادات الشركة، عملات الشركة، أسعار الصرف، دليل الحسابات، مراكز التكلفة، المستودعات، أرصدة المخزون، حركات المخزون، وحدات القياس، كتالوج الأصناف، ومدخلات مركز الاستيراد.

قورنت في كل فجوة ثلاث طبقات: payload صلاحيات QA، الإجراء الظاهر فعليًا، وصلاحية router التي تحمي الطلب. نجح smoke النشط في فتح الرحلات المطلوبة على المقاسين بلا خطأ JavaScript أو تجاوز أفقي على مستوى الصفحة. لم تظهر فجوة P0.

## فجوات المنتج المؤكدة

### P1 — إجراءات إنشاء الحساب ظاهرة دون `accounts.create`

يحمل مستخدم QA `accounts.view` و`cost_centers.manage` ولا يحمل `accounts.create`. مع ذلك تعرض واجهة دليل الحسابات «حساب جديد» و«إنشاء حساب» وتفتح نموذج الإنشاء. يحمي API طلب `POST /accounts` بصلاحية `accounts.create`، فينتهي المسار برفض متأخر بدل حجب الفعل من البداية.

إعادة الإنتاج: افتح `/?qa=accounts#accounts` على أي من المقاسين ولاحظ زري الإنشاء. لم يُحفظ نموذج.

### P1 — عرض دليل الحسابات مربوط خطأ بإدارة مراكز التكلفة

تتطلب بوابة التنقل للعرض `accounts` الشرطين `accounts.view` و`cost_centers.manage` معًا، بينما يحمي `GET /accounts` و`GET /account-types` و`GET /accounts/default-template` شرط `accounts.view` فقط. لذلك لا يستطيع مستخدم عرض الحسابات الوصول إلى الدليل ما لم يُمنح أيضًا إذن إدارة مراكز التكلفة، وهو توسيع غير مبرر للصلاحية.

حاجز الاختبار يحقن authorization تركيبيًا يحتوي `accounts.view` وحدها، ويتوقع فتح الدليل وإخفاء تبويب مراكز التكلفة. لا يغير الاختبار fixture الخادم أو بياناته.

### P1 — واجهة المخزون تعرض أوامر كتابة لصلاحيات العرض فقط

يحمل مستخدم QA `warehouses.view` و`inventory_catalog.view` و`inventory_movements.view`، من دون صلاحيات الإدارة أو إنشاء الحركات. رغم ذلك تعرض الواجهة:

- إنشاء المستودع وتعديل المستودعات وتعطيلها؛ ويحمي API الكتابة بـ`warehouses.manage`.
- إنشاء وحدات القياس والأصناف وتعديلها وتعطيلها؛ ويحمي API الكتابة بـ`inventory_catalog.manage`.
- إنشاء حركة مخزون وتهيئة تقييم الرصيد؛ ويحمي API العمليتين بـ`inventory_movements.create`.

تكررت الإجراءات على 390 و1440. لم يُفتح حفظ ولم يُرسل طلب كتابة.

### P1 — مركز الاستيراد يبدأ رحلة لا يملك المستخدم معاينتها

يحمل المستخدم `data_imports.view`، و`customers.view`، و`suppliers.view`، مع `sales_invoices.create` و`purchase_invoices.create`. تعرض الواجهة الأنواع الأربعة بالتساوي وتبدأ افتراضيًا بالعملاء مع منتقي ملف مفعّل. لكن `POST /data-imports/preview` يطلب، بعد `data_imports.view`، `customers.manage` للعملاء و`suppliers.manage` للموردين، أو صلاحية الإنشاء لنوع الفاتورة.

يجب حسم قدرة المعاينة قبل اختيار الملف: إخفاء النوع غير المتاح أو تعطيل منتقيه مع تفسير الصلاحية. لم يُرفع أي ملف ولم تُنفذ معاينة أو commit. كما أن fixture لا يحمل `data_imports.execute`؛ لم يصل التدقيق إلى خطوة commit بسبب غياب ملف، لذلك لا تُسجل فجوة مستقلة لها دون إعادة إنتاج عملي.

## فجوة fixture مفصولة عن المنتج

### P1 QA — حالة القالب لا تطابق قائمة الحسابات

يعيد `/accounts/default-template` أن الدليل مكتمل: 42 إجماليًا و42 مطابقًا وصفر مفقود. لكن `/accounts` يعيد قائمة فارغة، فتجمع الشاشة بين «الدليل مكتمل (42 حسابًا)» و«لا توجد حسابات» و«أنشئ الحسابات الرئيسية أولًا». هذا تناقض في بيانات QA، وليس دليلًا على أن API الإنتاج يعيد القيم المتعارضة. أضيف حاجز `P1 QA` مستقل كي تصبح رحلة الدليل قابلة للاختبار الواقعي.

لا تُصنف حقيقة أن payload المرئي لا يسرد `currencies.manage` و`currencies.create` كفجوة منتج؛ سياسة الصلاحيات المرجعية توثق التوارث `settings.manage → currencies.manage → currencies.create`. يحتاج fixture مستقبلًا إلى تمثيل الصلاحيات الفعالة بوضوح، لكن ظهور إدارة العملات لمدير الإعدادات متوافق مع السياسة.

## ما تحقق بلا فجوة مصنفة

- ظهرت إعدادات الشركة والعملات وأسعار الصرف على المقاسين، مع حماية العملة الأساسية من التعطيل وعرض آخر سعر ومصدره.
- حقل المنطقة الزمنية textbox حر بينما تستخدم التهيئة قائمة مدعومة، لكن API لا يرفض نصًا غير فارغ ضمن حد الطول ولم يُرسل حفظ. لذلك بقيت ملاحظة تحسين غير مصنفة، بلا `fixme` ولا إدراج في backlog عيوب المنتج في هذا التدقيق.
- ظهرت بيانات المستودعين ووحدة القياس والصنف والرصيد والحركة التركيبية، وحافظت الجداول على تمرير داخلي من دون توسيع الصفحة.
- ظهر مركز الاستيراد وأنواع الملفات وحدود الحجم والصفوف والتنبيه إلى أن المعاينة لا تحفظ الملف.
- لم تظهر أخطاء JavaScript في الحالات الابتدائية التي يغطيها smoke.

## ما لم يُختبر

- مصروفات الموظفين مستبعدة صراحة، ولم تُفتح أو تُستدعَ endpoints الخاصة بها.
- لم تُرسل أي عملية إنشاء أو تعديل أو تعطيل أو تقييم أو حركة أو سعر صرف أو إعدادات.
- لم يُرفع ملف ولم يُنزّل قالب ولم تُختبر المعاينة أو الاعتماد الذري أو rollback أو محتوى XLSX/CSV.
- لم تُختبر صفوف حسابات أو مراكز تكلفة فعلية لأن fixture الحسابات والمراكز فارغ؛ إجراءات تعديل الحساب وحذفه وتطبيق القالب غير مختبرة.
- لم تُختبر الباركودات أو ملف بيع الصنف لأن صلاحيات fixture لا تعرض هذه الرحلات.
- لم تُختبر صلاحيات settings بوضع view-only لأن صفحة الإعدادات نفسها مصممة لصلاحية `settings.manage`.
- لم تُستخدم قاعدة بيانات أو API إنتاجي، ولم تُختبر العزلة متعددة الشركات أو صلاحيات الخادم هجوميًا.
- لم تُفحص لغات غير العربية أو المقاسات 768 و1920 في هذه الموجة.
