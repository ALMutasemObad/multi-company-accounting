# حدود صلاحيات إدارة المستخدمين والأدوار والجلسات

## النطاق

- الأساس: `731fc11f3635143558fcd6431b864afd0807ff53`.
- الملفات الوظيفية: صفحة الإدارة، سياسة الإدارة المحلية، وسياسة الوصول للتنقل.
- لم تُعدّل الموافقات أو سجلات التدقيق أو أحداث الأمن أو مصروفات الموظفين، ولم تُعدّل API أو OpenAPI أو قاعدة البيانات أو الترجمة.

## ما نُفذ

- أصبح الوصول إلى صفحة الإدارة قائمًا على `anyOf` بين:
  - `users.view`
  - `roles.view`
  - `auth.sessions.view`
- تعرض الصفحة التبويبات المسموحة فقط، وتختار أول تبويب مسموح مباشرة دون تركيب عابر لتبويب المستخدمين:
  - المستخدمون يقرأ `/users` فقط مع `users.view`.
  - الأدوار يقرأ `/roles` و`/permissions` فقط مع `roles.view`.
  - الجلسات تقرأ `/auth/sessions` فقط مع `auth.sessions.view`.
- فُصلت إجراءات المستخدم بدقة إلى `users.create` و`users.update` و`users.disable`.
- يتطلب ربط الموظف `users.create + users.update`: الأول مطلوب خادميًا لقراءة `/users/employee-options`، والثاني مطلوب لكتابة رابط الموظف.
- يتطلب تعيين أدوار المستخدم `roles.view + roles.manage`: الأول مطلوب لقراءة الأدوار وأدوار المستخدم، والثاني مطلوب للحفظ.
- كل إنشاء/تعديل/تعطيل للأدوار محمي بـ`roles.manage`، وإلغاء الجلسة محمي بـ`auth.sessions.revoke`.
- أضيفت الحراسة عند إظهار الإجراء وتركيب النموذج وداخل handler/submit، لمنع الطلب إذا تغيّرت الصلاحية بعد فتح الواجهة.
