# وصول تبويبات التقارير

## المنفذ

- أصبح شريط تقارير النظام `tablist` ذا اسم وصول مترجم مشتق من عنوان «التقارير المالية».
- كل خيار تقرير أصبح `role="tab"` بمعرف ثابت، وحالة `aria-selected`، وربط `aria-controls` بلوحة التقرير المقابلة.
- التبويب النشط وحده يدخل ترتيب Tab العادي (`tabIndex=0`) بينما بقية التبويبات تستخدم `tabIndex=-1`.
- لوحة التقرير النشطة أصبحت `role="tabpanel"` ومربوطة بالتبويب عبر `aria-labelledby`، ولا توجد أكثر من لوحة نشطة في DOM.
- يدعم الشريط `Home` و`End` والالتفاف عند الأطراف. مفاتيح السهم تتبع الاتجاه المرئي: في العربية ينتقل ArrowLeft إلى التبويب التالي يسارًا وArrowRight إلى السابق يمينًا، وينعكس ذلك تلقائيًا في الواجهات LTR.
- النقر بالفأرة أو اللمس يحافظ على السلوك السابق، ولم يتغير تحميل التقارير أو مرشحاتها أو تصديرها.

## التحقق

- اختبار Playwright عملي مخصص يفحص البنية، العلاقة بين التبويب واللوحة، roving tabindex، التركيز، ArrowLeft/ArrowRight/Home/End، النقر، وعدم التجاوز الأفقي.
- نطاق العرض: 390×844 و1440×900، باللغة العربية وعلى خادم QA المحلي المعزول.
- Playwright: نجح 2/2 على `mobile-390` و`desktop-1440`.
- `typecheck` للواجهة و`e2e:typecheck`: ناجحان.
- تحقق المتصفح الفعلي أكد انتقال التركيز والتحديد بالسهم على 390، وانتقال End إلى آخر تبويب على 1440، مع تبويب واحد فقط `tabIndex=0` وتطابق `aria-controls` مع لوحة موجودة وربطها العكسي بـ`aria-labelledby`.

## خارج النطاق

- لم تتغير نصوص الترجمة أو عقود API أو حسابات التقارير.
- لم تُختبر تنزيلات CSV/Excel/PDF أو بيانات حية أو صلاحيات أدوار متعددة.
- لم تُعدّل تبويبات المبيعات أو المشتريات ضمن هذه المهمة.
