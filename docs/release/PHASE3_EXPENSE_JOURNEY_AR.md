# تسليم رحلة المصروفات — المرحلة الثالثة

التاريخ: 2026-09-06. المهمة: expense-journey. الفرع: task/expense-journey.
الأساس: main عند 9be397c7a435720c921425b6cb7b64e5dbab7ebc.

## ما نُفّذ

- أصبح نجاح حفظ المسودة يضبط «مطالباتي / كل الحالات / الصفحة الأولى» ثم يعيد تحميل القائمة من الحالة الجديدة؛ يعيد التحميل أيضًا إن كانت الفلاتر نفسها محددة مسبقًا. لا يُستدعى تحميل بالإغلاق السابق.
- يُسمح لآخر طلب قائمة فقط بتحديث البيانات والخطأ والانتظار. لا تعرض العدادات أو التنقل نتائج قديمة أثناء التحميل أو الفشل.
- قفل متزامن يمنع النقر المكرر قبل إعادة الرسم، مع تعطيل الغرض وكل حقول البنود أثناء العمل. تبقى المدخلات عند الفشل.
- تحتفظ المحاولة ذات الحمولة نفسها بمفتاح idempotency عند إعادة المحاولة، لكل من إنشاء المسودة وإرسال المطالبة للمراجعة. الحمولة المعدّلة لها مفتاح آخر. بعد نجاح الإنشاء يبدأ إدخال جديد بمفتاح جديد.
- حدود React مستقلة لهوية المستخدم والشركة والصلاحيات: تغيير أي منها يعيد تركيب الصفحة، فيمسح المسودة ومراكز التكلفة والنتائج السابقة، ويتجاهل إكمال الطلبات السابقة. لا تخزين محلي أو دائم للمسودات أو مفاتيح المحاولات.
- لا جلب لنطاق الشركة دون review، ولا جلب للمطالبات الشخصية دون view. الإنشاء يحتاج submit وview، والإرسال يظل مقتصرًا على مسودة يملكها المستخدم ولديه submit. بقي فرض صلاحيات الخادم كما هو.
- فشل جلب مراكز التكلفة يظهر داخل النموذج مع إعادة المحاولة. نتائج هذا الجلب المتأخرة لا تغيّر الصفحة بعد مغادرتها.
- بيان مترجم بأربع لغات بأن الملخص للصفحة الحالية وفق الفلاتر، وأن READY_FOR_PAYMENT لا يعني الدفع. وصف العربية والإنجليزية يوضح عدم إنشاء سند أو قيد، دون تفاصيل داخلية في رحلة المستخدم.
- ضبط النصوص المحلية إلى 1rem والعناوين إلى 1.15rem، مع إخفاء التمهيد الصغير فوق عنوان الصفحة. احتُفظ بتخطيط RTL والاستجابة للشاشات الصغيرة.

## أوامر التحقق ونتائجها

كل أوامر المشروع أدناه من جذر worktree. استُخدم Node v24.19.0 من runtime الجهاز. npm لم يكن ضمن runtime أو PATH؛ نُزلت الحزمة الرسمية npm-12.0.2.tgz من registry.npmjs.org إلى مجلد TEMP/expense-npm-12.0.2 فقط، ثم استُخدم npm-cli.js مباشرة. لم تُغيّر إعدادات global ولم يُعدّل lock ولم تُشارك node_modules.

اختبارات callbacks تستعمل harness ضيقًا للـhooks وتشغّل callbacks الحقيقية والاستجابات المؤجلة؛ ليست snapshots. تغطي الفلاتر والصفحات، نجاح وفشل الطلب القديم، القفل المتزامن، إعادة استخدام مفاتيح الإنشاء والإرسال، الحفاظ على المدخلات، الصلاحيات، وحدود الهوية. اختبارات Playwright تكملها بتركيب DOM فعلي وتعطيل الحقول native، وفشل ثم نجاح الحفظ بالفلاتر الصحيحة، وتبديل الشركة أثناء حفظ معلق وحماية المسودة الجديدة، وسحب صلاحية الكتابة، والفشل المتأخر بعد unmount، وسباق فلاتر مع فشل الطلب القديم، وعدم تجاوز العرض عند 390px.

ملفات المتصفح fixture محلية فقط وغير مستوردة في مسار التطبيق الرئيسي. إعداد Playwright يشغّل Vite على 127.0.0.1:4183 ويحفظ مخرجاته في TEMP/expense-journey-browser-results. يستخدم Chromium الخاص بـPlaywright؛ يمكن تعيين EXPENSE_CHROME لمسار بديل. لا يستخدم الموقع الحي.

## ما لم يُختبر والقيود

- لم تُشغّل قاعدة بيانات أو backend حقيقي أو اختبارات CSRF/جلسة حقيقية. اختبارات المتصفح تحاكي HTTP؛ لا تثبت تنفيذ idempotency أو RBAC على الخادم أو عمليات مالية.
- مفاتيح المحاولات والمسودات في ذاكرة الصفحة فقط. الإغلاق أو تبديل الشركة/المستخدم/الصلاحيات يمسحها عمدًا؛ بعد نتيجة شبكة غير محسومة ومغادرة الصفحة يجب مراجعة القائمة قبل إعادة إدخال مطالبة مماثلة. الحماية لا تدعي تغطية إعادة المحاولة عبر إعادة فتح المتصفح.
- يعتمد عرض المطالبة بعد نجاح الحفظ على GET لاحق. إذا فشل هذا الجلب يظهر خطأ القائمة وإعادة المحاولة؛ رسالة نجاح الحفظ تبقى صحيحة ولا تعني أن الحفظ فشل.
- لا إلغاء لنقل HTTP من هذه الصفحة؛ تُهمل نتائجه بعد انتهاء النطاق. يجب مراجعة تكامل موجة session-safety عند الدمج، خصوصًا نافذة تبديل الشركة قبل تحديث AuthorizationProvider.
- لا اختبار بصري يدوي شامل ولا تحقق بشري من الهندية والأردية؛ فحص RTL والعرض الضيق آلي.
- ظهر تحذير Vite: chunk employee-expenses نحو 540.55kB (gzip 124.60kB)، وchunk صفحة المصروفات نحو 11.33kB. لم تُعدّل ملفات configs المشتركة لمعالجته.

## التسليم والدمج

جميع التغييرات ضمن نطاق المهمة، ولا تعديل لـApp.tsx أو api.ts أو registry أو types أو backend أو schema أو migrations أو الاعتمادات. يجب على المدير مراجعة الحد الجديد لهوية الصفحة مع تغييرات الجلسة ثم تشغيل تحقق الدمج. لا تنفيذ دفع أو سند أو قيد أو تغيير سياسات الموافقات. لم يُنشأ PR ولم يحدث push أو دمج بعيد أو نشر. الالتزام المحلي النهائي يسجله Workspace.ps1 -Action MarkReady في WORKSPACE.json بعد commit؛ هذا المستند لا يدعي CI أو نشرًا.
