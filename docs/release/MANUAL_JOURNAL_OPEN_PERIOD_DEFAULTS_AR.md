# افتراضات تاريخ وفترة القيد اليدوي

التاريخ: 2026-09-08

## النتيجة

أُغلقت فجوة P1 القديمة في نموذج القيد اليدوي الجديد. يبدأ النموذج الآن بتاريخ
الشركة لا بتاريخ UTC، ويختار فترة `OPEN` أو `REOPENED` تحتوي ذلك التاريخ. إذا
كان تاريخ الشركة خارج كل الفترات المؤهلة، يختار أقرب فترة ويحصر التاريخ عند
بدايتها أو نهايتها بترتيب حتمي.

التغيير محصور في الويب ومساعد محلي لهذه المهمة. لم تتغير عقود API أو schema
أو OpenAPI أو الترجمات أو الاعتمادات، ولم تتغير أجسام الأوامر أو حواجز
الصلاحيات القائمة.

## قاعدة الاختيار

- يُحوّل الوقت الحالي إلى تاريخ تقويم الشركة باستخدام `selectedCompany.timezone`.
- عند غياب المنطقة أو عدم صلاحيتها تكون العودة الحتمية تاريخ UTC.
- تُستبعد الفترات `CLOSED` والفترات ذات التواريخ غير الصالحة.
- الأولوية لفترة مؤهلة تحتوي تاريخ الشركة؛ المسافة حينها صفر.
- وإلا تُحسب المسافة إلى أقرب حد للفترة ويُحصر التاريخ إلى ذلك الحد.
- عند تعادل المسافة يكون الترتيب ببداية الفترة ثم نهايتها ثم المعرّف، لضمان
  نتيجة قابلة لإعادة الإنتاج.

## حماية المسودة وإدخال المستخدم

يحتفظ النموذج بعلامات مستقلة للمس الفترة وتاريخ المستند وتواريخ القيود. عند
وصول المراجع بعد فتح النموذج، تُملأ الحقول التي لم يلمسها المستخدم فقط. لا
تُطبّق الافتراضات مطلقًا على قيد محفوظ مفتوح للتعديل، ولا تُستبدل أوصاف أو
سطور أدخلها المستخدم. يبدأ أي سطر جديد بتاريخ المستند الحالي.

## أدلة التحقق

- وحدة المساعد: **5/5 ناجحة**؛ غطت مناطق زمنية موجبة وسالبة، UTC fallback،
  فترة تحتوي التاريخ، `REOPENED`، أقرب فترة والحصر والتعادل الحتمي، التواريخ
  غير الصالحة، وحماية المسودة والحقول الملموسة.
- Playwright: **4/4 ناجحة** على 390 و1440. ثُبت الوقت عند
  `2026-09-08T22:30:00.000Z` والمنطقة `Asia/Riyadh`، فأصبح التاريخ الافتراضي
  `2026-09-09` للمستند والقيد.
- أخّر اختبار Playwright استجابة الفترات عمدًا حتى بعد فتح النموذج. أثبت
  تطبيق الفترة عند وصولها، وأثبت في رحلة مستقلة بقاء تاريخي المستخدم
  `2026-09-15` و`2026-09-16` دون استبدال.
- أثبت الاختبار جسم `POST /manual-journals`: الفترة وتاريخ المستند وتاريخ
  القيد والأوصاف هي القيم الظاهرة نفسها، مع قيد مدين ودائن متوازن.
- Web Vitest الكامل: **54 ملفًا و716 اختبارًا ناجحًا**، مع **4 ملفات و16
  اختبارًا skipped** مشروطة بمتغيرات بيئية؛ لا تُحسب المتخطاة نجاحًا.
- Web وE2E typechecks: ناجحان.
- فحص UI: ناجح، `31` رأس صفحة و`68` منطقة جدول.
- بناء الويب: ناجح. بقي تحذير baseline للحزمة المشتركة المسماة
  `employee-expenses` بحجم `591.43 kB` في هذا الفرع المبني على `origin/main`؛
  لم تُمس مصروفات الموظفين أو Vite في هذه المهمة، وسيُزال التحذير عند دمج
  مرشح اللغات الأحدث في تكامل الإصدار.
- `git diff --check`: ناجح عند الإغلاق.

## حدود الدليل

- استخدمت رحلة المتصفح API محلية محاكاة وبيانات تركيبية، ولم تكتب في قاعدة
  بيانات حقيقية.
- لم يُختبر ترحيل القيد أو العكس؛ النطاق هو افتراضات إنشاء المسودة وجسم طلب
  حفظها فقط.
- أعيد استخدام مساعد `companyCalendarDate` الموحد أثناء تكامل الإصدار؛ لا
  يوجد منطق ثانٍ دائم لتحويل المنطقة الزمنية إلى تاريخ الشركة.
- لم يحدث push أو PR أو نشر.
