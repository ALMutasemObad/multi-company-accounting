# تاريخ عكس المستند وفق تقويم الشركة

## النتيجة

عولجت الفجوة `FIN-LIFE-P1-001` في فواتير البيع والشراء وسندات القبض والدفع.
كان prompt العكس يستخدم تاريخ UTC الناتج من `toISOString()`، وقد يسبق أو يلي
اليوم الفعلي للشركة قرب منتصف الليل. أصبح التاريخ الافتراضي يُحسب من
`selectedCompany.timezone` ويُرسل كما ظهر في prompt ضمن جسم طلب العكس.

المهمة مبنية على `origin/main` عند
`731fc11f3635143558fcd6431b864afd0807ff53`، ولا تعدل API أو العقود أو قاعدة
البيانات أو `invoice-date-defaults.ts` الذي سيُصالح معه المصدر الموحد في تكامل
لاحق.

## التصميم

أضيف المساعد المركزي `companyCalendarDate(timeZone, instant)`:

- يستخدم `Intl.DateTimeFormat` بتقويم ISO وأرقام لاتينية، ثم يجمع السنة والشهر
  واليوم صراحة بصيغة `YYYY-MM-DD`.
- يعيد تاريخ UTC نفسه بصورة حتمية عند غياب المنطقة الزمنية أو فراغها أو عدم
  صلاحيتها، بدل الاعتماد على منطقة جهاز المستخدم.
- يقبل `instant` صريحًا للاختبار، ويستخدم الوقت الحالي افتراضيًا في الواجهة.

تقرأ الصفحات الأربع `selectedCompany` من سياق التفويض القائم. التغيير الوحيد
داخل الأمر هو القيمة الافتراضية للـprompt؛ بقي فحص الصلاحية الدقيقة قبل أي
confirm، وبقي ترتيب confirm ثم السبب ثم التاريخ، وبقي جسم الطلب
`{ version, reason, reversalDate }` ومفتاح idempotency ومسار API كما كانت.
