# تسليم مساحة الموارد البشرية اليومية

التاريخ: 2026-09-09
المهمة: `hr-workspace-next`

## المنفذ

- أعيد تنظيم شاشة الموارد البشرية كمساحة يومية تجمع ملخص الحالات، والبحث بالاسم أو
  الرقم الوظيفي، والتصفية بالحالة والقسم، وسجل الموظفين، وتفاصيل الموظف وعقوده،
  والأقسام والمناصب.
- بقيت عمليات الإنشاء والتعديل وتغيير الحالة وإنهاء العقد على العقود الحالية نفسها،
  مع إخفاء العرض والإجراءات بحسب صلاحيات الموظفين والهيكل والعقود.
- أضيفت حالات تحميل وخطأ ولا نتائج، وتبويبات وأغلفة قوائم قابلة للوصول بلوحة
  المفاتيح، مع دعم RTL/LTR والعروض 390/768/1440/1920 ومن دون إخفاء overflow على
  مستوى المستند.
- تقبل بوابة الشاشة صلاحية عرض الموظفين أو عرض الهيكل، وتعرض التبويب المسموح وحده؛
  لا تكفي صلاحية العقود وحدها لأن العقد تابع لسجل موظف.
- تستخدم جميع قراءات القائمة والملخص والتفاصيل والهيكل قناة latest-request مستقلة
  تجمع AbortController ورقم جيل. يشمل ذلك effects وإعادة المحاولة والتحديث بعد
  الكتابة، وتمنع الشاشة إجراءات موظف لا يطابق الاختيار الحالي.
- فشل ملخص الحالات مستقل عن سجل الموظفين؛ يظهر تنبيه إعادة محاولة للملخص من دون
  حجب القائمة الناجحة.
- لم يتغير Prisma schema أو Migration أو OpenAPI أو API، ولم تنفذ رواتب. التصميم
  المقترح فقط موثق في `docs/architecture/PAYROLL_FOUNDATION_SLICE_AR.md`.
- لم يحدث نشر أو Push أو PR.

## قيد بيئة E2E العامة

إعداد `playwright.config.ts` العام يشغّل API كاملًا وينتظر `/ready`. لم توجد خدمة
MySQL محلية متاحة لعنوان الاختبار، لذلك انتهى انتظار الجاهزية قبل بدء السيناريو؛ لم
يكن ذلك فشلًا في توقع واجهة HR. أضيف إعداد معزول داخل نطاق التسليم يشغّل Vite فقط،
لأن السيناريو يعترض جميع عقود `/api/v1/**`، ونجح من خلاله المسار كاملًا. يبقى تشغيل
الحزمة العامة مع قاعدة MySQL فعلية ضمن تحقق التكامل البيئي.

مباشرة من fragment الخاص بها في هذه الشريحة. هذه هي القائمة المطلوبة لدمج runtime

## القيود المقصودة

- الرواتب تصميم Foundation فقط، محايد للدولة وغير صالح بذاته كادعاء امتثال قانوني.
- لا دفع بنكي ولا Treasury Port في الشريحة المقترحة؛ الترحيل المحاسبي لا يعني الدفع.
- لا حساب تلقائي لضريبة أو تأمين أو غياب أو تجزئة فترة أو تحويل عملة.
- قائمة المدير في نموذج الموظف تستفيد من صفحة الموظفين المحملة حاليًا، كما في القدرة
  الحالية؛ البحث المرجعي الخادمي للمدير يحتاج عقدًا أو مسارًا مستقلًا في مهمة لاحقة.
