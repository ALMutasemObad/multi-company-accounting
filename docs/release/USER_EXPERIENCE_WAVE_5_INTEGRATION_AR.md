## النتيجة الملموسة

- تفاصيل العميل في وضع العرض فقط لا تعرض معرّف حساب داخليًا مبهمًا إذا لم
  يملك المستخدم صلاحية قراءة الحسابات؛ تعرض `—` بدلًا منه، مع بقاء بيانات
  العميل والعناوين قابلة للقراءة.
- تثبت الرحلة الجديدة الفصل بين `customers.view` و`customers.manage`، ودورة
  إنشاء العميل وتعديله وإضافة عنوان وتعديله وحذفه وتعطيل العميل، وإزالة نماذج
  الكتابة عند سحب التفويض قبل أي طلب.
- تستمد لوحة المؤشرات وجهاتها من `isNavigationItemVisible` وسياسات التنقل
  الفعلية نفسها، بما يشمل صلاحية العرض وmodule entitlement. لا تُركب وجهة
  غير مخولة، ويعيد handler فحص `allowedViews` قبل التنقل.
- بقيت مؤشرات Dashboard والمخطط والنشاط وحالات التحميل والخطأ وإعادة المحاولة
  والفلاتر قابلة للاستخدام لمستخدم `dashboard.view`، حتى إذا لم يملك صلاحية
  فتح أي وجهة تشغيلية أخرى.
- بقيت تحسينات الموجات السابقة فعالة: اكتشاف اللغات والتحميل الكسول، صلاحيات
  الكتابة الدقيقة، open-period defaults، تاريخ الشركة للعكس، CRM، والدورة
  المالية والمطابقة البنكية.

## قرار اختبار تفاصيل العميل القديم

أزيل `test.fixme` مؤقتًا عن assertion القديم
`P1 QA: customer details remain rendered when the synthetic customer is opened`
وشُغّل كما هو، بلا تخفيف assertions أو تغيير fixture، على 390 و1440. فشل
2/2 لأن fixture القديم يعيد سجل عميل بلا خاصية `addresses`، فتصل
`CustomerDetails` إلى `customer.addresses.length` على قيمة غير معرفة. هذا
دين fixture قديم وليس إعادة إنتاج للسلوك الحقيقي الذي تغطيه الرحلة الجديدة.

أُعيد `fixme` إلى حالته السابقة ولم يُحسب نجاحًا. في المقابل تستخدم
`customer-details-practical-maturity.spec.ts` استجابة مطابقة للعقد وتغطي
العرض فقط ودورة الإدارة وسحب التفويض؛ نجحت **6/6** منفردة وداخل الجولة
المجمعة. لم يُزوّر fixture القديم فقط لخفض عدد الحالات المتخطاة.

## حدود الدليل والمتبقي

- رحلات Playwright تستخدم بيانات تركيبية واعتراضات API محلية؛ تثبت سلوك
  الواجهة والطلبات المرصودة ولا تثبت معاملات قاعدة بيانات حقيقية.
- لم تُشغّل اختبارات Social Auth الثلاثة عشر المعتمدة على قاعدة البيانات،
  ولم تُشغّل CRM أو رحلة العملاء على API/DB حقيقيين. يلزم ذلك لاحقًا على
  قاعدة اختبار معزولة ضمن بوابة الإصدار.
- لم تُرسل رسائل حية ولم يحدث اتصال فعلي بمزودي Google أو Apple أو بنك خارجي.
- بقي fixture العميل القديم دين اختبار موثق، بينما المنتج مغطى بالرحلة
  الجديدة المطابقة للعقد.
- لم تُمس مصروفات الموظفين، ولم يحدث push أو PR أو نشر.
