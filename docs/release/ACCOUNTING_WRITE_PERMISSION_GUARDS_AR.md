# تسليم حراسة صلاحيات الكتابة المحاسبية

المهمة: `accounting-write-permission-guards`، الفرع `task/accounting-write-permission-guards`، والأساس المتحقق منه `731fc11f3635143558fcd6431b864afd0807ff53`. التنفيذ محلي داخل worktree المسجل فقط.

## ما نُفذ

- أضيفت سياسات واجهة دقيقة للقيود اليدوية: الإنشاء، والتعديل، والترحيل، والإلغاء، والعكس، وطباعة PDF. لا تظهر الطباعة ولا يبدأ تنزيلها دون `manual_journals.print`.
- أضيفت سياسات مستقلة للفترات المالية: الإدارة، والإغلاق، وإعادة الفتح. `fiscal_periods.manage` لا يمنح الإغلاق أو إعادة الفتح ضمنيًا، كما أن الإغلاق وإعادة الفتح منفصلان.
- حُرست إجراءات الصفحتين في ثلاث نقاط: الإظهار عبر `Can`، وتركيب نموذج/مساحة الكتابة عبر `allows`، والتنفيذ داخل handler قبل أي تحقق أو prompt أو confirm أو طلب شبكة. إخفاء الزر ليس الحاجز الوحيد.
- لم تتغير واجهات API أو OpenAPI أو قاعدة البيانات أو الترجمة المشتركة، ولم يتغير سلوك القراءة.

## دليل اختبار الصلاحيات

أضيف `tests/visual/accounting-write-permission-guards.spec.ts` ببيانات محلية معترضة لمساري القيود والفترات. في كل عرض اختبر مستخدم القراءة فقط، ثم كل صلاحية كتابة منفردة:

- القراءة فقط: لا تظهر أسماء إجراءات الإنشاء/التعديل/الترحيل/الإلغاء/العكس/الطباعة أو الإدارة/الإغلاق/إعادة الفتح، ولا يركب نموذج كتابة أو مساحة إغلاق، ولم يُرصد أي طلب غير `GET/HEAD`.
- القيود اليدوية: كل من `create/update/post/cancel/reverse/print` أظهر إجراءه المناسب فقط. اختبرت المسودة للإجراءات الثلاثة الخاصة بها، والقيد المرحل للعكس والطباعة.
- الفترات المالية: `manage` أظهر إنشاء السنة وتعديل السنة والفترتين فقط، من دون `close/reopen`. أظهر `close` الإغلاق للفترة المفتوحة فقط وركّب مساحة الإغلاق، وأظهر `reopen` إعادة الفتح للفترة المغلقة فقط.
- شُغلت الحالتان على `390×844` و`1440×900`: **4/4 ناجحة**. لم تخرج طلبات `POST/PATCH` أثناء سيناريوهات الحراسة.

التشغيل النهائي:

```powershell
node node_modules/@playwright/test/cli.js test tests/visual/accounting-write-permission-guards.spec.ts --config playwright.visual.config.ts --project mobile-390 --project desktop-1440
```

النتيجة: `4 passed (36.2s)`. كشف التشغيل الأول خطأً في محدد الاختبار نفسه (`.page-actions` غير موجود في `PageHeader`) بينما لقطة الفشل أظهرت الأزرار المصرح بها فعلًا؛ استُبدل بمحددات `getByRole` وأسماء الإجراءات، ثم نجحت السلسلة كاملة من دون خفض معيار القبول.

## الحدود

- اختبار المتصفح يستخدم API محلية محاكاة ولا يثبت قاعدة بيانات أو جلسة إنتاج. الحراسة الخادمية الموجودة لم تتغير في هذه المهمة.
