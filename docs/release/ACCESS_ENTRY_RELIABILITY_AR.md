# اعتمادية مدخل الوصول والتسجيل

## النتيجة

أضيفت تغطية رجعية مركزة لمساري تسجيل الدخول والتسجيل دون تغيير سلوك الإنتاج أو
العقد أو قاعدة البيانات. تثبت التغطية أن الواجهة تعرض Google وApple فقط وفق جاهزية
المزود التي يعلنها الخادم، وتغلق الخيارين عند تعذر قراءة الجاهزية، وتحافظ على مدخلات
التسجيل عند الفشل المؤكد أو انتهاء المهلة، وتمنع النقر المتكرر من إنشاء طلبات متوازية.

تغطي الواجهة العربية والإنجليزية والأردية والهندية باتجاهي RTL/LTR على عرض هاتف
390px وعرض مكتب 1440px. وتبقى رسالة انتظار البريد وإعادة الإرسال عامة وصادقة: قبول
الطلب لا يعني إرسال البريد أو وصوله ولا يكشف وجود الحساب.

## ما اختُبر

- اختبارا المتصفح الفعليان لمساري الوصول والبريد: 22/22 ناجحة.
  - مزودان معطلان، Google فقط، Apple فقط، وفشل endpoint مع إخفاء المزودين.
  - شاشة الدخول بأربع لغات عند 390px و1440px، مع الاتجاه الصحيح ومنع الفيضان الأفقي.
  - رسالة انتظار التسجيل بأربع لغات عند العرضين نفسيهما.
  - نقرتان متزامنتان على التسجيل تنتجان طلب تسجيل واحدًا، ونقرتان على إعادة الإرسال
    تنتجان طلب إعادة إرسال واحدًا.
  - بقاء جميع حقول التسجيل بعد استجابة 503 وبعد انتهاء مهلة الطلب.
  - رحلة الاستكمال الاجتماعي على الهاتف من دون جمع كلمة مرور أو كشف مطالبات الهوية.
- اختبارات نسخة بريد التسجيل ومكوّن الانتظار: 8/8 ناجحة.
- TypeScript للواجهة عبر `tsc -p apps/web/tsconfig.json --noEmit`: ناجح.
- بوابة الترجمة `scripts/check-web-i18n.mjs`: ناجحة.
- بوابة عقد الواجهة `scripts/check-web-ui.mjs`: ناجحة؛ 31 رأس صفحة و68 منطقة جدول.

ثبتت اعتمادات المهمة مستقلًا من ملف القفل داخل worktree بعد التحقق من وجود أكثر من
10GB حرة على C، وباستخدام مخزن التنزيل المعتمد `E:/DevelopmentCaches/npm`.

## ما لم يُختبر والحدود

- لم يُجر اتصال حي بـGoogle أو Apple ولم تستخدم أسرار أو حسابات مزودين.
- لم يُرسل بريد حي ولم يُثبت وصول رسالة إلى صندوق بريد؛ الاختبار يثبت صدق الواجهة
  وحالة قبول الطلب فقط.
- لم تُشغل حزمة Web الكاملة أو اختبارات API وقواعد البيانات لأن التغيير محصور في
  أدلة المتصفح ولا يغير كود الإنتاج أو العقد أو المخطط.
- لم يحدث push أو PR أو دمج أو نشر.
