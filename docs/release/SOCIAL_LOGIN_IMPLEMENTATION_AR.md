# تسليم تنفيذ الدخول الاجتماعي

## النتيجة

نُفذ مسار OIDC عامل ومغلق افتراضيًا لـGoogle وApple، من بدء التفويض حتى callback
وتدوير الجلسة. يعتمد الربط حصريًا على `issuer + subject` ولا يدمج حسابًا قائمًا
بالبريد، ولا ينشئ مستخدمًا أو شركة بصمت. يظهر الزران في الواجهة فقط عندما يعلن
الخادم أن المزود مهيأ فعليًا.

## حدود السلوك

- الدخول مسموح فقط لهوية خارجية مرتبطة مسبقًا ومستخدم نشط.
- البريد الموثق المطابق لحساب قائم يعيد نتيجة تطلب إثبات الحساب؛ لا يحدث ربط تلقائي.
- الهوية الجديدة تعيد مسار استكمال التسجيل، من دون إنشاء كيان أعمال أو صلاحيات.
- الربط يتطلب جلسة مصادقًا عليها حديثًا خلال عشر دقائق وموافقة صريحة، ويمنع نقل
  هوية مملوكة لمستخدم آخر.
- تحفظ المعاملة القصيرة `state` و`nonce` وPKCE وارتباط المتصفح بصور مهشمة أو
  محمية بـAES-256-GCM، وتستهلك ذريًا مرة واحدة. لا تحفظ access token أو refresh token.
- يتحقق `openid-client` من توقيع ID Token والمصدر والجمهور والانتهاء و`nonce`،
  ويستخدم PKCE. تستقبل Apple الرد بصيغة `form_post` ويدعم الحقل الاختياري `user`.
- cookie ارتباط callback ضيق المسار و`HttpOnly; SameSite=None; Secure`، بينما تبقى
  cookie الجلسة العامة `SameSite=Lax`. الأخطاء الخارجية تعود برسالة عامة فقط.
- الاحتفاظ الافتراضي بسجلات المعاملات المنتهية أو المستهلكة سبعة أيام عبر عملية
  التنظيف المتاحة في الخدمة.

## الإعداد

المزودان معطلان افتراضيًا. تفعيل أي مزود يتطلب client id وclient secret وredirect
URI وسر المعاملة. في الإنتاج تُقبل نقاط المزود القانونية فقط، ويلزم redirect HTTPS
على أصل الواجهة نفسه. قيمة Apple client secret هي client assertion قصير العمر يورده
مدير الأسرار؛ لا تحفظ مفاتيح Apple الخاصة في التطبيق أو المستودع. يحتوي
`.env.example` على أسماء ومتغيرات بديلة فقط بلا أسرار.

أضيف `openid-client@6.8.8` بإصدار مقيد في lockfile. صُحح مصدر شريحة الأساس قبل
التنفيذ: بُني الفرع على `8ae2eaf` ثم التقط التزاما الأساس `5c9d30b` و`b7917f3`
فقط، وتطابقت ملفات الأساس الأربعة بايتًا مع مصدرها.

## قاعدة البيانات

أضيف جدولا `ExternalIdentity` و`SocialAuthorizationTransaction` مع المفاتيح
والفهارس وقيود الملكية اللازمة، وترحيل أمامي وrollback صريحين.

- MySQL 8.4.11: نجح تطبيق 72 ترحيلًا على قاعدة جديدة مع seed، ثم نجحت اختبارات
  الدخول الاجتماعي والمصادقة `5/5`. بعد تصحيح حذف FK إلى `CASCADE` طُبق التصحيح
  على قاعدة الاختبار وأعيدت الاختبارات بنجاح؛ لم تعد جولة fresh الحالية بعد هذا
  التصحيح الحرفي.
- MariaDB 10.11.16: نجح fresh لجميع الترحيلات الحالية مع seed، ونجح upgrade من
  71 ترحيلًا، ثم rollback (اختفاء الجدولين) وإعادة التطبيق. نجحت اختبارات الدخول
  الاجتماعي والمصادقة `5/5`، ثم نجح ملف التكامل المحدّث `3/3` بما فيه Apple
  `form_post` وخصائص cookie.
- أوقفت المحركات بعد التحقق، وأبقيت مجلدات بيانات الاختبار وأدلة القياس وفق سياسة
  المساحة؛ لم تُحذف أو تُعامل كأرشيف.

## التحقق

- نجح TypeScript لـAPI، ونجح build الخاص به.
- نجح build الواجهة بـVite؛ بقي تحذير chunk قائم مسبقًا يتجاوز 500 kB.
- نجح فحص العقود: 183 request bodies و2343 response bodies.
- نجحت 106 اختبارات مستهدفة تشمل policy والإعداد والعقود وتكافؤ المسارات والحواجز
  المعمارية.
- نجحت حزمة الواجهة: 51 ملفًا ناجحًا وملف واحد متجاوز، و702 اختبار ناجح و4 متجاوزة.
- نجح اختبار OIDC تشفيري محلي بمصدر HTTP وJWKS ورمز RSA مولد، ويثبت فشل التوقيع
  أو المصدر أو الجمهور أو الانتهاء أو nonce/PKCE غير الصحيح؛ هو محاكاة وليس شهادة
  توافق من Google أو Apple.
- نجح `git diff --check` وفحص مواضع الأسرار؛ لا توجد قيمة اعتماد فعلية في الفرق.
- حاولت حزمة API الكاملة غير المعتمدة على قاعدة البيانات مرتين، لكنها بقيت صامتة
  دون نتيجة لأكثر من دقيقتين ونصف فأوقفت بأمان. عوضًا عنها نُفذت الحزم المستهدفة
  والعقود والنوع والبناء، ولا تُسجل المحاولة كاختبار ناجح.

## ما لم يختبر وما بقي تشغيليًا

لم يُجر اتصال حقيقي بحسابات Google أو Apple، ولم تستخدم أسرار إنتاج أو callback
عام، لذلك لا يعد الاختبار المحلي شهادة مزود. يلزم قبل التفعيل التشغيلي تجهيز أسرار
المزودين، تسجيل redirect URIs، تشغيل smoke test في بيئة آمنة، وجدولة استدعاء تنظيف
المعاملات ومراقبته. كما تبقى إعادة fresh/upgrade على MySQL بملف الترحيل النهائي
الحرفي بند تحقق صريحًا إذا اشترط المدير تطابق الاختبارين على المحركين.

لم يحدث push أو PR أو دمج بعيد أو نشر.
