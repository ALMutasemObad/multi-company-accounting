# حواجز صلاحيات إجراءات التحكم

- التاريخ: 2026-09-08
- الفرع: `task/control-action-permission-boundaries`
- الأساس: `731fc11f3635143558fcd6431b864afd0807ff53`

## النتيجة

أصبحت إجراءات الموافقات والتصدير والإقرار الأمني مستقلة عن صلاحيات القراءة. يستطيع مستخدم العرض فقط فتح الصفحات وقراءة السجلات وفتح تفاصيل سجل التدقيق والحدث الأمني، لكنه لا يرى ولا يستطيع بدء أي إجراء من الإجراءات الثلاثة التالية:

| الإجراء | الصلاحية الدقيقة |
| --- | --- |
| اعتماد طلب الموافقة أو رفضه | `approvals.decide` |
| تنزيل سجل التدقيق بصيغة CSV | `audit_logs.export` |
| الإقرار بالتنبيه الأمني | `security_events.acknowledge` |

## الدفاعات المطبقة

- سياسة محلية مركزية تربط كل إجراء بصلاحيته الدقيقة من دون منح متبادل.
- حاجز تركيب `Can` يمنع وجود زر الإجراء في DOM عند غياب الصلاحية.
- حاجز داخل كل handler يسبق `confirm` و`prompt` والتنزيل وتغيير الحالة والطلب الكتابي؛ وهذا يحمي أيضًا من استدعاء handler قديم بعد تغيّر التفويض.
- لم تتغير صلاحيات التنقل أو القراءة، ويبقى الخادم هو حد الإنفاذ النهائي.

## التحقق

- اختبار السياسة المركّز: ملف واحد، 5 اختبارات ناجحة.
- Playwright محلي معزول على `390×844` و`1440×900`: 8 اختبارات ناجحة، بلا تجاوز أفقي للصفحات المفحوصة.
- أثبت سيناريو العرض فقط ببيانات تركيبية آمنة:
  - بقاء قائمة الموافقات والسجلات وتفاصيل التدقيق والأمان قابلة للقراءة.
  - عدم تركيب أزرار الاعتماد والرفض والتصدير والإقرار.
  - صفر dialogs وصفر downloads وصفر طلبات غير `GET` وصفر طلبات لمسار تصدير CSV.
- أثبتت السيناريوهات الإيجابية أن كل صلاحية دقيقة تعيد تركيب عنصر التحكم الخاص بها في المقاسين.
- نجح `@mcap/web` typecheck ونجح `e2e:typecheck`.
- نجح build لتطبيق الويب ونجح فحص عقد واجهة المستخدم `ui:check`.
- نجح `git diff --check`.

## ما لم يُختبر وما لم يتغير

- لم تُنفذ الإجراءات المسموحة فعليًا في Playwright، لتجنب أي كتابة أو تنزيل؛ التحقق الإيجابي اقتصر على تركيب عناصر التحكم، بينما غطى الاختبار السلبي غياب الآثار الجانبية المحظورة.
- لم تُستخدم بيانات حية، ولم تُعدّل واجهة API أو ملفات الترجمة أو `AdminPage` أو مصروفات الموظفين.
- لا دفع بعيد ولا PR ولا نشر ضمن هذه المهمة.
