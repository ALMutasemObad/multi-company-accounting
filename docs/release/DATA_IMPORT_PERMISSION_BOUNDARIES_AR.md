# حدود صلاحيات مركز استيراد البيانات

## النتيجة

حُسمت قدرة المستخدم على بدء الاستيراد قبل اختيار الملف. تعرض الواجهة فقط مسار عمل قابلًا للتنفيذ بصلاحيات المستخدم الحالية، ولا ترسل طلب معاينة أو اعتماد من إجراء محجوب. يبقى سجل الدفعات متاحًا لمستخدم القراءة فقط عبر `data_imports.view`.

## مصفوفة السياسة

| العملية | الصلاحيات المطلوبة |
| --- | --- |
| قراءة سجل الدفعات | `data_imports.view` |
| معاينة العملاء | `data_imports.view` + `customers.manage` |
| معاينة الموردين | `data_imports.view` + `suppliers.manage` |
| معاينة فواتير المبيعات | `data_imports.view` + `sales_invoices.create` |
| معاينة فواتير المشتريات | `data_imports.view` + `purchase_invoices.create` |
| اعتماد أي دفعة | صلاحية النوع نفسه + `data_imports.execute` |

تطابق هذه المصفوفة بوابات الـAPI الحالية، لكن الخادم يظل حد الإنفاذ الأمني النهائي.

## سلوك الواجهة

- تُعطّل أنواع البيانات التي لا يملك المستخدم قدرة معاينتها قبل اختيار الملف، ويُرفق بكل خيار معطّل اسم النوع وسبب المنع بصيغة متاحة لقارئ الشاشة، كما يرتبط حقل النوع برسالة ظاهرة كلما احتوى خيارات مقيدة.
- إذا كان هناك نوع مسموح واحد على الأقل، تختار الواجهة أول نوع مسموح بدل ترك المستخدم على نوع محجوب.
- إذا لم توجد قدرة معاينة لأي نوع، تتعطل عناصر النوع والصيغة والملف والقالب والمعاينة، ويظهر تفسير الصلاحية القائم في الترجمات الحالية.
- تحرس دوال اختيار الملف وتنزيل القالب والمعاينة والاعتماد نفسها من الاستدعاء غير المسموح، ولا تعتمد على حالة الزر وحدها.
- يبقى سجل الدفعات مقروءًا لمن يملك `data_imports.view` حتى عند تعطيل منشئ الدفعة كله.
- لا يظهر الاعتماد كإجراء متاح بعد معاينة سليمة إلا عند اجتماع `data_imports.execute` وصلاحية النوع المحدد.

تعطيل تنزيل القالب حسب قدرة النوع قرار واجهة وقائي مقصود: endpoint القالب الحالي يحتاج `data_imports.view` فقط، لكن القالب هو مدخل مباشر لمسار معاينة لا يستطيع المستخدم إكماله دون صلاحية النوع. لم تتغير صلاحيات الـAPI أو عقوده في هذه المهمة.

## التحقق

- اختبارات السياسة الوحدوية: 5/5 ناجحة، وتشمل المطابقة الدقيقة لكل نوع، القراءة فقط، فصل الأنواع، واشتراط التنفيذ للاعتماد.
- فحص TypeScript لتطبيق الويب: ناجح.
- فحص TypeScript لاختبارات Playwright: ناجح.
- Playwright على QA تركيبي ومعزول: 8/8 ناجحة؛ أربع رحلات على عرض 390 وأربع على عرض 1440.
- بناء تطبيق الويب للإنتاج: ناجح.
- بيانات المعاينة في Playwright تركيبية واعترضها الاختبار محليًا؛ لم تُرسل بيانات حية.

استُخدمت منافذ QA معزولة لأن المنافذ الافتراضية كانت عرضة للالتقاط من مهام محلية موازية. لا تمثل تلك المنافسة فجوة في المنتج.

## ما لم يُختبر أو يتغير

- لم تُنفذ عملية اعتماد فعلية ولم تُكتب بيانات إلى قاعدة بيانات.
- لم تتغير الـAPI أو OpenAPI أو قاعدة البيانات أو الترجمات.
- لم تُختبر مصروفات الموظفين، وهي خارج نطاق المهمة صراحة.
- لم يحدث push أو نشر.
