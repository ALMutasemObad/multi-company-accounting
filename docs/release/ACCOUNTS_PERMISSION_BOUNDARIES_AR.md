# تسليم حدود صلاحيات الحسابات ومراكز التكلفة

المهمة: `accounts-permission-boundaries`، الفرع `task/accounts-permission-boundaries`، والأساس المتحقق منه `731fc11f3635143558fcd6431b864afd0807ff53`. التنفيذ محلي داخل worktree المسجل فقط.

## ما نُفذ

- أصبح الوصول إلى مساحة دليل الحسابات متاحًا عند امتلاك `accounts.view` **أو** `cost_centers.manage` بدل اشتراط الصلاحيتين معًا.
- أضيف ملف سياسات محلي للصفحة يفصل `accounts.view/create/update/deactivate/delete/template.apply` عن `cost_centers.manage`، من دون تعديل ملف سياسات الإجراءات المشترك مع مهمة دمج أخرى.
- لا تعرض الصفحة إلا التبويبات المصرح بها. صلاحية الحسابات وحدها تعرض دليل الحسابات، وصلاحية مراكز التكلفة وحدها تعرض مراكز التكلفة، واجتماعهما يحفظ التبويبين.
- أصبحت القراءة محدودة بالـendpoint المصرح به: مسارات الحسابات وأنواع الحسابات وحالة القالب لا تُطلب دون `accounts.view`، ومسار مراكز التكلفة لا يُطلب دون `cost_centers.manage`.
- حُرست إجراءات الحسابات الدقيقة ومراكز التكلفة عند الإظهار، وقبل تركيب النموذج، وداخل handler أو submit قبل prompt/confirm/network. لا تكفي إخفاءات الأزرار وحدها للحماية.
- بقيت عقود API وOpenAPI وقاعدة البيانات والترجمة خارج التغيير.

## دليل اختبار الصلاحيات والشبكة

أضيف `tests/visual/accounts-permission-boundaries.spec.ts` ببيانات API محلية معترضة وسجل مستقل لطلبات القراءة والكتابة:

- بلا أي صلاحية: لا يظهر تنقل دليل الحسابات، ولا يفتح المسار مباشرة، ولا يخرج أي read ذي صلة.
- `accounts.view` وحدها: تظهر بيانات الحساب والتبويب الخاص به فقط، وتُطلب `/accounts` و`/account-types` و`/accounts/default-template` فقط؛ لا يُطلب `/cost-centers`، ولا تظهر أزرار الإنشاء أو التعديل أو التعطيل أو الحذف أو تطبيق القالب، ولا يركب نموذج كتابة.
- اختُبرت `accounts.create/update/deactivate/delete/template.apply` كل واحدة منفردة مع `accounts.view`: أظهرت فعلها المناسب فقط. رُكّب نموذجا الإنشاء والتعديل دون إرسال، وبقيت الأفعال الأخرى غائبة.
- `cost_centers.manage` وحدها: ظل تنقل المساحة متاحًا، وظهر تبويب المراكز وإجراءاته فقط، ولم يُطلب أي endpoint للحسابات أو أنواعها أو القالب.
- عند اجتماع `accounts.view` و`cost_centers.manage`: ظهر التبويبان، ونُفذت القراءات المصرح بها لكليهما، وظلت أفعال الحسابات الكتابية غائبة دون صلاحياتها الدقيقة.
- تعامل الفحص مع إعادة قراءات React StrictMode على أنها تكرار للمسار المصرح نفسه، مع مقارنة مجموعة المسارات الفريدة. لم يظهر أي مسار قراءة ممنوع، ولم يُرصد أي طلب كتابة في سيناريوهات العرض/تركيب النماذج.

شُغلت الحالتان على `390×844` و`1440×900`: **4/4 ناجحة**. نجحت الإعادة النهائية بعد آخر تعديل على الإعداد القياسي في `25.9s`.
