# اكتمال دلالات تبويبات المبيعات والمشتريات

التاريخ: 2026-09-08

## النتيجة

حُسمت فجوة الوصول القديمة في شريطي تبويبات فواتير المبيعات والمشتريات دون تغيير طلبات البيانات أو منطق الصلاحيات أو النماذج. أصبح كل شريط يعلن `tablist` باسم الصفحة، وكل زر يعلن `tab` و`aria-selected` وموضعه في ترتيب التركيز، ويرتبط بلوحة واحدة ثابتة موجودة دائمًا عبر `aria-controls`. وتعلن اللوحة النشطة `tabpanel` و`aria-labelledby` للتبويب المحدد.

تتحرك الأسهم وفق الاتجاه المرئي: السهم الأيمن يتقدم في LTR ويتراجع في RTL، والسهم الأيسر يعكس ذلك. يختار `Home` أول تبويب و`End` آخر تبويب، وينتقل التركيز والتحديد معًا مع التفاف آمن عند الطرفين.

## حدود الصلاحيات

- لا يدخل تبويب أعمار الذمم في ترتيب لوحة المفاتيح ما لم تتوافر `reports.receivables.view` للمبيعات أو `reports.payables.view` للمشتريات.
- عند غياب صلاحية الأعمار يصبح الترتيب «الفواتير، الضرائب»، وتقفز الأسهم مباشرة بين التبويبين المسموحين.
- إذا فُقدت صلاحية الأعمار بينما كانت هي الحالة المطلوبة، تُحل الحالة المعروضة فورًا إلى أول تبويب مسموح ثم تُزامَن الحالة الداخلية؛ لذلك لا يشير `aria-labelledby` إلى تبويب غائب.
- لم تتغير سياسات إنشاء الفواتير أو تعديلها أو ترحيلها أو إدارة الضرائب، ولم تُضف أي كتابة أو طلب API جديد.

## دليل التحقق

- Vitest: ثلاث حالات ناجحة للمصفوفة المسموحة، fallback، اتجاهي RTL/LTR، الالتفاف، `Home` و`End` وثبات المعرّفات.
- Playwright: أربع حالات ناجحة تغطي العربية والإنجليزية على عرضي 390 و1440. تختبر الصفحتين بالحالتين الكاملة والمقيّدة، ووجود هدف `aria-controls`، و`aria-labelledby`، وانتقال التركيز، وكون `tabindex=0` للتبويب النشط فقط، وصفر طلبات كتابة.
- TypeScript: نجح فحص الويب وفحص E2E.
- نجح بناء الويب وفحص قواعد الواجهة و`git diff --check`.

## ما لم يُختبر

لم تُستخدم بيانات حية أو قاعدة إنتاج، ولم تُختبر أوامر إنشاء/تعديل/ترحيل الفواتير لأن نطاق المهمة محصور في دلالات التبويبات والتنقل بينها. لم يحدث دفع بعيد أو نشر.
