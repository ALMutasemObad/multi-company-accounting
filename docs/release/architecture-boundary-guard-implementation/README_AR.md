# حارس حدود الاستيراد المعمارية

تنفيذ محلي للمهمة `architecture-boundary-guard-implementation`، مبني على
`188089d249324e61b5d5c323798de0dafd245f1a`. لا يغير سلوك التطبيق أو قاعدة البيانات،
ولا يثبت اعتمادًا أو يعدل `package.json` أو إعدادات CI. لا يوجد push أو PR أو دمج
بعيد أو نشر لهذه المهمة.

## ما نُفذ

- يعلن `architecture-boundaries.json` ملكية مسارات General Projects وProfessional
  Projects وService Catalog وHR وAttendance وPayroll وBranch/POS. يبقى المسار
  الحالي `apps/api/src/projects` للمشاريع المهنية وحدها؛ المسارات المحجوزة لا تعني
  وجود وحدات أو جداول منفذة.
- يفحص `scripts/architecture-boundaries.mjs` جميع ملفات المصدر تحت
  `apps/api/src`، بما فيها الملفات المستقبلية، باستخدام Node built-ins فقط.
  لا يدخل `node_modules` أو `dist` أو `coverage`.
- يرفض الواردات إلى السياقات المحمية من سياق آخر أو مصدر غير مصنف، ما لم تطابق
  منفذًا ومستهلكًا معلنين، أو تصدر من نقطة تركيب معلنة. تعامل استيرادات الأنواع
  وإعادة التصدير كاعتمادات أيضًا. لا يمنح الاسم `adapter` أو `port` استثناءً تلقائيًا.
- يحدد الـmanifest المحوّلات الحالية التي تطبق عقود المشاريع المهنية وHR واستعادة
  POS، ويسمح لها باستيراد الأنواع من ملفات العقود المحددة فقط. النقاط المحجوزة
  للتكامل المستقبلي مسارات مقترحة للحجز؛ يجب مراجعة العقد الفعلي عند تنفيذه وتحديث
  هذا الملف واختباره إذا اختير اسم مختلف.
- نقاط التركيب المعلنة هي `app.ts` و`server.ts` و`composition/**` داخل مصدر API.
  يمنع استيرادها من السياقات المحمية، حتى لا تصبح طريقًا خلفيًا إلى الخدمات.
  تسبق قواعد المنع الصريحة أي سماح بالتكامل.
- يحل المسارات النسبية وامتدادات `.js` التي تشير إلى مصدر `.ts` واستيراد مجلد
  `index`، ويصنف الهدف غير الموجود دون اعتباره خطأ تجميع. يطبّع المقاطع النسبية
  وفواصل Windows ولا يسمح بالخروج من المستودع. يتجاهل query/fragment عند تحديد
  ملكية الملف. يرفض الروابط الرمزية في جذور الفحص، والهدف الذي يخرج عبر رابط رمزي.
- يقرأ import وexport-from وrequire وimport() ذوات النص الثابت، بما فيها
  التصريحات متعددة الأسطر والنصوص المهربة. يتجاهل التعليقات والنصوص العادية ونص
  القالب ويفحص تعبيرات `${...}` داخله. يقبل `import type` و`export type` وحقول
  `type` المسماة في السماحات المقصورة على الأنواع.
- يرفض إعدادات الملكية المتداخلة والمسارات غير المغطاة بالفحص وسماحات المنافذ
  العامة ذات wildcard. يتيح aliases صريحة وقواعد حظر package specifier في
  الـmanifest؛ القائمتان فارغتان في خط الأساس الحالي.

## التشغيل

من جذر worktree باستخدام Node 22 أو أحدث:

```powershell
node scripts/architecture-boundaries.mjs
node scripts/architecture-boundaries.mjs --json
node --test scripts/tests/architecture-boundaries.test.mjs
git diff --check
```

يدعم الفاحص `--root DIR` و`--manifest FILE` لاختبار مستودع أو سياسة مستقلين.
الجذر الافتراضي مشتق من موضع الأداة، وليس من مجلد shell الحالي. النتيجة JSON
تحتوي عدد الملفات والاستيرادات وملفات كل سياق، والمخالفات والتحذيرات مع الملف
والسطر والهدف والقاعدة. رموز الخروج: `0` نجاح، `1` مخالفات مصدر، `2` خطأ إعداد
أو قراءة جذور الفحص أو استعمال CLI.

دلالة المسارات في السياسة: المسار المنتهي بـ`/**` شجرة مجلد محددة، وغيره ملف
وحدة محدد مع تكافؤ امتدادات المصدر والتنفيذ. لا يوجد glob عام أو مطابقة جزئية
لأسماء المجالات. الاستيراد إلى `hr-lookalike` لا يعامل بوصفه استيرادًا إلى `hr`.

## التحقق المحلي

شُغل التحقق على Node `v24.19.0` دون تثبيت اعتماد:

- نجح `node --test scripts/tests/architecture-boundaries.test.mjs`: عدد الاختبارات
  43، جميعها ناجحة. تنشئ الاختبارات fixtures صغيرة داخل نطاق توثيق المهمة وتحذف
  فقط مجلداتها المؤقتة التي أنشأتها.
- نجح فحص خط الأساس: 323 ملف مصدر و1422 استيرادًا، دون مخالفات أو تحذيرات مراجعة.
  للمشاريع المهنية 11 ملفًا، ولـHR سبعة، ولـBranch/POS عشرة؛ بقية السياقات المحجوزة
  بلا ملفات في هذا الالتزام. النتيجة الآلية محفوظة في `baseline-result.json`.
- تغطي الاختبارات حدود الاتجاهين والمستهلك غير المصنف، وحظر خدمات المجال،
  وسماح الأنواع والمحوّلات، ونقاط التركيب، وسبق المنع على السماح، والملفات
  المستقبلية والغائبة، وحل المسارات والـaliases، وإعادة التصدير وrequire وimport
  الديناميكي الثابت، وتجنب التعليقات والنصوص، وأخطاء السياسة، ورموز خروج CLI.
- نجح فحص whitespace للفروق؛ تُراجع الملفات الجديدة أيضًا بعد إضافتها إلى index
  باستخدام `git diff --cached --check` قبل commit.

## حدود الدليل والمتبقي

الفحص حارس ساكن للاستيرادات داخل مصدر API، وليس محلل TypeScript كاملًا أو بديلًا
عن compiler. لا يفحص JSX أو الواجهة أو الاختبارات خارج `scanRoots`، ولا يثبت عزل
الشركات أو ملكية كتابة Prisma أو سلامة المعاملات أو عدم وجود دورات اعتماد. لم
تُشغّل اختبارات التطبيق أو قاعدة البيانات أو المتصفح لهذه المهمة، ولم يُشغّل CI.

الاستيراد إلى مسار غير مصنف يبقى خارج حظر الملكية ما لم تطابقه قاعدة منع صريحة.
هذا مقصود لحصر السياسة بالسياقات المطلوبة والسماح بالبنية المشتركة الحالية؛ لا
يعني أن كل اعتماد في بقية النظام أصبح جائزًا معماريًا. إضافة سياق جديد أو تغيير
مكانه تحتاج تحديث manifest ومراجعة الملكية. لا يقرأ الفاحص aliases من tsconfig
تلقائيًا؛ يجب إعلانها عند إضافتها.

التحميل المحسوب مثل `import(variable)` يولد `COMPUTED_IMPORT` للمراجعة اليدوية
ولا يحوله الفاحص إلى مخالفة تخمينية؛ وجود هذا التحذير لا يغيّر رمز النجاح إذا
لم توجد مخالفات أخرى. لا يتتبع eval أو loaders مخصصة أو require عبر alias أو
عضو object، ولا يثبت صحة بناء اللغة بالكامل. استعلام النوع `import('...')`
يعامل تحفظيًا كاستيراد ديناميكي؛ للعقد المقصور على الأنواع استخدم تصريح
`import type` الصريح. لا تسمح السياسة الحالية بأي تحذير في اختبار خط الأساس.

الخطوة التالية للمدير هي مراجعة الالتزام المحلي ومسارات العقود المحجوزة. إضافة
بوابة CI أو تعديل package scripts عمل مستقل ضمن ملكية ملفاتها. لا تنشئ هذه
المهمة General Projects أو Service Catalog أو Attendance أو Payroll أو Branch.

## أثر المراجعة المعمارية والباركود

الأثر محصور في أداة تحقق وسياسة مسارات واختباراتها؛ لا تغيير لمالك جدول أو عقد
OpenAPI أو Prisma أو migration أو حدث أو ترحيل مالي أو حدود المصادقة. لا تغيير
لإدخال صنف أو اختياره أو مسحه أو طباعته؛ لذلك لا توجد رحلة باركود أو جهاز طرفي
متأثرة تستدعي اختبارًا تشغيليًا في هذا النطاق.
