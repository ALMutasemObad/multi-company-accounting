# مراجعة النضج العملي لمساحة CRM

- التاريخ: 2026-09-08
- الفرع: `task/crm-practical-maturity`
- الأساس: `731fc11f3635143558fcd6431b864afd0807ff53`

## الخلاصة

اكتملت رحلة `Lead → Opportunity → Activity → Customer` من واجهة المستخدم الفعلية على عرضي `390×844` و`1440×900`. لم تظهر فجوة منتج من درجتي P0 أو P1، ولذلك لم يُعدّل كود الإنتاج أو CSS أو خدمة CRM. اقتصرت التغييرات على تقوية أدلة الاختبار الآلي وتوثيق النتيجة.

## الرحلة العملية

نفذ Playwright الخطوات التالية عبر الأزرار والنماذج، لا عبر استدعاء أوامر مباشر من `page.evaluate`:

1. إنشاء عميل محتمل مملوك لموظف قابل للإسناد.
2. تأهيله وإنشاء فرصة بقيمة Decimal وعملة محددتين.
3. إضافة متابعة مرتبطة بالفرصة.
4. تحويل العميل المحتمل المؤهل بربطه بعميل Sales قائم.

في كل مقاس ثبت ظهور الحالة والفرصة والمتابعة وحالة التحويل النهائية، وعدم تجاوز المستند أفقيًا. لم يصدر إلا أربعة أوامر `POST` الموافقة للخطوات الأربع، وحمل كل أمر مفتاح Idempotency صالحًا.

## الصلاحيات

قورنت الواجهة بموجّه CRM الحالي، وثبت الفصل التالي:

| القدرة | المسارات | الصلاحية |
| --- | --- | --- |
| الخيارات والقوائم وPipeline والمتابعات | جميع مسارات `GET /crm/*` | `crm.view` |
| إنشاء/تحديث Lead وتأهيله وتحريك مرحلة Opportunity | أوامر Lead وOpportunity | `crm.manage` |
| إنشاء Activity وإكمالها | أوامر Activity | `crm.activities.manage` |
| تحويل Lead إلى Customer | أمر التحويل فقط | `crm.convert` |

- كل أوامر الكتابة السبعة تتطلب CSRF ومفتاح Idempotency.
- مستخدم `crm.view` فقط لا يرى أي زر أو قائمة كتابة ولا يصدر أي `POST`.
- `crm.manage` وحدها لا تمنح إنشاء/إكمال المتابعات أو التحويل.
- `crm.activities.manage` وحدها لا تمنح التأهيل أو التحويل.
- `crm.convert` وحدها تعيد إجراء التحويل للـLead المؤهل فقط.
- تحتفظ الواجهة بحاجز handler مركزي يعيد فحص الصلاحية قبل إرسال الأمر.

## عزل الشركات والحدود المعمارية

- اختبارات القراءة تؤكد تمرير `companyId` الحالي إلى قوائم Leads وOpportunities وActivities وPipeline وإلى منافذ الموظفين والعملات والعملاء.
- اختبار التحويل العابر للشركة يعيد `NOT_FOUND` قبل استدعاء منفذ Customer.
- اختبارات الواجهة تمنع نتيجة قراءة أو كتابة متأخرة من الشركة السابقة من استبدال حالة الشركة الجديدة، وتمسح المسودة عند تبديل الشركة.
- يبقى CRM مالكًا لـLead وOpportunity وActivity فقط؛ التحويل يمر عبر `CrmCustomerProvisioningPort`/`CrmCustomerQueryPort` المملوكين لـSales، ولا توجد كتابة Customer أو Ledger داخل CRM.
- لا Schema أو Migration أو OpenAPI أو dependency أو أحداث جديدة في هذه المهمة.

## ما لم يُختبر

- الرحلة العملية استخدمت استجابات تركيبية داخل Playwright؛ لم تُكتب بيانات حية ولم تُنفذ الرحلة كاملة على MariaDB 10.11 أو MySQL 8.4.
- اختُبر التحويل إلى عميل قائم من الواجهة. مسار إنشاء Customer جديد بقي مغطى بعقود وخدمة CRM الحالية ولم يُنفذ عمليًا في هذه الجولة.
- لم تُختبر تكاملات خارجية أو إنشاء مشروع/قضية من CRM؛ هذا الإجراء غير متاح عمدًا حتى بوابة F2.
- لم تُمس مصروفات الموظفين، ولم يحدث push أو نشر.
