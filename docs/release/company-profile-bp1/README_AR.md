# شريحة ملف الشركة والتسجيل

## ما أُنجز

- أضيفت حقول الهاتف والدولة والنشاط الأساسي إلى التسجيل بالبريد والتسجيل الاجتماعي وإنشاء شركة المجموعة، وتنتقل القيم إلى ملف الشركة داخل معاملة التهيئة نفسها.
- أصبحت قوالب دليل الحسابات المسموح بها للشركات الجديدة: الخدمات المهنية، والتجزئة والمخزون، والإنتاج والتصنيع. فُصلت هذه القائمة عن قائمة القوالب المدعومة تقنيًا؛ يبقى القالب العام القديم قابلًا للقراءة والتوافق للحسابات القائمة، لكنه يُرفض صراحة في التسجيل بالبريد والتسجيل الاجتماعي وإنشاء شركة المجموعة.
- أضيف ملف شركة مع الاسم التجاري والقانوني والشكل القانوني ووسائل الاتصال واللغة والنشاط الأساسي، وسجلات تجارية وضريبية وعناوين مسجلة ووطنية وتشغيلية وفوترة.
- تتضمن السجلات تواريخ الإصدار والانتهاء وحالة التصريح أو التحقق أو الرفض أو الانتهاء، ويعرض الرد حالة التجديد المحسوبة دون تحويل اكتمال الملف إلى عائق تشغيلي.
- تعرض إعدادات الشركة جاهزية تدريجية وتوصيات قابلة للتنفيذ. الشركات السابقة للترحيل موسومة كتوافق قديم وتبقى قابلة للاستخدام.

## الأمن والعزل

- كل قراءة وكتابة مرتبطة بـ `companyId` المستخلص من سياق الجلسة؛ لا يقبل العقد معرّف شركة من جسم الطلب.
- فُصلت صلاحيات عرض وإدارة الملف عن صلاحيات عرض وإدارة الامتثال، مع فرض RBAC وCSRF على مسارات التعديل.
- تستخدم تعديلات الملف والامتثال جيل نسخة موحدًا مع قفل صف `CompanyProfile` داخل معاملة `Serializable`. يمنع ذلك سباق تغيير الدولة مع إنشاء سجل ضريبي أو عنوان، ويرفض تسلسليًا أي دولة امتثال لا تطابق دولة الملف.
- تطبق كائنات التسجيل والضريبة والعنوان دلالة `PATCH` حقيقية: الحقول غير المرسلة تبقى كما هي، ولا تمس كتابة الاسم القانوني السجلات الفرعية. تحفظ حالة `VERIFIED` وتاريخها ما لم تتغير بينة الوثيقة المخزنة، وتعيد الواجهة إرسال الكائن الفرعي المتغير فقط.
- لا تُخزن أرقام التسجيل أو الضريبة كاملة؛ يقبلها مسار الكتابة ولا يحتفظ إلا بآخر أربعة أحرف، ولا يسجل الرقم في تفاصيل التدقيق.
- يمنع تغيير دولة الملف أو إزالتها عندما يتعارض ذلك مع سجلات الامتثال الموجودة.

## سياسة الجاهزية وإعادة التهيئة

- يحمل رد الجاهزية نسخة السياسة ومصدرها `ADR-018` وتاريخ نفاذها. متطلبات التسجيل والضريبة والعنوان غير المثبتة قانونيًا لا تظهر كـ`MISSING`: هي `NOT_APPLICABLE` لليمن و`OPTIONAL` للسعودية والدول العامة حتى اعتماد مصدر رسمي خاص بالدولة.
- لا يُحتسب صف امتثال فارغ مكتملًا؛ يتطلب التسجيل والضريبة قيمة مقنّعة محفوظة، ويتطلب العنوان مكوّنًا ذا معنى.
- عند إعادة تشغيل التهيئة لشركة موجودة، يُثبت تطابق قالب الدليل المسجل قبل تحديث الملف. اختلاف القالب يرفض التهيئة ولا يغير `initialChartTemplateCode`.
- يمكن لصاحب صلاحية عرض الملف أو الامتثال اكتشاف صفحة الإعدادات وتحميل الجزء المصرح به وحده. لا تطلب الواجهة إعدادات الشركة أو العملات بلا صلاحياتها، ويُحدّث ملخص الجاهزية بعد حفظ الامتثال.

## الشعار والورق الرسمي

لا تدعم هذه الشريحة رفع ملفات ثنائية. يعيد العقد ميتاداتا قدرات `LOGO` و`LETTERHEAD` بالحالة `STORAGE_POLICY_REQUIRED` مع `uploadSupported=false` و`metadataAccepted=false`. يؤجل الرفع حتى اعتماد سياسة تحدد التخزين الخاص بالشركة، والتشفير، وفحص المحتوى، وأنواع الملفات وأحجامها، والاحتفاظ والحذف والتدقيق. لم تُنشأ روابط مؤقتة أو حقول مسار أو كائنات ثنائية يمكن أن تتحول إلى تخزين غير آمن.

## التوافق والترحيل

- تنشئ الترحيلة ملفًا لكل شركة قائمة وتضع `grandfatheredAt`، من دون جعل البيانات الجديدة شرطًا لاستخدام الحساب القديم.
- كل قالب جديد يبدأ بالحسابات الأساسية التاريخية نفسها ويحافظ على وسم المصدر `SMALL_BUSINESS_GENERAL`، ثم يضيف حسابات القالب المختار. يحافظ ذلك على الأكواد التي تعتمد عليها المستندات والمسارات القديمة.
- تتضمن الترحيلة SQL رجوعًا محروسًا، ولا تسمح بإزالة الجداول إذا كانت تحتوي بيانات ملف أو امتثال فعلية.

## التحقق المنفذ محليًا

- بناء الإنتاج لكل مساحات العمل، وفحص TypeScript لكل الـAPI والويب: ناجح.
- اختبار API الكامل: 139 ملفًا ناجحًا و44 متجاوزًا عمدًا؛ 1283 اختبارًا ناجحًا و194 متجاوزًا عمدًا.
- اختبار الويب الكامل: 66 ملفًا ناجحًا و4 متجاوزة عمدًا؛ 784 اختبارًا ناجحًا و34 متجاوزًا عمدًا.
- اختبارات الوحدة المركزة لخدمة الملف والسياسة وإعادة التهيئة والقوالب والتسجيل والحواجز: 7 ملفات و76 اختبارًا ناجحًا. اختبارات واجهة الملف والتنقل والصلاحيات: ملفان و23 اختبارًا ناجحًا.
- بوابات OpenAPI والترجمات والواجهة: ناجحة؛ الحارس المولد مطابق لـ187 جسم طلب و2396 جسم استجابة.
- MariaDB 10.4.32: نجحت حالات ملف الشركة الست، وتشمل `PATCH` المتداخل، وعدم إسقاط التحقق، وعزل الشركة، والتدقيق، ورفض عدم تطابق الدولة، وسباقًا حقيقيًا بين تغيير الدولة وإضافة العنوان. نجحت كذلك 15 حالة تسجيل/شركة مجموعة/تسجيل اجتماعي شملت رفض القالب القديم.
- E2E حقيقي على قاعدة معزولة: نجحت 12 حالة، ومنها التسجيل والتهيئة وإعداد العملة والفترة واستيراد عميل وإنشاء أول قيد، مع استكمال بقية رحلات النظام القائمة.
- اختبار بصري عبر العربية والإنجليزية والهندية والأردية: 8 حالات ناجحة على الهاتف وسطح المكتب، و8 حالات أحجام إضافية متجاوزة عمدًا وفق مصفوفة الاختبار.

لم تتوفر خدمة MySQL 8.4 أو Docker على المضيف، لذلك نُفذ اختبار قاعدة البيانات الفعلي على MariaDB 10.4.32 فقط. احتاج مشغل E2E محليًا إلى ضبط منطقة MariaDB العامة مؤقتًا إلى UTC بسبب اختلاف ساعة خدمة XAMPP عن تحويل Prisma، ثم أعيدت فورًا إلى `SYSTEM`. لم يحدث دفع بعيد أو نشر.
