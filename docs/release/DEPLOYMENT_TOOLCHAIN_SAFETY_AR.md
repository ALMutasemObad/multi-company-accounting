## مدى وصول مسارات Prisma

- [Studio في وسم 7.9.1](https://raw.githubusercontent.com/prisma/prisma/7.9.1/packages/cli/src/Studio.ts) يستورد `mysql2/promise` ديناميكيًا لإنشاء pool عند اختيار MySQL. النص المنشور في `prisma/build/cli.js` يطابق ذلك؛ لا يوجد mysql2 مضمّن داخل الملف يتجاوز npm override.
- [MigrateDeploy](https://raw.githubusercontent.com/prisma/prisma/7.9.1/packages/migrate/src/commands/MigrateDeploy.ts) يستدعي [Migrate.setup](https://raw.githubusercontent.com/prisma/prisma/7.9.1/packages/migrate/src/Migrate.ts)، الذي ينشئ [SchemaEngineCLI](https://raw.githubusercontent.com/prisma/prisma/7.9.1/packages/migrate/src/SchemaEngineCLI.ts) ويستخدم محركًا أصليًا منفصلًا. [فحص وجود القاعدة](https://raw.githubusercontent.com/prisma/prisma/7.9.1/packages/migrate/src/utils/ensureDatabaseExists.ts) يمر بدوره بمرافق المحرك.
- الاستنتاج من المصدر: لا يثبت audit أن الثغرتين قابلتان للاستغلال عبر `migrate deploy` في هذا الإعداد. الاستخدام المباشر الذي وجدناه لـmysql2 هو Studio. يبقى تنزيل CLI وشجرته خارج lock خللًا في قابلية إعادة الإنتاج حتى لو لم يدخل مسار mysql2 أثناء الترحيل.
- التطبيق يستخدم `@prisma/adapter-mariadb` وmariadb المقفلة مسبقًا؛ لم تتغير تلك الحزمة أو Prisma Client أو schema أو migrations أو الحراس أو عقود الأعمال.

## المعالجة المنفذة

1. إضافة override ثابت `mysql2: 3.23.1` وتحديث القفل عبر `npm update mysql2 --package-lock-only`. تغيرت mysql2 وتبعيتها البديلة `sql-escaper` وأزيلت تبعيتاها اللتان لم تعودا مطلوبتين؛ بقي Prisma على `7.9.1`. لم يُستخدم `audit fix --force`.
2. إضافة manifest وlock مستقلين تحت `deploy/scripts/prisma-toolchain`. يتطلبان Prisma `7.9.1` ويقفلان mysql2 `3.23.1` وdeepmerge-ts `8.0.1`، مع allowScripts صريح فقط لـPrisma ومحركاته. لا مشاركة لمجلد الاعتماد مع التطبيق أو مهمة أخرى.
3. ينفذ packager `npm ci` بالنسخة `12.0.2` ثم audit كامل لحزمة الأداة بحد moderate قبل إنشاء release manifest. مسار `deploy/scripts` مشمول أصلًا في create-release؛ يدخل CLI ومحركه وجميع ملفاته تحت بصمات manifest وأرشيف الإصدار. لم نعدل create-release أو manifest أو workflow.
4. يستدعي اختبار roundtrip وinstall-cpanel المشغّل المضمّن بالمسار المطلق. أزيل `npx prisma@7.9.1` وإعداد `MCAP_NPX_CLI` من المثبّت. لا تثبيت npm على المضيف ولا تنزيل CLI وقت الترحيل.
5. يتحقق المشغّل من نسخ Prisma وmysql2 والمحركات ومن بقائها داخل مجلد الأداة. يفرض وجود محرك أصلي واحد مطابق للمنصة ويحدد مساره صراحة لمنع رجوع Prisma إلى تنزيل المحرك، ويتجاهل مسار المحرك الخارجي من البيئة. يسمح فقط بالإصدار وvalidate وmigrate deploy/status، ويحافظ على exit code. يفحص المثبّت الأداة بعد مصادقة الأرشيف وقبل فحص هوية قاعدة البيانات والترحيل؛ يبقى ترتيب التحقق ثم الترحيل ثم seed ثم التفعيل محفوظًا. فحص الإصدار يعمل من دليل الأداة حتى لا يحمّل إعداد قاعدة بيانات يخص دليل المستدعي.

هذا يضيف أدوات الترحيل إلى **الأرشيف الكامل** في مسار منفصل، بينما يبقى node_modules الجذري للتطبيق مقلمًا. لا يصح وصف الأرشيف الكامل بأنه runtime-only بعد هذا التغيير. مالك تحديث القفلين وأدلة audit هو مسؤول أدوات النشر؛ يجب تحديثهما معًا عند ترقية Prisma ومراجعة الثغرات مجددًا قبل الإصدار.

## الأدلة المحلية الحالية

- Node `24.19.0`، npm `12.0.2` منزلة من registry الرسمي مع مطابقة SHA512 لـdist.integrity قبل فكها. الاعتمادات مثبتة بـci لكل شجرة مستقلة. أول `install --package-lock-only` للجذر لم يغير mysql2 القائمة؛ كشف فحص النسخة ذلك ثم استُخدم update المحدود وأعيد ci بنجاح.
- audit كامل التطبيق وأداة الترحيل: صفر ثغرات، دون omit-dev لإخفاء أداة الترحيل. الأدلة `test-results/toolchain-evidence/audit-*.json` محلية متجاهلة.
- 28/28 اختبار أدوات نشر ومشغّل وmanifest؛ تشمل fail closed عند غياب CLI أو محركه أو نسخة mysql2 الصحيحة أو عدم توافق المنصة، ورفض محرك خارجي من متغير البيئة، ومنع أوامر إضافية، وتمرير خروج CLI. فحصا mysql2 ينفذان دون شبكة: رفض المصادقة النصية الافتراضية دون كتابة، ورفض فك ضغط 32 بايت مع طول معلن 31 بايت. لا exploit ضد خادم.
- نجح Prisma generate، وفحوص i18n وUI وإزالة العلامة التجارية وgit diff --check. هذه نتائج مستقلة عن بناء التطبيق والترحيلات.
- فشل بناء API الأول في TypeScript7 بسبب `VirtualAlloc errno1455` ونفاد الذاكرة الافتراضية أثناء ضغط المهام. نجحت الإعادة في نافذة منفردة باستخدام `--singleThreaded` و`GOMAXPROCS=2` و`GOMEMLIMIT=768MiB` وحد ذاكرة Node مقداره 768MiB: بناء API، وفحص أنواع الواجهة، وVite build. بقي تحذير chunks أكبر من 500kB في الواجهة، خارج نطاق إصلاح الاعتماد.
- إعادة `npm ci` لشجرة CLI تركت بصمات القفل ثابتة؛ البصمات محفوظة في `lock-hashes-before.json`.

الصورة الرسمية الموجودة مسبقًا `node@sha256:83f487e0a63425e5b4d146fb5e5be574bcbe1b7b843d3ebafdd95eaf7767a7e5`، Node22.23.2، Linux x64. استُخدمت حاوية نشطة واحدة في كل وقت، بحد 0.5CPU و512MiB وmemory-swap512MiB وpids64، دون capabilities أو privileged أو host network أو منافذ أو volumes إنتاج. مرحلة ci استعملت شبكة اختبار منفصلة؛ توقفت حاوية البناء قبل بدء حاوية smoke ذات `network=none`. لم يُشغّل محرك قاعدة بيانات على الخادم.

## إغلاق تخمين OpenSSL بعد استئناف العمل

بعد نقل المساحة إلى E ونجاح Check أُضيف الحاجز النهائي: قراءة `getPlatformInfo` والتحقق من الملاحظات الأصلية `libssl` و`targetDistro`، بدل الاكتفاء بـbinaryTarget الذي قد يكون افتراضيًا. غياب libssl معروف يفشل بخروج 1 ورسالة `TOOLCHAIN_OPENSSL_ABI_UNKNOWN`؛ عائلة Linux غير المعروفة/غير المدعومة تفشل بـ`TOOLCHAIN_LINUX_ABI_UNKNOWN`. يحدث ذلك قبل إطلاق CLI أو المحرك؛ يظل probe نظام التشغيل الذي ينفذه get-platform جزءًا من اكتشاف المنصة.

- نجحت 11/11 اختبارات محدودة بعد التغيير، دون إعادة تثبيت: اختبارات launcher وmanifest. عينة Linux مجهولة SSL تفشل بخروج 1 وstdout فارغ؛ عينات libssl1.0.x و1.1.x و3.0.x المعروفة تصل إلى CLI التجريبية ولا تُرفض بالخطأ؛ واختبرت أيضًا غياب عائلة Linux وعدم تطابق المحرك. هذه الحالات الموجبة محاكاة لنتيجة الكاشف، وليست شهادة منصات Linux فعلية.
- نجح الإصدار وvalidate بالمشغّل النهائي على Windows، والأخير مع منع Node sockets. لا إعادة بناء أو تشغيل DB متزامن مع مهمة onboarding بعد النقل.
- في نافذة Linux ثانية، دون تنزيل أو تثبيت، نُقل المشغّل النهائي وحده ببصمة `bbd79ba091ab41499dec7b6b44bc74f7f3c735ebc835d605b7d710f136342655`. استُخدمت الصورة السابقة بلا شبكة وبـmount للقراءة فقط. أصبح فشل OpenSSL فيها **متوقعًا ومثبتًا**: خروج CLI يساوي 1، الرمز السابق ظاهر، stdout يساوي صفرًا. نجح اختبار الرفض نفسه بخروج الحاوية 0 وOOM=false. أُزيلت حاوية الجولة الثانية فقط بعد حفظ سجلها، وأُبقيت الملفات والصورة؛ لا prune.
