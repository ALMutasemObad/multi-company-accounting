## النتيجة الملموسة

- حُسنت دلائل التسجيل وإيصال البريد، وبقي ظهور Google وApple مرتبطًا بجاهزية
  المزود الحقيقي بدل عرض أزرار غير قابلة للاستخدام.
- أصبحت رحلة إنشاء شركة أخرى داخل المجموعة أوضح، وتحفظ نتيجة الإنشاء عند فشل
  التحديث، وتحجب الردود القديمة، وتتيح فتح الشركة الجديدة بعد ظهورها.
- أصبحت الوحدات المشمولة والاختيارية والإضافات مصنفة وقابلة للترشيح، مع بقاء
  التفعيل الفعلي في مسار مراجعة الاشتراك دون ادعاء دفع أو تفعيل غير منفذ.
- يكتشف البناء أي ملف `*.locale.ts` ذاتي مكتمل تلقائيًا، ويضيفه إلى مبدل اللغة
  ويحمّله كسولًا دون تعديل registry أو core أو Vite. تقبل الواجهة والعقد والخادم
  locale آمنًا وفق BCP47، ويعود قالب البريد بالترتيب exact ثم base ثم العربية.
- تبدأ فواتير البيع والشراء داخل الفترة المفتوحة مع اتساق تاريخ المستند والاستحقاق.
- أصبحت تبويبات التقارير قابلة للوصول بلوحة المفاتيح ومرتبطة بلوحة واحدة معنونة.
- حُجبت أفعال القيود والفترات والحسابات ومراكز التكلفة وفق الصلاحية الدقيقة، مع
  حراسة العرض وتركيب النموذج والمعالج وطلب الشبكة، وفصل قراءة دليل الحسابات عن
  إدارة مراكز التكلفة.

## مصالحة الدمج الدلالية

لم تظهر تعارضات نصية أثناء الاستيراد، لكن المراجعة كشفت تعارضًا دلاليًا صامتًا:
ملفات اللغات في التزام المنصة سبقت 16 مفتاحًا أضافتها موجتا الوحدات وشركات
المجموعة. أُعيدت المفاتيح الستة عشر إلى اللغات الأربع، فأصبحت كل لغة تحتوي
`3502` مفتاحًا متطابقًا وتستهلكها الاختبارات الفعلية.

نُقل اختبار التقارير إلى `reports-tab-accessibility.spec.ts` قبل استيراد اختبار
التدقيق العام كي يبقيا رحلتين مستقلتين. كما سُجل plugin اكتشاف اللغات داخل
harnesses متصفح Vitest، وثُبتت جذورها ومساراتها، وأُعطي كل suite `cacheDir`
مستقلًا؛ أثبت التشغيل المتوازي عدم عودة خطأ `EPERM`.

فُعّلت حواجز التدقيق التي أصبحت إصلاحاتها موجودة فعلًا: منع الكتابة لمستخدم
العرض فقط، تواريخ الفواتير داخل الفترة المفتوحة، إخفاء إنشاء الحساب دون
`accounts.create`، وفتح دليل الحسابات بـ`accounts.view` وحدها. بقيت حواجز
`fixme` الأخرى غير منفذة ولا تُحسب نجاحًا.
