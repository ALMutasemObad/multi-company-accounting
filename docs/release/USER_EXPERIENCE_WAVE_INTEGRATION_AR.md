# تكامل موجة تجربة الوصول والمجموعة والإضافات

## القرار

استوردت التزامات المهام الثلاث مرة واحدة وبالترتيب إلى فرع تكامل مبني على
`origin/main` المتحقق منه عند `731fc11f3635143558fcd6431b864afd0807ff53`.
تم الاستيراد بلا تعارض، وبقيت التغييرات ضمن واجهة الويب واختباراتها ووثائقها؛
لا يوجد تعديل على OpenAPI أو Prisma أو `App.tsx` أو ملف القفل.

المرشح المحلي يجمع ثلاث نتائج:

1. إثبات أقوى لصدق التسجيل والبريد وظهور Google/Apple فقط عند جاهزية المزود.
2. رحلة أوضح لإنشاء شركة أخرى، تحفظ النجاح عند فشل التحديث وتتيح فتح الشركة بعد
   ظهورها، وتحجب الردود القديمة.
3. تصنيف ومرشحات وعدادات للوحدات المشمولة والاختيارية والإضافات الحالية، مع بقاء
   التغيير في مسار مراجعة الاشتراك وعدم ادعاء تفعيل أو دفع.

## التحقق المجمع

- اختبارات متصفح الوصول والتسجيل: `22/22` ناجحة.
- اختبارات نص وحالة بريد التسجيل: `8/8` ناجحة.
- اختبارات Chromium المركزة لإنشاء شركة المجموعة: `7/7` ناجحة.
- اختبارات وحدة كتالوج الإضافات: `26/26` ناجحة.
- Playwright المجمع لتجربتي المجموعة والإضافات: `18/18` ناجح للعربية
  والإنجليزية والأردية والهندية عند عرضي `390px` و`1440px`.
- TypeScript للواجهة، وبناء Vite للإنتاج، وبوابتا i18n وUI: ناجحة.
- بقي تحذير حجم حزمة `employee-expenses` الأكبر من 500kB، وهو سابق لهذه الموجة
  ولم يتحول إلى فشل بناء.

شغلت الاختبارات التي تنشئ Vite من جذرها الصحيح: اختبارات الوصول من جذر المستودع،
واختبار المجموعة المركز من `apps/web`. محاولتا تشغيلهما من جذر غير مناسب أُوقفتا
ولم تُحتسبا ضمن النتائج أعلاه.

## الحدود ودورة الإصدار

- HTTP في اختبارات الواجهة محاكى؛ لم تُشغل MariaDB/MySQL لأن هذه الموجة لا تغير
  API أو مخططًا أو ترحيلًا أو منطق صلاحيات خادميًا.
- لم يُرسل بريد حي ولم يحدث اتصال حي بـGoogle أو Apple، ولم تستخدم أسرار مزودين.
- لم تُنشأ شركة حقيقية في بيئة مستضافة ولم تُغيّر استحقاقات أو تُجر دفعة.
- لا push أو PR أو دمج بعيد أو نشر في هذه الجولة. يحتاج أي انتقال بعيد إذنًا صريحًا
  جديدًا، ثم بوابات CI والإصدار الخاصة بالتزام المرشح.
