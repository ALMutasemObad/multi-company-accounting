# حدود صلاحيات الكتابة في المخزون

المهمة `inventory-permission-boundaries` مبنية على `origin/main` المتحقق منه عند
`731fc11f3635143558fcd6431b864afd0807ff53`. التنفيذ محلي في worktree مستقل،
ولا يتضمن API أو OpenAPI أو قاعدة البيانات أو الترجمة أو مصروفات الموظفين.

## النتيجة

بقيت أقسام المستودعات والكتالوج والأرصدة والحركات قابلة للقراءة وفق بوابات العرض
القائمة، بينما أصبحت كل كتابة ظاهرة ومركبة ومنفذة فقط بالصلاحية الدقيقة التي
يفرضها API:

| المجال | الصلاحية | الأفعال المحروسة |
| --- | --- | --- |
| المستودعات | `warehouses.manage` | إنشاء المستودع وتعديله وتعطيله |
| وحدات القياس والأصناف | `inventory_catalog.manage` | الإنشاء والتعديل والتعطيل |
| حركات المخزون | `inventory_movements.create` | إنشاء الحركة وتهيئة تقييم الرصيد التاريخي |
| عكس الحركة | `inventory_movements.reverse` | فتح نموذج العكس وإرساله |

لا تمنح صلاحيات العرض أي كتابة ضمن هذه المصفوفة، ولا تمنح صلاحية إنشاء الحركة
عكسها أو العكس.

## طبقات الحراسة

- تستخدم الأزرار والإجراءات `Can` بالسياسة الدقيقة؛ لا يرى مستخدم العرض فقط
  أزرار الإنشاء أو التعديل أو التعطيل أو التقييم أو العكس.
- لا تُركب نماذج المستودع أو الوحدة أو الصنف أو الحركة أو التقييم أو العكس ما لم
  تبقَ الصلاحية المطلوبة فعالة، وتُغلق الحالة المفتوحة عند سحب الصلاحية.
- تتحقق handlers من الصلاحية قبل فتح النموذج أو إظهار `prompt`، وتتحقق دوال
  `submit` مرة أخرى قبل التحقق التجاري أو إنشاء مفتاح idempotency أو طلب الشبكة.
- بقي عرض تفاصيل حركة المخزون إجراء قراءة متاحًا؛ يظهر زر العكس داخله فقط عند
  اجتماع صلاحية العكس مع شروط العمل القائمة للحركة اليدوية المنشورة.
- بقيت صلاحيات الباركود ومساحة ملف بيع الصنف مستقلة كما كانت، ولم تُوسّع هذه
  المهمة نطاقها أو تعيد تعريفها.

## دليل الاختبار

- اختبار السياسة الوحدوي: **7/7 ناجحة**. يثبت التطابق الحرفي مع صلاحيات API،
  وأن صلاحيات العرض لا تمنح كتابة، واستقلال الصلاحيات الأربع، وربط التقييم
  بإنشاء الحركة دون منح العكس.
- Playwright على `390×844` و`1440×900`: **8/8 ناجحة**.
  - مستخدم العرض فقط تصفح الأقسام الخمسة ورأى البيانات، بلا أفعال كتابة أو نموذج
    أو prompt أو طلب كتابة.
  - `warehouses.manage` أظهر أفعال المستودعات وحدها.
  - `inventory_catalog.manage` أظهر أفعال الوحدات والأصناف وحدها.
  - اختُبر `inventory_movements.create` و`inventory_movements.reverse` كل على
    حدة، بما في ذلك نموذج التقييم ونموذجا الإنشاء والعكس، وبقيت الطلبات الكتابية
    صفرًا لأن الاختبار اقتصر على العرض وتركيب النماذج.
- أول مرور Playwright نجح في 6 حالات وفشل في حالتين بسبب محدد اختبار صارم وجد
  الاسم الإنجليزي مرتين داخل الصف نفسه؛ استُبدل برمز الصف الفريد، ثم نجحت الإعادة
  الكاملة 8/8. لم يكن الفشل سلوك منتج.
- TypeScript للويب وTypeScript لاختبارات E2E/Visual: ناجحان.
- Web Vitest الكامل: **54 ملفًا و718 اختبارًا ناجحًا**، مع **4 ملفات و16
  اختبارًا skipped** لأن تشغيلها مشروط بمتغيرات بيئية. لم تُحسب الحالات المتخطاة
  نجاحًا ولم تكن ضمن تغيير المخزون.
- بناء Vite الإنتاجي: ناجح. ظهر تحذير chunk `employee-expenses` بحجم
  `591.43 kB` الموجود في فرع الأساس؛ لا ينتج من تغيير المخزون، وتتعامل معه منصة
  اللغات في مرشح تكامل مستقل.
- بوابة UI: ناجحة، `31` رأس صفحة و`68` منطقة جدول.

## الحدود

- API في Playwright محاكى محليًا، ولم تُرسل عملية حفظ أو تعطيل أو تقييم أو حركة
  أو عكس، ولم تُستخدم قاعدة بيانات أو بيانات حية.
- الخادم يظل حد الإنفاذ الأمني النهائي؛ هذه المهمة تمنع الواجهة المضللة والرفض
  المتأخر، ولا تستبدل RBAC الخادمي.
- لم يحدث push أو PR أو دمج بعيد أو نشر.
