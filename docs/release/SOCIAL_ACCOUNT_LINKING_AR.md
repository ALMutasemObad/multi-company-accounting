# تسليم أمان الحساب وربط Google وApple

## المنفذ

أضيفت شاشة «أمان الحساب» بأربع لغات واتجاهي RTL/LTR ومقاسين أساسيين للنص. تعرض
المزودات المهيأة فقط، وحالة كل مزود وتاريخ الربط، وتتطلب تحديد موافقة صريحة قبل
الربط أو الفك. لا تعرض الشاشة أو استجابة API `issuer` أو `subject` أو البريد أو
tokens.

أضيفت عمليتا OpenAPI للعرض والفك، وأعيد توليد حراس الطلب والاستجابة. الربط يستخدم
رحلة OIDC القائمة مع recent-auth وCSRF وstate/nonce/PKCE وربط المتصفح، ويعود إلى
شاشة الأمان بعد callback مع تدوير SID والمحافظة على سياق الشركة. يرفض الفك إزالة
آخر وسيلة دخول ويكتب SecurityEvent ذريًا. يضيف الترحيل 74 قيد هوية واحدة لكل مزود
لكل مستخدم، ويفشل مغلقًا عند بيانات مكررة بلا حذف.

## تحقق قاعدة البيانات

شُغل المحركان بالتتابع على قواعد وdatadir جديدة تحت
`E:/CodexTaskArtifacts/social-account-linking-20260907` ثم أوقفا طبيعيًا:

- MySQL 8.4.11: fresh لجميع الترحيلات الـ74 وseed؛ اختبارات الربط والفك والسباقات
  `11/11`. نجح upgrade اليدوي 73→74، وفشل الترحيل كما هو مطلوب مع صفين مكررين
  وبقيا صفين، ثم نجح بعد إزالة نسخة الاختبار. نجح rollback وإعادة التطبيق.
- MariaDB 10.11.16: الأدلة نفسها؛ fresh 74 وseed، والاختبارات `11/11`، وupgrade
  وفشل مغلق يحافظ على الصفين، ثم rollback/reapply.

غطت الاختبارات: الخصوصية، إخفاء المزود غير المهيأ، recent-auth، CSRF، الموافقة،
آخر عامل، حساب كلمة مرور، حساب اجتماعي، مزودين، فكين متزامنين، replay وربط
المتصفح وتدوير الجلسة والعودة إلى شاشة الأمان، واستهلاك معاملة callback الملغاة
ومنع إعادة استخدامها. بعد الاختبارات لم يبق أي
`mysqld`/`mariadbd` أو listener على 3398/3399.
