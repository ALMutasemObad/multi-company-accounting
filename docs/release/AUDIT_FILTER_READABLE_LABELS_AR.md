# تسميات فلاتر سجل التدقيق المقروءة

التاريخ: 2026-09-08

الفرع: `task/audit-filter-readable-labels`

خط الأساس: `731fc11f3635143558fcd6431b864afd0807ff53`

## النتيجة

تعرض فلاتر الإجراء ونوع الكيان ترجمة اللغة الحالية عندما يوجد مفتاح مسجل، وتعرض fallback محليًا ومقروءًا عند وصول كود فعلي أو مستقبلي بلا ترجمة. بقيت قيمة `<option>` ومعامل الاستعلام code الأصلي حرفيًا، لذلك لم يتغير عقد API.

ثبت الاختبار القبلي أن `POS_SALE_COMPLETED` كان يظهر كنص خام في قائمة الإجراءات. بعد الإصلاح أصبح مثلًا:

- العربية: `إجراء غير معروف — POS sale completed`
- الإنجليزية: `Unknown action — POS sale completed`
- الأردية: `نامعلوم کارروائی — POS sale completed`
- الهندية: `अज्ञात कार्रवाई — POS sale completed`

وينطبق النمط نفسه على `POS_SALE` باستخدام تسمية «كيان غير معروف» المترجمة.

## التصميم

- helper محلي `audit-filter-labels.ts` يعيد الترجمة الحالية للأكواد المعروفة.
- الأكواد غير المعروفة تُجزأ عند `_` أو `-` أو `.` وتعرض بكلمات مقروءة، مع الحفاظ على الاختصارات `API` و`CSV` و`FX` و`ID` و`PDF` و`POS`.
- الكود الفارغ أو المكوّن من فواصل فقط يعيد تسمية «غير معروف» غير فارغة ولا يسبب انهيارًا.
- لم تُضف مفاتيح i18n؛ استُخدمت المفاتيح الحالية `audit.unknownAction` و`audit.unknownEntity`.

## دليل المتصفح

غُطيت اللغات `ar` و`en` و`ur` و`hi` على عرضي 390 و1440 بكسل. تحقق الاختبار من:

- ترجمة `CUSTOMER_CREATED` و`CUSTOMER` في اللغات الأربع.
- fallback المقروء لـ`POS_SALE_COMPLETED` و`POS_SALE` دون نص option خام.
- بقاء `option.value` كما ورد من الخادم.
- إرسال `action=POS_SALE_COMPLETED` و`entityType=POS_SALE` حرفيًا عند تطبيق الفلاتر.
- إزالة المعاملين عند مسح الفلاتر.
- صفر طلبات كتابة، وصفر أخطاء صفحة، وعدم تجاوز عرض الشاشة.
