## تنظيم العمل ومنع الانجراف

- نسخة مرجعية محلية واحدة على `main`؛ لا تنفيذ متوازٍ داخلها.
- سجل واحد لمسارات المهام والمسؤولين والفروع ومعايير القبول، بحد أقصى ثلاث مهام تنفيذ نشطة.
- لا نسخ كاملة بأسماء الموجات. worktree مستقل لكل مهمة من main المتحقق منه، وتثبيت اعتماد مستقل خصوصًا Prisma Client.
- أرشفة العمل القديم مع الحفاظ على الفروع والتعديلات والأدلة؛ لا يعد الفرع النظيف دليلًا على أنه مدمج، خصوصًا مع squash merge.
- [حزمة تنظيم مساحة العمل](../workspace-kit/README_AR.md) تحفظ الأدوات والقواعد المحلية للمراجعة، ولا تستبدل سجل الإصدار أو ملفات البيئة.
- لا دفع أو نشر تلقائي بناءً على هذه الوثيقة؛ أي نشر جديد يحتاج إذن المالك الصريح.

## العمل المتبقي حسب الأولوية

1. مراجعة تغييرات العمل القديم غير المدمج قبل أي استيراد أو حذف، وقبول حزمة تصحيح التوثيق بصورة مستقلة.
2. اختيار شرائح المستخدم التالية بمعايير قبول واضحة، مع اختبارات الشركة والصلاحيات والواجهة، وإدارة تسلسل العقد والترحيلات مركزيًا.
3. تتبع تحذير حجم حزمة مصروفات الموظفين وتحذير مكون OpenAPI غير المستخدم كتحسينات لاحقة؛ لم تُعالجا في جولة التنظيم.
4. الرواتب والأصول الثابتة والتجميع المالي وIntercompany وفحص تعارض المصالح F2 ليست منفذة بهذه الجولة. تظل المطابقة البنكية خلف ضوابط تفعيلها؛ لا يوسع التنظيم صلاحياتها.
5. التكامل مع مزود دفع حي، والإطلاق إلى الإنتاج، وأي متطلبات محلية نظامية تحتاج قراراتها ومراجعاتها الخاصة، ولا تُفترض من واجهات العرض.

ابدأ كل مهمة بقراءة `AGENTS.md` وفحص Git وسجل العمل المحلي. لا تنفذ التعليمات المؤقتة
في تسليم قديم قبل مطابقتها بهذه الحالة والكود الحالي.
