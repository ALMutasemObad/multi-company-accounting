# قياس قراءات الاشتراك محليًا — مسار G

التاريخ:2026-08-31. هذه أداة تشغيل وفحص محدودة ضمن دفعة
`feat/subscription-operational-readiness`، وليست اختبار حمل ممثلًا أو إثباتًا لحل
حادثة بطء الاستضافة أو معايرةSLO. لا تغيّر إعدادات الخادم أو Connection Pool.

## عقد السلامة

- تقبل أصولHTTP/HTTPS على127.0.0.1 أوIPv6 loopback فقط؛ localhost يثبت إلى
  127.0.0.1 دونDNS. لا credentials/path/query/hash في الأصل، ولا قبول لمسار حر
  أو method أو headers إضافية أو تعطيلTLS. لا تتبعredirect ولا تعاود الطلب.
- يسمح GET فقط لخمس حالات:public-plans،subscription-usage،subscription-catalog،
  billing-invoices،billing-payments. صفحات القراءة محدودة9/20/10/10؛ لا جلب
  كتالوج كامل أو إنشاء/إلغاء/دفع/دخول/CSRF أو بريد.
- الافتراضي12 طلبًا بتزامن1 وفاصل150ms لكلworker، ومدةكلية10s ومهلةطلب2s.
  الحدود القصوى200 طلب/4workers/60s، والحدالأدنى للفاصل50ms. حجم الاستجابة
  المسموح الافتراضي256KiB والأقصى1MiB؛ لا يحتفظ البرنامج بجسم الاستجابة.
  قد تصل قطعةHTTP واحدة تتجاوز حدالحجم قبل إغلاق المقبس، دون تجميعها.
- أي429/503 يوقف الجولة ويقطع انتظار بقية القراءات؛401/403 توقفها كذلك.
  redirect وأيnon-2xx أوانقطاع أوتجاوزمهلة/حجم توقف دونretry. Ctrl+C يوقف
  جدولةالمزيد. إغلاق العميل لا يثبت إلغاءQuery سبق إرساله إلىقاعدةالبيانات.
- جلسةاختبار صالحة عند القراءات الخاصة تأتي من متغيرالبيئة
  `SUBSCRIPTION_PROBE_SID` فقط، وليستCLI أوملفإعداد. العامة لا ترسلها حتى لو
  وجدت. لاPassword/CSRF/Token/Body/Set-Cookie أوتفاصيلأشخاص/أنشطة في التقرير.
  التقريريسمح بالحقولالمجمعة صراحة، ولا يطبع errors الخام أوURL غيرصالح.
- شغّلها علىعمليةمحلية مملوكةلك وبياناتاختبار فقط. loopback قد يكونproxy أوSSH
  tunnel إلىاستضافة؛ **هذا غيرمسموح ضمن هذاالإجراء**. لا تستخدمجلسةحقيقية أو
  تستهدف بيئة مشتركة أو مُستضافة دونتفويضقياس مستقلبنطاقومدةومتوقفات واضحة.

الأرقام أعلاه حدودأمان للأداة الصغيرة، وليست قيمسعةERP أوSLO أوحجمPool مقترحًا.

## الاستخدام

بعد تشغيلAPI محلي مخصص، منجذرالمستودع:

```powershell
npm run performance:subscription-reads -- --base-url http://127.0.0.1:3133 --scenario public-plans --requests 6 --concurrency 1
```

لـsubscription-usage أوالكتالوج/الفوترة، جهزجلسةاختبار بالنشاط والصلاحياتالصحيحة
فيالعمليةالمحلية، واحقنSID منمصدرمحليآمن إلىبيئةالعملية. لا تضع القيمة فيالأمر
أووثيقة أوتقرير. الأداةلا تنشئالجلسة ولا تغيرالنشاطالمحدد فيها. يمكنفحصالبروتوكول
بالـvisual-QA fixture معtoken اصطناعي، لكنهلايثبتمصادقة أوRBAC حقيقيين.

يخرجJSON إلىstdout، وexit0 فقط إذااكتملالعددبنجاحاتHTTP؛غيرذلكexit1.
`validation:HTTP_STATUS_ONLY` يعنيأن200 لايثبت صحةJSON أوالمحاسبة أوعزل
البيانات؛ اختباراتالعقدوالخادمهيالتيتفعلذلك. لا تضع secret فيstdout captures.

التقريريشملالميزانيات والعددوحالاتHTTP وأسبابالتوقف والحجم ومدةالقراءة ووقت
وصولالرؤوس. p50/p95/p99 بطريقةnearest-rank لنجاحاتHTTP فقط؛النتيجةالخاليةnull
وليستصفرًا، وتظهرأعدادالفشل منفصلة حتىلايختفيالفشل خلفlatency جيد.
`completedReadsPerSecond` يشملالفواصلوزمنالجولة، وليسThroughput أقصى للخادم.
إعادةالاتصالkeep-alive مقصودة؛ لا يقيسالسيناريو handshake جديدًا لكلطلب.

## الأدلة المحلية وحدودها

اجتاز `node --test scripts/tests/subscription-read-probe.test.mjs` عدد22 اختبارًا:
رفضالأصولوالمدخلاتغيرالمسموحة،ضبطالتزامنوالعدد،النسبالمئوية،عدمإرسالسر في
العامة أوإخراجهبالتقرير،كلالحالاتالخاصةومحدوديةصفحاتها،ضغط/auth/redirect/500،
حدالحجم،مهلةالرؤوسوالجسم،المدةالعامة،الإلغاءقبل/أثناءالقراءة،انقطاعbody،
إعادةاستخدامالمقبس،وتنقيحخطأCLI. مكوناتHTTP تجريبية ولاقاعدةبياناتبها.

شُغلتالأداةفعليًا على `scripts/visual-qa-server.mjs` المخصصبمنفذ3133، ثمأوقف
المنسقعمليتهفقط. عند07:41UTC نجحت6/6 قراءةعامةبتزامن1،ثم6/6 استهلاكبتزامن2؛
جميعهاHTTP200 دونكتابات. هذهعيناتصغيرةلاختبارالأداةبالـfixture؛ لا ننشرمنها
مؤشرأداءللاستضافة أوتحسنDB أورقمSLO. لم يتصلالقياسبالموقعالعام.

## المرحلة التي تسبق معايرة فعلية

1. افتحبيئةقياس معزولة ومصرحًابها علىMariaDB10.11 وMySQL8.4، معنسخةكودمثبتة
   وحجومأنشطة/مستخدمين/مستنداتقابلةللإعادة وحالاتفارغةوكبيرة وحدودفترةUTC.
   دوننسخبرمجيةلأسرار/أشخاص أوتشغيلتحصيل/رسائلحقيقية.
2. سجلنفسإعداداتعددعملياتAPI وPool لكلعملية وسعةDB المتاحة، ومواردCPU/RAM
   ونقطةالاتصالوwarm/cold. يوجدحاليًاإعدادبيئيصريح فيconfig/database-pool-options؛
   لمتغيرهذهالدفعةالقيمالافتراضية. راجع `operational-resilience.md` للمعايرة.
3. قسالمساراتبمزيجواقعي وتدرجتزامنمعتمد، معlatencyومعدلاتالفشل والـdeadlines
   وقياساتCPU/الذاكرة وانتظارالقاعدة وأعدادSQL وخطةEXPLAIN عندالحاجة.
   metrics الحاليةتجمعفئاتHTTP محدودة؛ ليستكلهاقياسًاخاصًابمساراشتراك.
4. قبل/بعدبنفسالبياناتوالإعدادات وبعدعددعيناتكافٍ، افصلTLS/الشبكةمنزمنAPI/DB،
   وأوقفالحملعندالضغط. الأداةالصغيرةبحد200/4 ليستكافيةلاختبارتحملأوطويلالمدة؛
   أيأداةحملأوسع تحتاجتفويضًاوميزانيةمواردجديدين، لا رفعحدودهذهالأداةبصمت.
5. اعتمدSLO وPool فقطبعدالدليل؛ إزالةAudit.count غيرالمستخدمتثبتتقليلعملمنطقي
   واحد، لا نسبةlatency بعينها. تبقىبواباتDB fresh+upgrade+E2E إلزاميةللدمج.
