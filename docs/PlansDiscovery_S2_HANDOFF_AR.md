## دلالة الكتالوج والميزات

- ينفذ `PlansDiscoveryRead` طلب `GET` واحدًا للصفحة المطلوبة إلى
  `/api/v1/public/subscription-plans?page=<page>` مع `credentials: "omit"`
  و`cache: "no-store"`. لا يطلب الجلسة أو الشركات أو CSRF لعرض الإعلان.
- مهلة واحدة قدرها 12 ثانية تشمل قراءة جسم الاستجابة، مع إلغاء ومنع تطبيق نتيجة
  متأخرة. إعادة المحاولة فعل صريح؛ لا retry أو prefetch أو تحميل لجميع الصفحات تلقائيًا.
- الحدود مطابقة لعرض ADR-019 القائم: 9 عروض في الصفحة، و100 وحدة للعرض، وصفحات
  من 1 إلى 1000. إذا تجاوز مجموع الصفحات الحد، يوضح النص نطاق العرض ويتوقف زر التالي
  عند 1000؛ لا يُدّعى أن المعروض يمثل جميع خطط الحساب.
- يتحقق قارئ العرض من بنية الكتالوج والحقول الضرورية ومعرفات النص والـDecimal والحدود؛
  الاستجابة غير الآمنة أو غير الصالحة تتحول إلى خطأ قراءة، ولا ينتج عنها كتالوج بديل.
- `loading` و`error` و`empty` حالات مستقلة. لا تعرض بيانات كتالوج مخزنة في حالة تحميل
  أو فشل؛ مسار تغيير الصفحة يمسح البيانات ويضبط التحميل مباشرةً. أضيف أيضًا حاجز
  لاختلاف `catalog.meta.page` عن الصفحة المطلوبة.
- فراغ الصفحة الأولى يعني أنه لا توجد عروض عامة ظاهرة الآن، لا أن الخطط «قيد التجهيز»
  أو أنه لا يوجد اشتراك. فراغ صفحة لاحقة يوضح احتمال تغير القائمة ويعرض عودة صريحة للأولى.
- الظهور العام ليس بيانًا باشتراك الزائر. غياب خطة أو إخفاؤها لا يلغي اشتراكًا قائمًا،
  ولا يمحو اختيارًا محفوظًا أو يستبدله بخطة أخرى.
- أعمدة الميزات مشتقة من الوحدات المرسلة فعلًا. `INCLUDED` و`OPTIONAL` وعدم عرض الوحدة
  معانٍ منفصلة؛ `null` ليس صفرًا، والصفر ليس «غير محدود». تعرض رسوم الوحدات الاختيارية
  بعملة الخطة ولكل دورتها وقبل الضريبة، دون تحويل رسوم سنوية إلى شهرية أو ترتيب ترقية من السعر.
- لا أسعار أو خطط أو وحدات fixture في كود المنتج. بيانات `Test offer` تستوردها ملفات
  الاختبار فقط؛ لا fallback تجاري ولا شهادات أو أسماء عملاء مختلقة.

## عقد الاختيار في أساس S2 وحدوده قبل تركيب المنسق

زر التسجيل ينتج `/#register?plan=<versionId>` بواسطة `registrationPlanHref` القائم.
المعرّف هو **معرّف إصدار نصي**، ولا يحول إلى `Number`. النقرة الصريحة تحفظ التفضيل
بواسطة `rememberSubscriptionPlan`؛ مجرد عرض الصفحة أو المقارنة لا يكتب اختيارًا.

رابط صاحب الحساب الحالي هو `/#login` مع حفظ الاختيار في `onClick` فقط. هذا قرار
انتقالي متعمد إلى أن يركب المنسق العقد المشترك؛ لا يصدر S2 رابط `#login?plan=` ثم
يدعي أن التطبيق يستهلكه، لأن الأساس يلتقط URL intent على التسجيل وحده.

التفضيل الحالي غير موثوق، مدته 24 ساعة وفي `sessionStorage` الخاص بالتبويب. عند منع
التخزين أو فتح رابط الدخول من تبويب آخر أو دون تنفيذ `onClick` قد يحتاج المستخدم
إلى الاختيار مجددًا داخل الحساب. هذا القيد ظاهر فوق البطاقات، وترتبط به روابطها
بـ`aria-describedby`. لا تُعد اختبارات helpers دليلًا على اكتمال رحلة المصادقة أو البريد
أو التبديل بين الحسابات والتبويبات.

بعد الدخول يجب أن تعاد مراجعة الإصدار والسعر والوحدات والتوافر من الكتالوج المصادق.
المعرّف الغائب يبقى اختيارًا غير متاح للمراجعة، ولا يُنشأ له option وهمي ولا يُختار
العرض الأول بدلًا منه. لا يرسل الاختيار أمر تغيير أو checkout أو تفعيل أو تحصيل.

## رقعة الربط المشتركة المقترحة للمنسق — غير منفذة في S2

**مقترح تاريخي للمراجعة، حلّ محله عمل المنسق اللاحق:** أبلغ المنسق عند الإغلاق بأنه
ركّب `subscriptionPlanHref` و`subscriptionPlanHash` و`subscriptionPlanForRoute`
في فرع next-wave، والتقاط login/register/subscription، وتطبيع route base في App
ونقل plan URL للمراجعة وحفظه عند التبديل، دون token/redirect/POST. الاختبارات كانت
جارية وقت الإفادة ولم يعد S2 تشغيلها. لا تُطبق الأسطر التالية فوق عمله؛ يحتفظ بها
التسليم لتوضيح الفجوة التي اكتشفها S2 وحدود المقترح المبكر.

هذه أسطر ربط مقترحة وليست إذنًا بتعديل shared أو ادعاءً بأنها مدمجة. تعتمد مصنعًا
واحدًا للروابط المحلية، ولا تكرر حفظ التفضيل أو تعريف صحته في مكونات S2.

### 1. مصنع canonical في `public-plans.ts`

يبقى `validPlanId` ومالك التخزين الحاليان في الملف نفسه. يستبدل تعريف
`registrationPlanHref` القائم بالتعريفات التالية:

```ts
export type SubscriptionPlanIntentRoute = "register" | "login" | "subscription";

export const subscriptionPlanIntentHref = (
  route: SubscriptionPlanIntentRoute,
  id: string | null,
) => id !== null && validPlanId(id)
  ? `/#${route}?plan=${encodeURIComponent(id)}`
  : `/#${route}`;

export const registrationPlanHref = (id: string) =>
  subscriptionPlanIntentHref("register", id);
export const loginPlanHref = (id: string) =>
  subscriptionPlanIntentHref("login", id);
```

العقد canonical عند جذر التطبيق ويستخدم fragment ومعرّف إصدار فقط؛ لا URL خارجي،
ولا سعر أو شركة أو `activate` أو بيانات جلسة في الرابط. لا يستنتج المصنع خطة افتراضية.
بعد اعتماد الربط فقط يستبدل المنسق `href="/#login"` الخاص بخطة محددة في
`PlansDiscoveryPlanActions` بـ`href={loginPlanHref(plan.id)}`، مع بقاء النقرة صريحة.

### 2. التقاط intent في `main.tsx` بحسب route base محدد

داخل `EntryPage.route` يستبدل شرط `startsWith("#register")` بما يلي:

```ts
const routeBase = location.hash.split("?", 1)[0] ?? "";
if (["#register", "#login", "#subscription"].includes(routeBase)) {
  captureSubscriptionPlanPreference(location.hash);
}
```

لا يستخدم `startsWith` لقبول مسارات مثل `#login-extra`، ولا يلتقط intent من
`#plans` أو FAQ أو صفحة استعادة كلمة المرور. يختبر المنسق كذلك المعرف غير الصالح
ومعامل `plan` المكرر؛ لا يحولهما إلى اختيار تجاري ولا إلى بديل محفوظ مختلف بصمت.

### 3. شرط العودة في `App.tsx`

داخل `activateAuthorization`، تستمر بوابتا الشركة المختارة و`subscriptions.view`
كما هما. يستبدل فحص hash الخام في شرط التوجيه فقط:

```diff
- && preferredSubscriptionPlan() && ["", "#home", "#login", "#register"].includes(location.hash)) {
+ && preferredSubscriptionPlan()
+ && ["", "#home", "#login", "#register"].includes(location.hash.split("?", 1)[0] ?? "")) {
```

لا يوجّه موظفًا بلا الصلاحية إلى صفحة غير مسموحة، ولا يتجاوز اختيار الشركة أو بوابة
المشغل، ولا يوسّع قائمة المسارات التي يسمح التفضيل بتغيير وجهتها.

### 4. التبديل بين الدخول والتسجيل وحفظ النية

في `App.tsx` يستورد `loginPlanHref` و`registrationPlanHref` من المالك المشترك.
الربط الأدنى القابل للاختبار مع التخزين القائم هو:

```ts
// داخل LoginScreen.onRegister، بدل location.hash = "register":
location.hash = new URL(
  registrationPlanHref(preferredSubscriptionPlan() ?? ""),
  location.origin,
).hash;
setState("register");

// داخل RegistrationPage.onBackToLogin، بدل إسقاط fragment كله:
const url = new URL(location.href);
const loginHash = new URL(
  loginPlanHref(preferredSubscriptionPlan() ?? ""),
  url.origin,
).hash;
history.replaceState(null, "", `${url.pathname}${url.search}${loginHash}`);
setState("login");
```

هذه الرقعة الدنيا تحفظ النية في مسار التخزين القائم، لكنها **لا تكفي وحدها لإغلاق
حالة storage-disabled**: على المنسق حمل معرّف URL الصريح عبر التبديل والعودة وتهيئة
`CompanySubscriptionPage` قبل إزالة query من fragment، باستخدام helper مشترك
لقراءة route/plan والتحقق منه، لا باختيار plan آخر من التخزين. وجود معامل صريح
غير صالح يجب أن يظهر كاختيار غير صالح ولا يتراجع إلى اختيار قديم بصمت.

يظل matcher الحالي للكتالوج المصادق هو الحاكم: عند غياب الإصدار يظهر تنبيه ويبقى
طلب التغيير معطلًا حتى اختيار صالح صريح. لا تنفذ التهيئة أو `useEffect` أمر اشتراك.
يملك المنسق تعديل هذه المكونات واختبار الرحلة كاملة؛ لا تعد الأكواد المقترحة هنا
دليل اجتيازها ولا تغلق حد التبويبات المذكور أعلاه.

### 5. مداخل الاكتشاف المشتركة المقترحة

- مراجعة تسمية مداخل `/plans` الموجودة في `LoginScreen` وفي `RegistrationPage` لتكون واضحة مثل «الخطط والأسعار»؛ ليست إضافة مسار جديد.
- رابط عام من الموضع المناسب داخل التطبيق، دون إظهار حالة اشتراك أو استحقاق مستنتجة من القائمة العامة.
- رابط إلى `/#subscription` لصاحب الحساب بعد تطبيق صلاحياته؛ لا تغيير في مكوّنات S1.
- عند العودة من اختيار خطة، تعرض واجهة المصادقة وصفًا بأنه تفضيل للمراجعة، وليس شراءً مكتملًا.

بوابة قبول الربط: direct URL/reload، تبديل login/register، حساب قائم وشركة مختارة أو
غير مختارة، موظف بلا الصلاحية، BIGINT نصي، storage محجوب، تبويب جديد، معرف غير صالح
أو مكرر، اختيار غير موجود في الكتالوج المصادق، وعدم وجود autoPOST أو phantom option.

## إرشاد المشغل لإظهار عروض حقيقية

`publiclyListed=false` افتراضيًا **مقصود لحماية المحتوى الداخلي**، وليس نقص seed يحتاج
إلى ملء. نشر إصدار الخطة للاستخدام التشغيلي مستقل عن اعتماده للعرض على الإنترنت.

يختار مشغل المنصة إصدارًا تجاريًا معتمدًا، ويراجع الاسم والوصف والأسعار والعملة
والدورة والضريبة والحصص والوحدات واعتمادياتها وسياسة الطلب. يراجع أهليته: خطة نشطة
غير Legacy، إصدار منشور وساري وغير متقاعد، خدمة ذاتية متاحة، وبيانات تجارية مكتملة
ووحدات نشطة. بعد المراجعة فقط يستخدم أمر الإظهار الصريح المحمي بصلاحية المشغل وCSRF
و`version`، ثم يفحص العرض كزائر بعد نشر التطبيق بإذن منفصل.

لا ينسخ المشغل fixtures أو خطط Legacy أو أسماء عملاء إلى الصفحة العامة، ولا يغيّر
السعر أو الاستحقاق لحل فراغ القائمة، ولا يشغّل تعبئة جماعية أو SQL/seed تلقائيًا.
إخفاء إعلان عام لا يلغي اشتراكًا ولا فاتورة ولا استحقاقًا قائمًا. هذه الشريحة لا
تغيّر metadata الظهور بنفسها؛ تقرأ النتيجة التي يعتمدها مالك الكتالوج.
