# سياسة محتوى الواجهة والتجاوب

آخر تحديث: 22 أغسطس 2026

## الغرض

هذه السياسة عقد إلزامي لأي تغيير في واجهة النظام. هدفها أن يرى المستخدم لغة وظيفية تخص عمله، وأن تبقى جميع الشاشات قابلة للاستخدام بالعربية والإنجليزية من الهاتف إلى الشاشات الواسعة، دون تسريب تفاصيل تشغيلية أو تمدد أفقي غير مقصود.

## قواعد محتوى الواجهة

### يجب إظهاره

- اسم الحقل أو الإجراء بصياغة أعمال واضحة.
- نتيجة الإجراء والخطوة التي يستطيع المستخدم اتخاذها عند الفشل.
- أثر أمني مباشر يحتاج المستخدم إلى معرفته، مثل إلغاء الجلسات السابقة بعد تغيير كلمة المرور.
- القيود المحاسبية أو الصلاحيات التي تؤثر في قرار المستخدم.

### يمنع إظهاره

- أسماء متغيرات البيئة أو مفاتيح الإعداد، مثل `SEED_*` و`DATABASE_*` و`SMTP_*` و`VITE_*`.
- حسابات الـSeed أو عناوين البريد وكلمات المرور الخاصة بالتطوير، أو تعبئتها مسبقًا في شاشة الدخول.
- عناوين `localhost` أو المنافذ أو أسماء الجداول والمسارات الداخلية أو تفاصيل قاعدة البيانات.
- شرح آلية التنفيذ، مثل «داخل معاملة واحدة» أو تفاصيل الـAPI والـqueue والـworker.
- ادعاءات أمنية عامة لا تساعد المستخدم على اتخاذ إجراء، مثل «كل العمليات الحساسة محمية».
- تأكيدات تقنية مثل «سُجلت في سجل التدقيق» ضمن رسائل النجاح؛ يكفي تأكيد النتيجة الوظيفية. يبقى سجل التدقيق نفسه واجهة إدارية مشروعة.

عند الشك، تصاغ الرسالة وفق هذا القالب: **ما الذي حدث؟ ما أثره على العمل؟ ما الخطوة التالية؟** ولا تشرح كيف نُفذ داخليًا.

## قواعد التخطيط المتجاوب

- يجب أن تحمل عناصر `Grid` و`Flex` والنماذج و`fieldset` القابلة للانكماش `min-width: 0` عند الحاجة.
- يمنع علاج المشكلة بإخفاء التمدد على `html` أو `body`. يجب إصلاح العنصر المسبب واحتواء العرض الواسع في مكوّنه فقط.
- يسمح بالتمرير الأفقي داخل الجداول، أسطر القيود الواسعة، الرسوم، أو مجموعات التبويب فقط عندما يكون ذلك مقصودًا ومسمى دلاليًا.
- تبقى أفعال البحث والأزرار القصيرة وتسميات التبويبات في سطر واحد. عند ضيق المساحة تتمدد مجموعة البحث، أو تلتف الأزرار كوحدات كاملة، أو تتمرر مجموعة التبويب.
- عند تحول شريط أدوات مرن إلى عمود، يجب تصفير `flex-basis` العرضي لعناصر البحث؛ لا يجوز أن يتحول أساس عرض مثل `260px` إلى ارتفاع للعنصر.
- لا يجوز أن يعتمد نموذج الفاتورة على مجموع الحدود الدنيا للأعمدة. تقسّم بيانات البند إلى صفوف دلالية وتتحول إلى عمودين ثم عمود واحد عند نقاط الفصل.
- أي نافذة منبثقة يجب ألا يزيد `scrollWidth` لها أو لنموذجها أو حقولها عن `clientWidth`، باستثناء منطقة تمرير صريحة.
- يجب فحص الاتجاهين `rtl` و`ltr`؛ نجاح اتجاه واحد لا يكفي.

## عقد نموذج الفاتورة

يستخدم سطر الفاتورة الأصناف الدلالية التالية، ولا تستبدل بأعمدة مجهولة تعتمد على ترتيب العناصر فقط:

- `line-description`
- `line-quantity`
- `line-unit-price`
- `line-discount`
- `line-account`
- `line-tax`
- `line-cost-center`
- `line-delete`

على سطح المكتب يعرض السطر في صفين، وعند 780 بكسل في شبكة ضيقة، وعند 520 بكسل في عمود واحد بعد رقم السطر. ينطبق العقد نفسه على فواتير المبيعات والمشتريات.

## بوابات المنع

يشغّل `npm run ui:check` في CI ويمنع حاليًا:

- ظهور مفاتيح إعداد معروفة أو عناوين تطوير في قواميس الواجهة.
- تعبئة هوية حساب تطوير مسبقًا في بطاقة الدخول.
- فقد `white-space: nowrap` من البحث أو التبويبات.
- فقد احتواء التبويبات أو قابلية انكماش `fieldset` الفاتورة أو حد عرض محرر البند.
- فقد تسميات الحقول ودلالات الجداول والأخطاء وأنواع أزرار النماذج.

تشغّل كذلك `npm run i18n:check` وTypeScript واختبارات الواجهة وبناء Vite.

تشغّل `npm run visual-qa:test` مصفوفة Chromium الإلزامية: 19 شاشة ونافذتا الفواتير باللغتين وعروض 390/768/1440/1920. تقيس قيم `scrollWidth/clientWidth` والحدود الفعلية للعناصر، وتمنع النصوص التشغيلية ومفاتيح الترجمة، وتتحقق من بقاء البحث مضغوطًا والتبويبات والفواتير محتواة واستعادة التركيز بعد إغلاق النافذة. تعمل في CI قبل E2E والإصدار.

## مصفوفة القبول البصري

قبل دمج تغيير يمس التخطيط أو النصوص، يفحص على الأقل:

- العربية والإنجليزية.
- عروض 390 و768 و1440 و1920 بكسل.
- الشاشة المعدلة وحالة النافذة المنبثقة أو الحالة الفارغة أو الخطأ ذات الصلة.
- عدم تمدد المستند أو `main`، وعدم خروج عناصر التفاعل، وعدم ظهور نصوص تشغيلية داخلية.

التدقيق المرجعي الكامل وطريقة تشغيل بيانات الفحص موثقان في [الفحص البصري ونظام الواجهات](visual-qa.md).

## قائمة مراجعة التغيير

- [ ] النص يصف حاجة المستخدم لا تفاصيل التنفيذ.
- [ ] لا يحتوي قيمة أو اسمًا يخص بيئة التطوير أو التشغيل.
- [ ] لا توجد هوية أو بيانات اعتماد معبأة مسبقًا.
- [ ] الأزرار القصيرة والتبويبات لا تتفكك إلى أسطر أو أحرف.
- [ ] صندوق البحث لا يزيد ارتفاعه بسبب `flex-basis` بعد التحول إلى تخطيط عمودي.
- [ ] لا يوجد تمدد للمستند في المقاسات الأربعة.
- [ ] العرض الواسع محصور في منطقة تمرير مقصودة.
- [ ] فُحصت العربية والإنجليزية بصريًا.
- [ ] نجحت بوابات UI وi18n و`visual-qa:test` والاختبارات والبناء.
