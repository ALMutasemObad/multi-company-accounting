## المخرجات

- مقارنة عرضين من الصفحة المحمّلة فقط، بقوائم اختيار أصلية، وأسماء أعمدة/صفوف
  ووصف لنطاق المقارنة. تغيير العرضين لا يصدر أي طلب لجلب صفحات أخرى.
- الرسم الأساسي والعملات والدورة والضريبة والحصص وأسعار الزيادة والوحدات
  المشمولة/الاختيارية مستقلة وواضحة؛ لا تحويل سنوي إلى شهري أو جمع عملات.
  الغياب «غير معروض ضمن هذه الخطة»، والسعر الناقص «غير مهيأ»، والصفر صفر.
- استخدام منسق Decimal النصي القائم؛ إصلاح عرض ضريبة صحيحة مثل `10` دون
  حذف صفرها الأخير. اختبارات `999999999999.1234` و`0.0001` والتجميع الهندي.
- بيان عدد العروض في الصفحة من الإجمالي؛ عند اختفاء الصفحة الحالية بعد
  تغير الكتالوج تظهر عودة صريحة للصفحة الأولى، دون إعلان أن الكتالوج كله فارغ.
- المقاسات الأساسية في الصفحة العامة 24px للعناوين و16px للنصوص، مع ترتيب
  العنوان قبل التفاصيل، وإزالة تمييز العمود الثاني بلا أساس تجاري.
- RTL/LTR والهاتف واللمس (44px) والتركيز المرئي، وجدول أفقي مستقل يمكن تركيزه
  وتحريكه بالمفاتيح؛ يعود التركيز إلى قسم الكتالوج بعد الصفحات/إعادة المحاولة.
- إرشادات تشغيلية، ومعاينة المحتوى والضريبة والإضافات، وقائمة تحقق لكل إصدار
  بما فيه المسودة؛ تمييز النشر والسريان والتقاعد وسياسة طلب الاشتراك والإخفاء.
- إقرار قبل الإظهار العام، مرتبط بمفتاح `id-version`؛ يعاد ضبطه عند تحديث
  النسخة/تبديلها وإعادة تحميل الخطة، وعند تعارض أمر الكتابة. الإخفاء لا يحتاج
  الإقرار ويظل متاحًا لإصدار معلّم للإظهار فقد أهليته.
- القائمة مراجعة استرشادية للّقطة المحمّلة، لا ضمان قبول ولا بديلًا عن الخادم.
  الأمر القائم يحتفظ بـ`version` وCSRF وصلاحية المشغل، دون Retry تلقائي للكتابة.
- إخفاء الإعلان لا يلغي اشتراكًا قائمًا ولا يسحب بمفرده أهلية طلب الإصدار داخل الحساب.

## فجوة الاختيار والتكامل المركزي

أثبت فحص النسخة الأساسية أن `CompanySubscriptionPage.load()` يستبدل التفضيل
المفقود بصمت بأول خطة في الصفحة المصادق عليها (`page=1&pageSize=100`). غياب
المعرف من الصفحة لا يثبت تقاعده أو إخفاءه، فقد يكون في صفحة تالية. لا يحتفظ
التفضيل بسعر أو استحقاق ولا يضمن السعر القديم؛ الخادم يعيد التحقق من الأمر.

أُرسلت الفجوة للمنسق ووجّه C إلى رسالة غير جازمة واختيار فارغ وتعطيل الإرسال
حتى اختيار صريح وصفحات خادمية عند الحاجة، دون تغيير دلالة `publiclyListed`.

**إجراء المنسق بعد جمع C:** اختبار الرحلة القديم في `public-plans.spec.ts`
ما زال يتوقع fallback إلى `2101` بعد اختيار `102` المفقود. بقي هذا التوقع
لتشغيل الفرع المستقل الحالي فقط؛ يجب استبداله بتوقع C الجديد عند التكامل.
لا يعد ذلك قبولًا دائمًا للسلوك المعيب. اختبارات A الجديدة لا تفرض السلوك القديم.

## عزل الاختبارات وأدلة التنفيذ

الإعداد المحلي يستخدم API `3130` وWeb `4180`، وproxy صحيح و`strictPort` و
`reuseExistingServer:false` وworker واحد. لم تُستخدم منافذ الآخرين أو تُوقف عملياتهم.
الاعتماديات المشتركة للقراءة فقط: لا install/ci/prune/update ولا prisma generate.
Cache تطبيق Vite في `tmp/track-a/vite-cache`؛ يستخدم `--configLoader runner`
لتجنب إخراج config مؤقت داخل junction. السماح بملفات الخطوط يقتصر على
`realpath(node_modules/@fontsource)` بجانب جذر النسخة، لا كود نسخة أخرى.

أثناء تطوير اختبارات الواجهة صُححت توقعات اختبار لا أخطاء أعمال: فحص خاصية
`disabled` على `option` مباشرة، وعدم الخلط بين النص التوضيحي «ليس غير محدود»
وقيمة الحصة، وعدم فرض التجميع الغربي على الأرقام الهندية. لا تُحسب الجولة
الفاشلة نجاحًا؛ النتيجة النهائية أعلاه تخص إعادة التشغيل بعد التصحيح.

سباق اختبار المهلة القديم: `getByRole('status')` يمكن أن يطابق مؤشر تحميل
`EntryPage` قبل تركيب طلب الكتالوج. أضيف انتظار إشارة من route المعلق، ثم
مؤشر التحميل داخل `.plans-catalog`، قبل `fastForward(12_100)`. لا انتظار عشوائي
ولا زيادة لمهلة 12 ثانية ولا تعديل fetch لهذا السبب.
اجتاز الاختبار المصحح الأحجام الأربعة؛ مدة الحالة الكاملة نحو 4.6–5.4 ثوانٍ
باستخدام الساعة الوهمية، ولا تمثل هذه المدة قياسًا لأداء الاستضافة.

## أوامر إعادة التحقق

من جذر نسخة المسار، بعد ضبط PATH إلى Node/npm المذكورين في وثيقة التنسيق:

```powershell
node node_modules/typescript/bin/tsc -p apps/web/tsconfig.json --pretty false
node node_modules/typescript/bin/tsc -p tsconfig.e2e.json --pretty false
node node_modules/typescript/bin/tsc -p tsconfig.track-a.json --pretty false
node node_modules/vitest/vitest.mjs run --root apps/web --maxWorkers=1
node node_modules/vitest/vitest.mjs run --root apps/api --maxWorkers=1 public-plan-catalog platform-subscription-router architecture-guardrails
node scripts/generate-openapi-guards.mjs --check
node scripts/check-web-i18n.mjs
node scripts/check-web-ui.mjs
node node_modules/vite/bin/vite.js build --config vite.track-a.config.ts --configLoader runner
node --test scripts/tests/*.test.mjs
node node_modules/@playwright/test/cli.js test --config playwright.track-a.config.ts
```
