# دليل تعدد اللغات والقواميس

آخر تحديث: 8 سبتمبر 2026

## النطاق

جميع النصوص التي تعرضها واجهة React تأتي من ملفات لغة مستقلة ذاتية الاكتشاف. اللغة العربية هي مصدر مفاتيح الترجمة واللغة الافتراضية الآمنة، وتتوفر ملفات مكتملة للإنجليزية والأوردية والهندية يراجعها TypeScript والاختبارات. تحمّل مرحلة bootstrap العربية أولًا ثم اللغة المختارة فقط عبر dynamic import؛ وعند التبديل لا تعتمد اللغة الجديدة قبل اكتمال chunk الخاص بها. يحفظ المزود اختيار المستخدم محليًا ويضبط `lang` و`dir` وتنسيقات `Intl` للأرقام والتواريخ والشهور وملفات CSV. الأوردية RTL بمعرّف `ur-PK`، والهندية LTR بمعرّف `hi-IN`.

تغطي بوابة الواجهة الحالية 27 شاشة أساسية باللغات الأربع عند عروض
390/768/1440/1920، إضافة إلى حالات الفواتير والمخزون والتقارير المركزة.

أسماء البيانات التي ينشئها المستخدم، مثل اسم الشركة ووصف القيد، ليست نصوص واجهة ولا تترجم تلقائيًا. أما أسماء المرجعيات، مثل العملة والحساب ومركز التكلفة، فتعالج منفصلة كما هو موضح أدناه.

## بنية الملفات واتفاقية الاكتشاف

- كل لغة قابلة للاختيار ملف واحد باسم `<code>.locale.ts` داخل `apps/web/src/i18n/locales`، حيث `code` واسم الملف وmetadata تستخدم صيغة BCP47 المعيارية نفسها مثل `ar` أو `pt-BR`.
- يصدّر الملف `localeMetadata` ككائن literal يحوي فقط `code` و`nativeName` و`dir` و`intl`، ويصدّر `localeDictionary` ككائن literal كاملًا، ثم يصدّر تعريف اللغة افتراضيًا. لا يسمح الملف باستيرادات runtime كي يبقى قاموسه chunk مستقلًا؛ يسمح باستيراد الأنواع فقط.
- يولّد plugin داخل `apps/web/vite.config.ts` manifest افتراضيًا صغيرًا من metadata، دون استيراد القواميس أو تنزيلها. يستهلك `registry.ts` هذا manifest فقط.
- يربط `apps/web/src/i18n/core.ts` الـmanifest مع `import.meta.glob("./locales/*.locale.ts")`. لذلك تظهر اللغة تلقائيًا في `LanguageSwitcher` ومحددي لغة التسجيل، ولا ينزّل قاموسها حتى bootstrap للعربية أو اختيارها.
- `apps/web/src/i18n/locale-definition.ts` يحتوي عقد الملف ومساعد fallback للنسخ المحلية القديمة.
- `apps/web/src/i18n/react.tsx` يحتوي المزود ومبدّل اللغة ودوال التنسيق داخل React.

## إضافة لغة واجهة جديدة

1. انسخ بنية `ar.locale.ts` إلى ملف واحد باسم BCP47 معياري، مثل `de.locale.ts`، وغيّر metadata وترجم كل قيم `localeDictionary` دون تغيير المفاتيح.
2. شغّل `npm run i18n:check` ثم اختبارات الواجهة والبناء. لا تعدّل `registry.ts` أو `core.ts` أو `vite.config.ts` أو OpenAPI أو خدمة التسجيل لإضافة اللغة.

هذه هي خطوة التأليف الوحيدة. يرفض الفحص metadata ناقصة، code أو intl غير صالح/غير معياري، عدم تطابق اسم الملف، استيراد runtime، مفتاحًا ناقصًا أو زائدًا، نصًا فارغًا، علامة ترحيل، أو اختلاف عناصر الاستيفاء مثل `{page}` و`{totalPages}` عن العربية. لا تضف قيمة احتياطية صامتة داخل القاموس الجديد.

## التسجيل والبريد

تقبل عقود التسجيل الذاتي واستعادة كلمة المرور والاستكمال الاجتماعي قيمة BCP47 آمنة بطول أقصى 35 حرفًا، وتحوّلها الخدمة إلى الصيغة المعيارية قبل التخزين. لم تعد هذه العقود تحتوي enum للغات الأربع.

قوالب البريد الأصلية متوفرة للعربية والإنجليزية والأوردية والهندية. اختيار القالب مستقل عن إتاحة لغة الواجهة ويطبق ترتيبًا صريحًا: تطابق كامل، ثم لغة الأساس (`en-GB` إلى `en`)، ثم العربية. تعيد حقول `locales` في خيارات التسجيل قائمة قوالب البريد الأصلية للتوافق والإفصاح فقط؛ لا تستخدمها الواجهة لتصفية ملفات اللغات المكتشفة.

## استخدام الترجمة في المكونات

داخل React استخدم `useI18n()` ثم `t("namespace.key")`. خارج React استخدم `translate()` للنص الذي يحسب وقت الاستدعاء، و`activeIntlLocale()` عند بناء `Intl.NumberFormat` أو `Intl.DateTimeFormat`. لا تحسب نصًا مترجمًا في ثابت أعلى الوحدة لأن الثابت لن يتغير عند تبديل اللغة.

رسائل أخطاء API لا تعرض نص الخادم. تستقبل الواجهة `code` و`reason`، وتجرب بالترتيب `errors.<reason>` ثم `errors.<code>`، ثم تستخدم `errors.DEFAULT`. الحالات تستخدم `status.<CODE>`، وإجراءات التدقيق والكيانات وأحداث الأمان تستخدم مفاتيح مشتقة من أكوادها. عند إضافة كود أعمال جديد يجب إضافة مفتاحه إلى القاموس العربي ثم جميع القواميس.

## أسماء البيانات المرجعية

تستخدم المكونات `localizedReferenceName()` بدل الوصول المباشر إلى `nameAr`. تقبل الدالة العقد المستقبلي العام:

```ts
{
  nameAr: string;
  nameEn?: string | null;
  names?: Record<string, string | null>;
}
```

تفضل الدالة `names[locale]`، ثم تدعم `nameEn` للتوافق الحالي في الإنجليزية، ثم تعود إلى `nameAr`. بذلك لا تحتاج المكونات إلى تغيير عندما يضيف الخادم خريطة `names` للغات جديدة.

العقد الحالي مكتمل ثنائي اللغة للحسابات ومراكز التكلفة والعملاء والموردين وحسابات الخزينة والأدوار. ما زالت الاستجابات التالية ترسل اسمًا عربيًا فقط وتظهر بالعربية كقيمة احتياطية عند اختيار الإنجليزية:

- العملات في إعدادات الشركة وأسعار الصرف والمستندات والتقارير، بما فيها العملة الأساسية.
- أنواع الحسابات وطرق الدفع والضرائب وحالة قالب دليل الحسابات.
- مراجع الحساب والعميل والمورد ومركز التكلفة المختصرة داخل فواتير المبيعات والمشتريات.
- صفوف ميزان المراجعة والقوائم المالية وكشف الأستاذ ولقطات بعض المستندات التاريخية.
- وصف الصلاحية الإدارية `descriptionAr`.

إكمال ترجمة هذه البيانات يتطلب توسيع نماذج قاعدة البيانات أو مسلسلات API وعقد OpenAPI إلى `names` أو حقول اللغة المناسبة، مع الحفاظ على اللقطات التاريخية غير القابلة للتغيير. هذه ليست نصوصًا صلبة في JSX، وقد وُثقت صراحةً حتى لا تختلط ترجمة الواجهة بترجمة بيانات الأعمال.

## بوابات الجودة

يشغّل `npm run i18n:check` محلل TypeScript/JSX، ويرفض:

- أي نص عربي خارج مجلد القواميس في مصدر الواجهة غير الاختباري.
- النصوص المرئية الصلبة داخل JSX وخصائص `label` و`title` و`placeholder` و`aria-label` و`alt` و`description`.
- تثبيت `ar-SA` أو `en-US` داخل الصفحات بدل سجل اللغة.
- حساب ترجمة في مستوى الوحدة بدل وقت الاستدعاء أو العرض، لأن القيمة المتجمدة لن تتبدل مع اللغة.
- استيراد القواميس من `registry.ts` أو تحميل اللغات الأربع ساكنًا في حزمة البداية.

وتتحقق اختبارات `i18n.test.ts` من تكافؤ المفاتيح، وتطابق عناصر الاستيفاء، وعدم وجود قيم فارغة أو علامات ترحيل، واللغة الافتراضية، واختيار أسماء المرجعيات. تختبر `domain.test.ts` ربط أكواد الحالات وأخطاء الأعمال بالقاموسين.

كما يرفض plugin البناء إذا اندمج أكثر من ملف لغة في chunk واحد، أو تجاوز chunk لغة 500KiB غير مضغوط، أو عاد chunk مشترك كبير من fragments. في قياس 8 سبتمبر 2026 اختفى chunk القواميس المشترك `employee-expenses` البالغ 591.43kB (الاسم كان ناتج hoisting للترجمات، وليس حجم واجهة مصروفات الموظفين). أصبحت chunks المستقلة: العربية 267.71kB، الإنجليزية 214.89kB، الأوردية 275.65kB، والهندية 352.98kB، بينما بقي chunk واجهة مصروفات الموظفين نفسه 11.33kB.

## قائمة مراجعة المترجم

- حافظ على معنى المصطلح المحاسبي لا ترجمته الحرفية فقط.
- لا تترجم الأكواد مثل `YER` و`IBAN` وأرقام المستندات.
- اختبر اللغة في RTL وLTR، وتحقق من عدم ظهور اسم مفتاح أو `{placeholder}` للمستخدم.
- افحص شاشة الدخول والتسجيل وصفحة تشغيلية واحدة على الأقل عند 390 و1280 بكسل قبل التسليم.
