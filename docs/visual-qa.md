# الفحص البصري ونظام الواجهات

آخر تحديث: 21 أغسطس 2026

## النطاق المعتمد

تغطي المصفوفة 18 شاشة: الدخول، التسجيل، و16 مساحة عمل مصادق عليها (`dashboard`, `customers`, `sales`, `receipts`, `suppliers`, `purchases`, `payments`, `journals`, `fiscal`, `accounts`, `treasury`, `reports`, `admin`, `audit`, `security`, `settings`). فُحصت كل شاشة بالعربية والإنجليزية عند عروض 390 و768 و1440 و1920 بكسل؛ أي **144 حالة واجهة**.

لكل حالة جرى التحقق من:

- تطابق `dir` مع اللغة وعدم ظهور مفاتيح ترجمة أو شاشة خطأ.
- عدم تجاوز عرض المستند أو `main` للمنفذ، وعدم خروج عنصر مرئي خارج الشاشة؛ يسمح بالعرض الأوسع داخل منطقة جدول قابلة للتمرير فقط.
- عدم تداخل عنوان الصفحة مع إجراءاته، وعدم وجود عنصر تفاعل مرئي أصغر من 32×32 بكسل.
- اكتمال حقول الدخول (حقلان) والتسجيل (10 حقول) وغياب رسائل الخطأ غير المتوقعة.
- عمل النافذة المنبثقة دلاليًا: `role=dialog` ومعرّف عنوان فريد، قفل تمرير الخلفية، الإغلاق بـ`Escape`، ثم استعادة التركيز إلى زر الفتح.

اكتشف الفحص تمدد بطاقة لوحة التحكم على 390 بكسل بسبب الحد الأدنى الضمني لعنصر Grid، وانكماش زر القائمة الإنجليزية مع العناوين الطويلة. أضيف `min-width: 0` لعناصر شبكة اللوحة ومنع انكماش زر القائمة؛ أُعيدت الحالات المتأثرة ونجحت.

## تشغيل بيئة الفحص

يوفر خادم القراءة الثابت بيانات واجهة حتمية، ولا يكتب في قاعدة بيانات أو يرسل بريدًا:

```bash
npm run visual-qa:api
npm run dev -w @mcap/web
```

يستمع خادم البيانات إلى `127.0.0.1:3000` افتراضيًا، ويمكن تغيير المنفذ عبر `VISUAL_QA_PORT`. يجب عدم استخدامه كخادم إنتاج.

تمنع بوابة `npm run ui:check` عودة العقود الأساسية: عناوين الصفحات المشتركة، مناطق الجداول القابلة للتمرير، تسميات الحقول، أنواع أزرار النماذج، أدوار رسائل الخطأ، حلقة التركيز، وحدود CSS المتجاوبة. تعمل البوابة في مهمتي CI.
