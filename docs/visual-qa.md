# الفحص البصري ونظام الواجهات

آخر تحديث: 25 أغسطس 2026

## النطاق المعتمد

تغطي المصفوفة 24 شاشة: الدخول، التسجيل، استعادة كلمة المرور، و21 مساحة عمل مصادق عليها (`dashboard`, `pos`, `customers`, `professionalProjects`, `sales`, `receipts`, `suppliers`, `purchases`, `payments`, `journals`, `fiscal`, `approvals`, `accounts`, `treasury`, `inventory`, `reports`, `imports`, `admin`, `audit`, `security`, `settings`). تُفحص كل شاشة بالعربية والإنجليزية والأوردية والهندية عند عروض 390 و768 و1440 و1920 بكسل؛ أي **384 حالة واجهة** قبل الحالات المركزة الإضافية.

يوجد فحص مركّز لنافذتي إنشاء فاتورة المبيعات والمشتريات باللغات الأربع والمقاسات الأربعة، أي **32 حالة نافذة** إضافية. وتضيف بوابة Inventory الأرصدة، والحركات ومحررها، ووحدات القياس ومحررها، والأصناف ومحررها باللغات الأربع والمقاسات الأربعة، أي **112 حالة** أخرى. كما تغطي التقارير ملخص الضريبة وحركة مراكز التكلفة ثم كشف الأستاذ المقيد بالمركز، أي **48 حالة سطح**. المجموع الحالي **560 حالة سطح بصرية متجاوبة**.

أصبحت قياسات منع الارتداد القابلة للحسم آليًا بوابة Chromium عبر `tests/visual/responsive-ui.spec.ts` و`playwright.visual.config.ts`، وتعمل في CI قبل رحلة E2E والإصدار. تمثلها 112 حالة Playwright موزعة على أربعة مشاريع عرض، وتفحص داخلها الحالات البصرية الـ560 دون الاعتماد على قاعدة بيانات؛ تبقى مراجعة الجودة الجمالية واللقطات المرجعية مسؤولية بشرية عند تغيير التصميم عمدًا.

لكل حالة جرى التحقق من:

- تطابق `dir` مع اللغة وعدم ظهور مفاتيح ترجمة أو شاشة خطأ.
- عدم تجاوز عرض المستند أو `main` للمنفذ، وعدم خروج عنصر مرئي خارج الشاشة؛ يسمح بالعرض الأوسع داخل منطقة جدول قابلة للتمرير فقط.
- عدم تداخل عنوان الصفحة مع إجراءاته، وعدم وجود عنصر تفاعل مرئي أصغر من 32×32 بكسل.
- بقاء زر البحث وعناوين التبويبات كوحدات غير مفككة، مع احتواء التبويبات عند ضيق الشاشة.
- بقاء صندوق البحث عنصرًا مضغوطًا لا يتحول `flex-basis` الأفقي فيه إلى ارتفاع عند تحول شريط الأدوات إلى عمود.
- غياب مفاتيح الإعداد وحسابات التطوير وتفاصيل التنفيذ من النص المرئي، وعدم تعبئة بريد تطوير في الدخول.
- اكتمال حقول الدخول (حقلان) والتسجيل (10 حقول) وغياب رسائل الخطأ غير المتوقعة.
- عمل النافذة المنبثقة دلاليًا: `role=dialog` ومعرّف عنوان فريد، قفل تمرير الخلفية، الإغلاق بـ`Escape`، ثم استعادة التركيز إلى زر الفتح.
- عدم تجاوز عرض نافذة الفاتورة ونموذجها و`fieldset` ومحرر البند للعرض المتاح، دون قص حقول أو تمدد أفقي.

في التدقيق الأخير اكتُشفت أربعة أسباب متكررة: قابلية زر البحث للانكماش مع `overflow-wrap: anywhere`، تحول أساسه المرن إلى ارتفاع كبير في شريط الأدوات العمودي، التفاف تسميات التبويبات حرفيًا على الهاتف، والحد الأدنى الضمني لـ`fieldset` مع شبكة بنود أعرض من نافذة الفاتورة. ثُبّت زر البحث والتبويبات كسطر واحد، وصُفّر أساس صندوق البحث في التخطيط العمودي، وحُوّلت التبويبات إلى احتواء/تمرير آمن، وأعيد توزيع بند الفاتورة في صفين دلاليين يتحولان إلى عمودين ثم عمود واحد. أزيلت كذلك نصوص التشغيل وحساب التطوير من الدخول وأعيدت صياغة رسائل التسجيل والإعدادات وفق [سياسة محتوى الواجهة والتجاوب](UI_CONTENT_RESPONSIVE_POLICY_AR.md).

## تشغيل بيئة الفحص

لتشغيل البوابة الكاملة؛ يبدأ Playwright خادم البيانات وVite ويوقفهما تلقائيًا:

```bash
npm run visual-qa:test
```

للاستكشاف البصري اليدوي، يوفر خادم القراءة الثابت بيانات واجهة حتمية، ولا يكتب في قاعدة بيانات أو يرسل بريدًا:

```bash
npm run visual-qa:api
npm run dev -w @mcap/web
```

يستمع خادم البيانات إلى `127.0.0.1:3000` افتراضيًا، ويمكن تغيير المنفذ عبر `VISUAL_QA_PORT`. يجب عدم استخدامه كخادم إنتاج.

تمنع بوابة `npm run ui:check` عودة العقود الساكنة الأساسية بسرعة، بينما تثبت `npm run visual-qa:test` السلوك المحسوب في Chromium: عرض المستند والعناصر، الاتجاه، النص المرئي، ارتفاع البحث، احتواء التبويبات والفواتير، ودلالات النافذة واستعادة التركيز. تعمل البوابة الديناميكية في مهمة MySQL الحاجبة للإصدار والنشر، وتحفظ CI لقطة وفيديو وTrace عند الفشل.
