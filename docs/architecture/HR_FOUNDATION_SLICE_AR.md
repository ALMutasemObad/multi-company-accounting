# شريحة أساس الموارد البشرية

## الملكية والحدود

يملك HR الجداول `hr_departments`, `hr_positions`, `employees`, و`employment_contracts`. يقرأ حسابات الدخول النشطة عبر `HrIdentityPort` يملكه Identity؛ العلاقة المركبة تمنع ربط حساب من شركة أخرى، ولا يحدّث HR حساب الدخول أو أدواره.

لا توجد مبالغ مالية في النموذج، ولا أثر على Ledger أو Treasury أو Sales أو Inventory. العقد هنا حقيقة وظيفية مؤرخة فقط، وليس عقد تسعير مشروع أو مستند دفع.

## نموذج البيانات

| الكيان | أهم الحقول والقواعد |
|---|---|
| `HrDepartment` | رمز `DEP-`، اسمان، وصف، نشاط، `version` |
| `HrPosition` | رمز `JOB-`، اسمان، وصف، نشاط، `version` |
| `Employee` | رمز `EMP-`، اسم، ربط User اختياري وفريد داخل الشركة، قسم/منصب/مدير اختياريون، نوع وحالة عمل، تاريخ التحاق/إنهاء، موقع عمل، `version` |
| `EmploymentContract` | موظف، نوع، مسمى عربي/إنجليزي، بداية/نهاية، حالة، سبب وتوقيت الإنهاء، `version` |

الرموز للعرض ولا تستخدم مفاتيح تكامل. كل العلاقات التشغيلية تحمل `companyId`، ولا يسمح للموظف أن يدير نفسه أو أن تنشأ دورة مديرين. الموظف المنتهي لا يعدل ولا يسند مديرًا، ولا يملك أكثر من عقد `ACTIVE`.

## حالات الاستخدام

1. إنشاء وتعديل وتعطيل قسم أو منصب، مع الاحتفاظ بالتاريخ.
2. إنشاء موظف مستقل أو ربطه بعضوية دخول نشطة اختيارية.
3. عرض سجل الموظفين وتفاصيل الموظف بهيكله ومديره.
4. تعديل الإسناد التنظيمي مع منع المراجع المعطلة والدورات والتعارض المتفائل.
5. وضع الموظف في إجازة أو إعادته للعمل أو إنهاء خدمته بسبب وتاريخ.
6. إنشاء عقد غير مالي وإنهاؤه مع إبقاء سجل immutable دلاليًا بعد النهاية.

## الصلاحيات

| الصلاحية | الغرض |
|---|---|
| `hr.employees.view` | عرض سجل الموظفين وتفاصيله غير الحساسة |
| `hr.employees.manage` | إنشاء الموظف وتعديل حالته وهيكله |
| `hr.structure.view` | عرض الأقسام والمناصب |
| `hr.structure.manage` | إنشاء وتعديل وتعطيل الهيكل |
| `hr.contracts.view` | عرض العقود المؤرخة |
| `hr.contracts.manage` | إنشاء العقود وإنهاؤها |

## عقد HTTP

- `GET/POST /hr/departments` و`PATCH /hr/departments/{departmentId}`.
- `GET/POST /hr/positions` و`PATCH /hr/positions/{positionId}`.
- `GET/POST /hr/employees`.
- `GET/PATCH /hr/employees/{employeeId}`.
- `POST /hr/employees/{employeeId}/transition`.
- `GET/POST /hr/employees/{employeeId}/contracts`.
- `POST /hr/employees/{employeeId}/contracts/{contractId}/end`.
- `GET /hr/user-options` للربط الاختياري بهوية نشطة.

تستخدم أجسام JSON حراس OpenAPI المولدة، وتُنقل معرفات BIGINT كنصوص. أوامر POST المغيرة للحالة تحمل `Idempotency-Key`، وتعديلات PATCH تحمل `version`.

## الواجهة

مسار `#humanResources` بواجهة متجاوبة ذات تبويبين: سجل الموظفين وتفاصيله وعقوده، والهيكل التنظيمي للأقسام والمناصب. جميع النصوص في قاموس مستقل يدمج في العربية والإنجليزية والهندية والأردية، مع RTL/LTR ومنع overflow على عروض 390 و768 و1440 و1920 بكسل.

## الاختبارات

- ترحيل من قاعدة فارغة وترقية من السابق، ثم Seed وعكس تشغيلي read-only.
- Idempotency متزامن للإنشاء، ورمز واحد وعدم تكرار الأثر.
- تعارض `version`، عقد نشط واحد، إنهاء الموظف والعقد ذريًا، ومنع دورة المدير.
- مراجع معطلة، ربط مستخدم من شركة أخرى، وعزل القراءة والكتابة بين شركتين.
- parity وحراس واستجابات OpenAPI، TypeScript، Web، E2E، وفحص الاستجابة عبر اللغات والمقاسات.

## الترحيل والعكس

الترحيل `20260827210000_hr_foundation` توسعي ويضيف الجداول والتسلسلات والصلاحيات فقط. العكس التشغيلي يعيد نسخة التطبيق السابقة ويحتفظ بالبيانات؛ ملف `rollback.sql` لا ينفذ DDL أو حذفًا، ويعرض أعداد الصفوف المحتفظ بها لتأكيد سلامة المسار. اختُبر الملف على صف فعلي في كل جدول وأعاد `1/1/1/1` مع بقاء السجلات.

## نتيجة التنفيذ المحلي

- OpenAPI `1.33.0`: خمس عشرة عملية جديدة وتسعة أجسام طلب؛ أصبح الإجمالي 241 عملية و125 جسم طلب و1590 جسم استجابة مولدًا.
- نجحت سلسلة 52 Migration من قاعدة MariaDB فارغة والـSeed و`migrate status`.
- نجحت حزمة API `315/315`، والواجهة `30/30`، والبنية `34/34`، واختبار E2E لإنشاء موظف وعقد غير مالي، ومصفوفة العرض `112/112` التي تغطي 25 شاشة بأربع لغات وأربعة عروض.
- لا Dependency جديدة، ولا نشر، ولا Push.
