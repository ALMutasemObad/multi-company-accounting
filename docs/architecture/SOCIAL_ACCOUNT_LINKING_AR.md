# ربط وفك وسائل الدخول الاجتماعية

## القرار والملكية

يملك سياق **Identity & Access** جداول `User` و`Session` و`ExternalIdentity` ومعاملات
OIDC. تعرض شاشة أمان الحساب Google وApple المهيأين فقط، وتعيد حالة الربط وتاريخه
دون `issuer` أو `subject` أو لقطة البريد أو أي token. لا تستخدم هوية البريد للربط أو
المطابقة؛ دليل الربط الوحيد هو `issuer + subject` الذي تحققه محولات OIDC الخادمة.

اعتمدت قاعدة هوية اجتماعية واحدة لكل `(user_id, provider)`. يضيف الترحيل 74 قيد
`ext_identity_user_provider_key` دون backfill أو حذف أو تعديل بيانات. إذا كانت قاعدة
الإصدار السابق تحتوي ازدواجية، يفشل `ALTER TABLE` ويترك الصفوف كما هي لتراجع يدوي؛
لا يختار الترحيل صفًا ولا يتلف بيانات. يعيد rollback الفهرس غير الفريد السابق فقط.

## الربط

يعيد الربط استخدام معاملة `LINK` الحالية ولا ينشئ بروتوكولًا موازيًا. الشروط:

- جلسة `AUTHENTICATED` لم يمض على `authenticatedAt` فيها أكثر من عشر دقائق.
- CSRF صحيح وموافقة صريحة قبل بدء التفويض.
- `state` و`nonce` وPKCE قصيرو العمر وأحاديو الاستخدام، مع Cookie ارتباط متصفح
  `HttpOnly` ضيقة لمسار callback.
- لا يرسل JavaScript `issuer` أو `subject` أو claims، ولا يربط الحساب بالبريد.
- callback يعود إلى شاشة أمان الحساب، ويدور SID مع إبقاء إثبات CSRF الموجود في
  المتصفح بدل وضع سر جديد في URL. يحافظ الربط على `selectedCompanyId` ولا يوسع
  شركة أو صلاحية.
- إلغاء المستخدم أو callback ناقص يستهلك معاملة التفويض ذريًا بعد التحقق من
  `state` وارتباط المتصفح؛ لذلك لا يمكن إعادة استخدام المعاملة الملغاة حتى قبل
  انتهاء مهلة صلاحيتها.
- يضمن قيدا `(issuer, subject)` و`(user_id, provider)` أن سباقين لا يربطان هوية
  مستخدم آخر أو أكثر من هوية للمزود نفسه.

## فك الربط والتزامن

يتطلب فك الربط جلسة حديثة وCSRF وتأكيدًا صريحًا. داخل معاملة `Serializable` محدودة
المهلة يقفل المسار صف المستخدم أولًا بـ`SELECT ... FOR UPDATE`، ثم يعيد فحص الجلسة
ووسائل الدخول. يسمح بالحذف فقط إذا بقيت كلمة مرور محلية أو هوية اجتماعية أخرى.
لذلك إذا حاول فكان متزامنان لحساب اجتماعي ذي مزودين، ينتظر الثاني قفل المستخدم ثم
يرى عاملًا واحدًا ويرفض بـ`LAST_SIGN_IN_METHOD`.

يحذف المسار هوية المستخدم الحالي فقط، ثم يكتب `SOCIAL_IDENTITY_UNLINKED` عبر
`SecurityEventAppendPort` لكل شركة نشطة في المعاملة نفسها. إذا تعذر التدقيق تتراجع
عملية الحذف. ولأن `SecurityEvent` الحالي شركة النطاق، يرفض المسار الحساب الذي لا
يملك أي إسناد شركة نشط بدل تنفيذ فك غير مدقق؛ توسيع سجل الأمان إلى نطاق عالمي قرار
منفصل مستقبلًا.

تنطبق قاعدة الفشل المغلق نفسها على الربط: يعاد فحص وجود إسناد شركة نشط داخل
معاملة callback قبل إنشاء `ExternalIdentity` أو تدوير الجلسة، فلا ينجح ربط غير
مدقق لحساب منصة فقط أو حساب منفصل عن الشركات.

## الخصوصية والفشل

- المزود غير المهيأ مخفي ويرفض خادميًا.
- لا تقبل العمليات user id من العميل ولا تسمح باستهداف حساب آخر.
- الأخطاء لا تعرض subject أو البريد أو سبب تعارض فريد خامًا.
- أي callback وصل مع `state` وربط متصفح صالحين يعد محاولة نهائية؛ إذا فشل تبادل
  المزود أو تحقق جسم الرد تستهلك المعاملة قبل إعادة المستخدم بخطأ عام، كي لا يبقى
  `state` صالحًا لإعادة التشغيل.
- لا Network I/O داخل معاملات قاعدة البيانات؛ تبادل OIDC يسبق معاملة الربط.
- لا Outbox جديد: التغيير والتدقيق متزامنان ولا يوجد مستهلك لاحق معروف.

## أثر الباركود

لا أثر. التغيير محصور في Identity & Access ولا يمس Inventory أو إدخال الأصناف أو
المستندات أو الطباعة.
