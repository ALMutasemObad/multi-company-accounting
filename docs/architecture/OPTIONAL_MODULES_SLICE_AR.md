# كتالوج الوحدات الاختيارية داخل النظام

## القرار وحدود الشريحة

مكون عرض عربي/RTL يستهلك `SubscriptionSnapshot` و`CurrentAuthorization` القائمين، ويعرض وحدات **نسخة الخطة الحالية** مع الاستحقاقات التي قد تكون خارجها. ليس سوق إضافات متصفح أو نظام اشتراك جديدًا. لا تحميل لكود طرف ثالث، ولا API جديد، ولا تغيير Domain أو قاعدة بيانات أو صلاحيات. مرجع الجرد هو `main` عند `9be397c7a435720c921425b6cb7b64e5dbab7ebc`؛ الوثائق التاريخية ليست دليل تنفيذ.

المالك القائم هو Platform Subscriptions & Entitlements. أعيد استخدام `permissionModule` من الواجهة بدل نسخ جدول الربط. العرض الجديد يحل نقص شرح الحالات والمتطلبات في قائمة الاستحقاقات المختصرة؛ يبقى نموذج اختيار الوحدات ومراجعة تغيير الاشتراك الحالي المالك الوحيد للتفاعل. لا يستبدل هذا المكون رحلة الخطط العامة أو كتالوج المشغل.

الوحدات المشمولة تظهر لتوضيح اعتماد الوحدات الاختيارية عليها. التفاصيل المفقودة لاستحقاق محفوظ سابقًا تبقى «غير متاحة». أسماء الاعتماديات وحالتها المباشرة للشرح فقط، ولا تشكل محرك صلاحيات أو تفسيرًا نهائيًا لكل أسباب غياب القدرة. طلب معلق أو تغيير مجدول لا يغير الحالة المعروضة.

## الربط المطلوب بعد انتهاء مهمة التكامل

هذه قائمة عمل للمسؤول عن التكامل؛ لم تعدل الملفات أدناه في هذه الشريحة:

1. **`apps/web/src/CompanySubscriptionPage.tsx`**: استبدال قسم قائمة الاستحقاقات المختصرة بالمكون، داخل السياق المحمي الحالي. الحصول على `CurrentAuthorization` من `useAuthorization()`؛ تمرير user/company النشطين ولقطة القراءة المقبولة نفسها. لا تغير نموذج OPTIONAL أو `toggleOptional` أو المراجعة/الإرسال. لا تستورد أي fixture.
2. **الملف نفسه، `load` و`blockContext`**: حفظ غلاف القراءة المقبولة مع هوية user/company وقت بدء الطلب. الانتقال إلى loading عند بدء التحديث، وerror عند فشله، وunavailable عند حجب السياق؛ لا تمرر snapshot سابقًا كـready بسبب بقائه في React state. لا تصنع الهوية بأثر رجعي من الشركة الجديدة. غلاف المكون يحجب اختلاف الهويات لكنه لا يثبت حداثة قراءتين للشركة نفسها؛ invalidation وتجاهل الاستجابات القديمة مسؤولية loader.
3. **`apps/web/src/App.tsx`، شرط الحاجة فقط بعد مراجعة التكامل**: التحقق من تحديث `/auth/me` بعد نجاح تغيير الاشتراك وعودة المستخدم للصفحة، ومن إبطال الحالة عند انتهاء الجلسة أو تبديل الشركة. لا route جديد ولا تعديل تنقل مطلوب لهذا العرض. إذا كان التحديث الحالي كافيًا فلا تعديل للملف.
4. **`apps/web/src/i18n/locales/optional-modules.ts` و`apps/web/src/i18n/locales/ar.ts` و`en.ts` و`ur.ts` و`hi.ts`**: نقل النصوص عند اعتماد الربط إلى آلية اللغات القائمة وإكمال الاتجاه LTR. النسخة الحالية عربية معزولة عمدًا؛ لا تعتمد للغات الأخرى قبل ذلك. يراجع المدير طريقة دمج ملف النصوص حسب نمط التسجيل الموجود وقت التكامل.
5. **`tests/visual/subscription-journey-integration.spec.ts`**: إضافة تحقق على الصفحة الموصولة: منع خلط الشركة، فشل التحديث مع لقطة قديمة، انتهاء الجلسة، تغير RBAC دون تبدل الشركة، استحقاق مسجل دون قدرة، بقاء نموذج اختيار OPTIONAL واحد فقط وعدم إرسال طلب من العرض. استمرار اختبارات مراجعة التغيير القائمة مطلوب.
6. **`apps/web/src/optional-modules/OptionalModulesCatalog.tsx` واختباراته**: يملك مسؤول الشريحة تعديل واجهة props إذا استدعى loader أو الترجمة ذلك، بعد تسلسل المدير. لا تعديل لـ`types.ts` أو OpenAPI أو ملفات الاعتماد مطلوب لهذا الربط.

معيار قبول الربط: لا تعرض بيانات جاهزة إلا بعد قراءة مقبولة للسياق الحالي، ولا تستبدل الطلبات المستقبلية الاستحقاق النافذ؛ مسار التغيير واحد، اختبارات الصفحة الفعلية ناجحة. لا يكفي اختبار fixture لإثباته.

## الأولويات لتفعيل وتعطيل آمنين لاحقًا

- **تخطيط مستقل — سياسة تعطيل مستقبلية عند مالك الاشتراك**: تحديد معنى توقف كل عملية مع إبقاء القراءة والتصدير والتدقيق التاريخي. لا حذف بيانات ولا تغيير دفتر الأستاذ عند التعطيل. وصف هذا السلوك سابقًا بفجوة P0 مسحوب: [سياسة SUB-2](PLATFORM_SUBSCRIPTION_CAPABILITY_ENFORCEMENT_AR.md) مؤرخة 2026-08-30 وتؤجل صراحة تعريف أثر حالات الاشتراك. أي سياسة تعطيل جديدة قرار منتج وخادم مستقل، ولا تتحول إلى قاعدة إخفاء في React.
- **P0 — إثبات الحواجز القائمة**: اختبارات API مباشرة لـRBAC والاستحقاق والشركة والاعتماديات؛ لا يكفي وجود كود في `/auth/me` لأن rollout والقيود التشغيلية الخاصة تبقى شروطًا إضافية.
- **P1 — إعادة استخدام التغييرات المؤرخة**: تمر كل إضافة/إزالة باختيار خطة ووحدات ومراجعة سعر وتأثير ثم أمر المالك القائم مع expectedCompanyId وversion وIdempotency. تبقى الحالات المعلقة والمجدولة والنتيجة المجهولة منفصلة، ولا يعادل الدفع الناجح تفعيلًا.
- **P1 — تحليل أثر الإزالة**: منع ترك تبعيات مكسورة؛ كشف العمليات المفتوحة ومهام الخلفية والتقارير اللازمة من خلال Query/Application Ports عند مالكيها. لا استعلام Prisma جديد عابر للسياق؛ لا API أسماء افتراضية قبل اعتماد عقد الحالة المحددة.
- **P1 — التزامن والرجوع**: اختبار تزامن تغيير الاشتراك مع العمليات المعتمدة على الوحدة على MariaDB/MySQL، أقفال مرتبة وdeadline وversion. إعادة التمكين تغيير مؤرخ جديد يحتفظ بالبيانات والتاريخ، وليس reset أو استعادة حالة محلية.
- **P2 — وحدات أو مكونات خارجية**: مهمة اكتشاف منفصلة وفق `OPEN_SOURCE_MODULE_ADOPTION_POLICY_AR.md` (مصادر، رخص، بصمات، اختبارات وخطة خروج) قبل اعتماد أي حزمة. هذه الشريحة تضيف واجهة React ضمن الاعتماد الحالي فقط.
