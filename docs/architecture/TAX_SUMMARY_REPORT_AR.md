# عقد ملخص الضريبة المحايد

## 1. الهدف وحدود النطاق

يقدم `Reporting` ملخصًا داخليًا للمطابقة حسب الفترة، واستخدام الضريبة، ونوع المستند، وحالة الحدث. لا يمثل التقرير إقرارًا ضريبيًا أو نموذجًا تنظيميًا لدولة بعينها، ولا يفسر أهلية الخصم أو توقيت الاستحقاق القانوني. لا ينشأ نموذج إقرار خاص بدولة قبل تحديد الـjurisdiction واعتماد قواعده ومراجعتها.

لا ينشئ التقرير قيودًا أو يعدل فاتورة أو معدل ضريبة. يقرأ لقطات بنود الفواتير المحفوظة عبر `TaxSummaryQueryPort` وAdapter مقيد بـ`companyId`، ثم يحسب المخرجات باستخدام `Prisma.Decimal`. أعيد استخدام بنية CSV/XLSX/PDF القائمة ولم تضف الشريحة Dependency جديدة.

## 2. مصدر الحقيقة والحساب

- المصدر هو `netAmount` و`taxAmount` و`taxRateSnapshot` و`exchangeRate` المحفوظة في كل بند، لا معدل الضريبة الحالي.
- تحول القيمة إلى عملة الأساس لكل بند ثم تقرب إلى أربع منازل بـ`ROUND_HALF_UP`.
- فاتورة المبيعات تزيد المخرجات، والإشعار الدائن يخفضها.
- فاتورة المشتريات تزيد المدخلات، والإشعار المدين يخفضها.
- صافي الضريبة المستحقة = ضريبة المخرجات - ضريبة المدخلات.
- عدد المستندات يحسب هويات أحداث المستند الفريدة ضمن النطاق، لا عدد البنود.

## 3. أساس الحدث وحالات المستند

الأساس الافتراضي `LEDGER` يعرض الأثر المرحل زمنيًا:

- يسجل أصل المستند كحدث `POSTED` في تاريخ المستند حتى إن أصبحت حالته الحالية `REVERSED` لاحقًا.
- يسجل العكس كحدث مستقل `REVERSED` بعكس الإشارة وفي تاريخ مستند العكس.
- لذلك لا يعيد عكس أغسطس كتابة نتيجة يوليو، ويصبح مجموع الأصل والعكس صفرًا عندما تشمل الفترة الحدثين.

مرشح الحالة اختياري لأغراض المراجعة: `POSTED` أو `REVERSED` أو `DRAFT` أو `CANCELLED`. عند اختياره يصبح الأساس `STATUS_FILTER`. المسودات والملغاة لا تدخل الأساس الافتراضي ولا تمثل أثرًا مرحلًا.

## 4. التجميع والعرض

يجمع التقرير حسب:

- `OUTPUT/INPUT`.
- نوع المستند: فاتورة بيع أو إشعارها الدائن، وفاتورة شراء أو إشعارها المدين.
- حالة الحدث.
- هوية معدل الضريبة ولقطة نسبته.

يعرض تبويب «ملخص الضريبة» في صفحة التقارير إجماليات المخرجات والمدخلات والصافي وعدد المستندات، وجدول التجميع بعملة الأساس، وتنبيهًا ثابتًا بأن المخرج ليس إقرارًا خاصًا بدولة. يدعم CSV وXLSX وPDF.

## 5. الأمن والعقد

- العرض يحتاج `reports.tax_summary.view`.
- التصدير يستخدم `reports.financial_statements.export` ويسجل `TAX_SUMMARY` في سجل التصدير.
- المدى الأقصى 366 يومًا، وجميع قراءات الـAdapter مقيدة بالشركة.
- يعلن OpenAPI عمليتي العرض والتصدير ومخطط الاستجابة، وتتحقق الاستجابة في بيئة التطوير والاختبار.

## 6. معايير القبول

- Calculator يغطي المخرجات والمدخلات والإشعارات والعكس المؤرخ والمرشح وسعر الصرف والتقريب.
- اختبار MariaDB من قاعدة فارغة يثبت قراءة لقطات البيع والشراء، والعكس في فترته، وعزل شركة أخرى.
- حارس معماري يمنع خدمة التقرير من القراءة المباشرة لجداول المبيعات والمشتريات والضرائب خارج Query Port.
- اختبارات Router وOpenAPI وتصدير CSV/XLSX/PDF وعقد الواجهة والترجمة والمصفوفة المتجاوبة.
- لا نشر ولا Push قبل أمر صريح من المستخدم.
