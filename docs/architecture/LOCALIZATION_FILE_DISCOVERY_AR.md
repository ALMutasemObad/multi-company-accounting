# قرار تصميم اكتشاف ملفات اللغات

التاريخ: 8 سبتمبر 2026

## القرار

مصدر حقيقة لغات الواجهة هو ملفات `apps/web/src/i18n/locales/*.locale.ts`. كل ملف حزمة ذاتية واحدة تجمع metadata والقاموس، واسمها يطابق `localeMetadata.code` بصيغة BCP47 معيارية. لا يوجد سجل يدوي لأكواد اللغات ولا map يدوي للمحمّلات.

يقرأ Vite metadata النصية أثناء البناء ويصدر module افتراضيًا صغيرًا. لا يستورد هذا module القواميس. يستخدم core glob ديناميكيًا ثابت النمط، ويربط مسار كل مدخل في manifest بدالة import الخاصة به. النتيجة أن خيارات اللغة معروفة من دون تحميل القواميس، وكل قاموس يبقى lazy chunk مستقلًا.

العربية `ar.locale.ts` إلزامية ومصدر مجموعة المفاتيح والاحتياط الآمن. ملفات اللغات لا تستخدم runtime imports؛ هذا يمنع Rollup من رفع fragments مشتركة تحتوي نصوص عدة لغات إلى chunk واحد كبير. يسمح باستيرادات type-only فقط.

## الحدود والتحقق

يتحقق `scripts/check-web-i18n.mjs` من:

- وجود العربية وبقاء العربية والإنجليزية والأوردية والهندية.
- اكتمال metadata وحصر حقولها واتجاهها وصحة BCP47 ومعياريته ومطابقة اسم الملف.
- كون القاموس literal ذاتيًا، وتساوي مفاتيحه مع العربية، وتساوي placeholders، وعدم وجود قيم فارغة أو علامات ترحيل.
- عدم وجود runtime imports داخل ملف اللغة، واستخدام core للـglob واستخدام registry للـmanifest.

ويتحقق plugin أثناء إنتاج bundle من عدم جمع ملفي لغة في chunk واحد ومن بقاء كل chunk لغة دون 500KiB. يقاس الحد ببايتات UTF-8 الفعلية (`Buffer.byteLength`) المطابقة للحجم غير المضغوط الذي يطبعه Vite، لا بعدد UTF-16 code units في JavaScript. هذا حد رجوع معماري وليس ترخيصًا لحشو القاموس حتى الحد.

## حدود الخادم

الخادم لا يملك سجل لغات الواجهة ولا يحتاج مزامنة مع build الواجهة. يقبل BCP47 المحافظ (`2..35` حرفًا مع تحقق `Intl.getCanonicalLocales`) ويخزن الصيغة المعيارية ضمن الحقول النصية الحالية، بلا migration.

قوالب البريد concern منفصل وله قائمة معلنة للنسخ الأصلية الحالية: `ar`, `en`, `ur`, `hi`. اختيار القالب يطابق الوسم كاملًا، ثم لغة الأساس، ثم العربية. لذلك إضافة ملف واجهة جديد لا تكسر التسجيل أو البريد ولا توهم بأن بريدًا مترجمًا أصبح متاحًا.

## نتيجة الأداء المرجعية

قبل القرار كان Rollup يرفع exports متعددة اللغات من fragments مشتركة إلى chunk باسم `employee-expenses` حجمه 591.43kB، رغم أن واجهة مصروفات الموظفين نفسها كانت 11.33kB. بعد جعل ملفات اللغات ذاتية اختفى chunk القواميس المشترك وبقيت واجهة مصروفات الموظفين 11.33kB. صارت القواميس chunks مستقلة: `ar` 267.71kB، `en` 214.89kB، `ur` 275.65kB، و`hi` 352.98kB، وكلها غير مضغوطة وتحت بوابة 500KiB.

## إضافة لغة

ينشئ المترجم ملف `<canonical-bcp47>.locale.ts` واحدًا، يملأ metadata والقاموس الكامل، ثم يشغّل `npm run i18n:check` واختبارات الويب والبناء. لا تعديل على registry أو core أو Vite أو عقود API أو خدمات التسجيل.

## دليل قبول الاكتشاف المباشر

أُجري اختبار قبول مؤقت في 8 سبتمبر 2026 بلغة `de-DE` غير مضمنة في المنتج النهائي:

1. نُسخ قاموس العربية كاملًا إلى `de-DE.locale.ts` مؤقت، وغُيرت metadata إلى BCP47 معياري والاسم الظاهر إلى `Deutsch (Deutschland)` ومفتاح `language.label` إلى `Sprache`.
2. أعاد `node scripts/check-web-i18n.mjs` نتيجة نجاح لخمس حزم ذاتية و3486 مفتاحًا في كل حزمة.
3. نجح اختبار مؤقت واحد يثبت أن `supportedLocales` و`LanguageSwitcher` يعرضان `de-DE`، وأن `loadLocale` يحمل الملف ويعيد `Sprache` من دون تعديل registry أو core.
4. أُنتج البناء مع manifest، وأثبت الفحص المباشر النتيجة التالية: `{"source":"src/i18n/locales/de-DE.locale.ts","file":"assets/de-DE.locale-Cob9MwMy.js","isDynamicEntry":true,"selectorLabel":"Deutsch (Deutschland)","lazyOnly":true}`. كانت `Sprache` غائبة عن entry chunks وموجودة في chunk الديناميكي للغة وحده.
5. حُذف ملف اللغة والاختبار المؤقتان، ثم أعيدت البوابات النهائية على اللغات الأربع فقط. لا يشحن هذا التغيير ترجمة ألمانية.

اختبار القياس `npm test -w @mcap/web -- vite.config.test.ts` يثبت كذلك أن حارس 500KiB يستخدم UTF-8، وأن النص غير اللاتيني يقاس بعدد بايتات أكبر من عدد code units، وأن payload مصطنعًا بحجم `500KiB + 1` يتجاوز الحد.
