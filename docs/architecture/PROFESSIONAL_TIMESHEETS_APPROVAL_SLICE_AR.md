# شريحة اعتماد الجداول الزمنية الأسبوعية

## حد الإغلاق

ينشئ الموظف المرتبط بحساب المستخدم فترة أسبوعية من الأحد إلى السبت، ويراجع مجموع الوقت الخام عبر مشاريعه، ثم يرسلها إلى صندوق الموافقات. تتجمد كل إدخالات أسبوعه حتى قرار Checker مستقل؛ الرفض يعيدها للتعديل ثم إعادة الإرسال، والاعتماد يثبتها نهائيًا.

## نموذج البيانات

### `ProfessionalTimesheet`

- معرف عام، `companyId`، `userId`، وبداية/نهاية الأسبوع.
- حالة `OPEN/AWAITING_APPROVAL/APPROVED` و`version`.
- `lastSubmissionNumber` و`activeSubmissionNumber` وبصمة الإرسال النشط وتوقيته.
- تفرد `(companyId, userId, periodStart)` وعلاقة مركبة بعضوية الشركة للعزل.

### `ProfessionalTimesheetSubmission`

- سجل immutable لكل محاولة إرسال، برقم متزايد داخل الفترة.
- JSON محدود يحوي معرف كل `ProfessionalTimeEntry` العام ونسخته فقط.
- SHA-256 للحقول الحاكمة المرتبة: المعرف والنسخة والمشروع والتاريخ والدقائق وقابلية الفوترة والوصف.
- لا يخزن مبلغًا أو سعرًا أو Invoice line أو قرار موافقة.

## حالات الاستخدام

- قائمة الفترات: `GET /professional-timesheets` مع `scope=MY|ALL` ومرشحات الحالة والتاريخ.
- إنشاء أسبوع شخصي: `POST /professional-timesheets` مع `periodStart` يوم أحد و`Idempotency-Key`.
- تفاصيل الأسبوع وإدخالاته: `GET /professional-timesheets/{professionalTimesheetId}`.
- الإرسال: `POST /approval-requests` بنوع `PROFESSIONAL_TIMESHEET` ومعرف ونسخة الفترة.
- الاعتماد/الرفض: أوامر Approvals الحالية؛ لا يضيف سياق المشاريع API قرار موازيًا.

لا يسمح بإرسال أسبوع بلا إدخالات، أو فترة لمستخدم ليس موظفًا نشطًا، أو فترة ليست `OPEN`، أو نسخة قديمة. لا يستطيع المستخدم إرسال فترة مستخدم آخر.

## OpenAPI والصلاحيات

يرتفع العقد إلى `1.34.0`، وتضاف العمليات الثلاث ومخططات Timesheet، ويوسع `ApprovalSubjectType`. تستخدم أجسام JSON الحراس المولدة. إنشاء الفترة وإرسال موضوعها يتطلبان `professional_timesheets.submit`، والعرض يتطلب `professional_timesheets.view`، والقرار يتطلب `approvals.decide`.

## الواجهة والترجمات

تضاف لوحة «جداولي الأسبوعية» داخل صفحة المشاريع المهنية: اختيار يوم الأحد، إنشاء الفترة، عرض المدة والمجاميع والحالة، وإرسال الفترة المفتوحة ذات الإدخالات. يبقى القرار في صندوق الموافقات وتعرض الصفحة هناك اسم موضوع Timesheet. تضاف النصوص العربية والإنجليزية والهندية والأردية دون نصوص مرئية ثابتة في JSX.

## العزل والتزامن والتدقيق

- كل Query مقيد بـ`companyId`، وتمنع العلاقات المركبة الارتباط بشركة أخرى.
- تقفل عمليات الوقت صف الفترة المطابق قبل التغيير، ويقفل الإرسال والقرار Aggregate الفترة نفسه.
- كل إرسال ينشئ لقطة واحدة؛ المفتاح نفسه والجسم نفسه يعيدان النتيجة، والمفتاح نفسه بجسم مختلف يرفض.
- `version` يحسم إرسالين أو قرارين متنافسين، ويفرض ApprovalRequest طلبًا نشطًا واحدًا للموضوع.
- تسجل أحداث إنشاء الفترة والإرسال والاعتماد والرفض داخل المعاملة.
- اختبار معماري يمنع خدمة المشاريع من الكتابة في HR أو ApprovalRequest/Decision أو Ledger/Sales/Inventory/Treasury.

## الترحيل والعكس

Migration `20260827230000_professional_timesheets_approval` تضيف الجداول والقيود والصلاحيات وتوسع Enum. يرفض العكس المدمر عند وجود Timesheet أو Submission أو طلب موضوع جديد. قبل الاستخدام فقط يحذف الصلاحيات والجداول ويعيد Enum. بعد الاستخدام يكون المسار الآمن تعطيل الواجهة والمسارات بطرح توافقي والاحتفاظ بالتاريخ ثم forward migration.

## مصفوفة الاختبار

- الأسبوع الصحيح، رفض يوم غير الأحد، ومنع أسبوع مكرر.
- ربط Employee نشط ورفض غير المرتبط/المنتهي.
- لقطة مرتبة ثابتة وبصمة واحدة وإرسال Idempotent.
- منع الإضافة والتعديل والحذف أثناء الانتظار وبعد الاعتماد.
- الرفض يعيد الفتح ويسمح بالتعديل ثم إرسال محاولة جديدة مع بقاء الأولى.
- Maker لا يقرر، وChecker يستطيع، وقراران متزامنان ينتج عنهما نجاح واحد.
- عزل شركتين والقوائم والتفاصيل والـsubject adapter.
- OpenAPI والحراس والاستجابة وTypeScript والواجهة والترجمات والبناء.
- قاعدة فارغة، ترقية قاعدة محلية، ورفض rollback بعد وجود بيانات.
