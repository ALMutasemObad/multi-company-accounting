# فهرس الحوكمة المعمارية

هذه المجلدات هي المرجع الحاكم لأي تغيير معماري أو إضافة مجال أعمال أو تعديل في الترحيل المحاسبي أو الأحداث.

2. [خريطة الـBounded Contexts](BOUNDED_CONTEXT_MAP_AR.md): مالك كل مفهوم واتجاهات الاعتماد المسموحة.

حالة التنفيذ: يخدم Transactional Outbox البريد والآثار اللاحقة ذات المستهلكين المعروفين، ويملك `PostingEngine` دفتر الأستاذ، وتستخدم تسويات Treasury عناصر ذمم مملوكة لـAR/AP. اكتملت المطابقة البنكية والإقفال والتقارير وPOS ومحرك Approvals. ويملك Professional Services & Projects المشروع والفريق والوقت وTimesheets المعتمدة وعقد الخدمة والسعر ومصدر الفوترة، وينشئ ويرحل الفاتورة عبر Sales port دون نسخ حقائق Sales أو Ledger. نُفذت E1 محليًا للمراحل والمهام والاعتماديات وميزانية الوقت، ولا تنشئ Outbox بلا مستهلك ولا تدعي Ethical Wall؛ يظل F1 شرط إطلاق قبل إدخال بيانات قانونية حساسة. يملك HR الهيكل والموظف والعقد غير المالي، وتبقى مصروفات E2 مؤجلة حتى قرار ملكية مستقل. لم يحدث نشر أو Push لهذه المراحل المحلية.

## ترتيب مصادر القرار

عند التعارض يستخدم الترتيب التالي داخل نطاق الاختصاص:

1. ADR مقبول وأحدث زمنيًا.
2. عقد OpenAPI ومخطط قاعدة البيانات والـMigration للسلوك المنفذ، كل في نطاقه.
3. الضوابط المعمارية وخريطة السياقات في هذا المجلد.
4. وثائق المنتج وحالات الاستخدام.
5. تقرير التدقيق كمرجع تشخيصي.

لا يعالج أي تعارض بصمت داخل الكود. يجب تحديث المصدر الحاكم أو إنشاء ADR جديد.

## متى يجب تحديث هذه الوثائق؟

يجب تحديثها عند:

- إنشاء Bounded Context أو وحدة أعمال جديدة.
- نقل ملكية جدول أو Aggregate بين السياقات.
- إضافة حدث Domain أو Integration جديد.
- إضافة Broker أو Queue أو Worker جديد.
- تغيير حدود معاملة الترحيل أو العكس أو إغلاق الفترة.
- تغيير سياسة الأقفال أو Retry أو Isolation أو deadlines.
- إضافة نوع رمز مرجعي أو تغيير صيغته أو نطاق تفرده أو قابليته للتعديل.
- تغيير جسم طلب أو استجابة JSON أو رمز حالة معلن أو دلالة نقل BIGINT/DECIMAL.
- السماح باستثناء جديد للوصول عبر حدود السياقات.
