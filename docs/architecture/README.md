# فهرس الحوكمة المعمارية

هذه المجلدات هي المرجع الحاكم لأي تغيير معماري أو إضافة مجال أعمال أو تعديل في الترحيل المحاسبي أو الأحداث.

## الوثائق الحاكمة

1. [الضوابط المعمارية](ARCHITECTURE_GUARDRAILS_AR.md): ما نحافظ عليه، وما يجب إصلاحه، والقواعد الإلزامية مستقبلًا.
2. [خريطة الـBounded Contexts](BOUNDED_CONTEXT_MAP_AR.md): مالك كل مفهوم واتجاهات الاعتماد المسموحة.
3. [ADR-003](ADR-003-domain-boundaries-and-eventing.md): القرار المعتمد لحدود المجالات والأحداث والـTransactional Outbox.
4. [سياسة رموز البيانات الرئيسية](MASTER_DATA_CODE_POLICY_AR.md): توليد الرموز المرجعية غير الدلالية، ثباتها، وعزلها وسلامتها تحت التزامن.
5. [سياسة التزامن والـDeadlock والـDeadlines](CONCURRENCY_DEADLOCK_DEADLINE_POLICY_AR.md): الأقفال وإعادة المحاولة والمهل والاختبارات الإلزامية.
6. [سياسة أمان استعادة كلمة المرور](PASSWORD_RESET_SECURITY_POLICY_AR.md): منع تعداد الحسابات، دورة الرمز، إلغاء الجلسات، ومتطلبات البريد.
7. [عناصر الذمم وعقد التسوية](AR_AP_SETTLEMENT_ITEMS_AR.md): الهوية المستقرة بين Treasury وAR/AP والـbackfill والتوافق والنشر.
8. [ملكية Tax وسياسة الحساب](TAX_CONTEXT_OWNERSHIP_AR.md): المالك الوحيد للنسب والحسابات والـquotes والتقريب والنسخ المتفائلة.
9. [ملكية Treasury وسياسة أدوات النقد](TREASURY_CONTEXT_OWNERSHIP_AR.md): المالك الوحيد للصناديق وطرق الدفع ومنفذ الحركات والنسخ المتفائلة.
10. [سياسة OpenAPI كعقد تنفيذي](OPENAPI_EXECUTABLE_CONTRACTS_AR.md): مصدر الحقيقة لأجسام JSON والتوليد والحراس وفحص الاستجابات وبوابات منع الانحراف.
11. [سياق استيراد البيانات](DATA_IMPORT_CONTEXT_AR.md): ملكية دفعة الاستيراد، الحدود الأمنية، المعاينة والاعتماد الذري، ومنافذ الأهداف.
12. [أساس سياق المخزون](INVENTORY_CONTEXT_FOUNDATION_AR.md): حدود شريحة المستودعات الحالية وخريطة التوسع إلى الأصناف والحركات والتكلفة.
13. [سياسة اعتماد الموديولات مفتوحة المصدر](OPEN_SOURCE_MODULE_ADOPTION_POLICY_AR.md): بوابة الاختيار والرخص والأمن وطريقة الربط وخطة التحديث والخروج.
14. [دراسة النواقص ودمج الموديولات مفتوحة المصدر](OPEN_SOURCE_MODULE_INTEGRATION_STUDY_AR.md): ترتيب الموديولات الناقصة، تقييم المرشحين، وخطة Prototype المطابقة البنكية.
15. [قائمة مراجعة التغيير](CHANGE_REVIEW_CHECKLIST_AR.md): بوابة إلزامية للمراجعة قبل دمج أي تغيير ذي أثر معماري.

التقرير [ARCHITECTURE_AUDIT_DDD_EVENT_DRIVEN_AR.md](../ARCHITECTURE_AUDIT_DDD_EVENT_DRIVEN_AR.md) وثيقة تقييم وأدلة، وليس بديلًا عن القرارات الحاكمة أعلاه.

حالة التنفيذ: يخدم Transactional Outbox بريد التسجيل وبريد استعادة كلمة المرور وأثر اكتمال الاستيراد، ويملك `PostingEngine` دفتر الأستاذ، وتستخدم تسويات Treasury عناصر ذمم مملوكة لـAR/AP بدل معرفات Ledger، وتملك وحدتا `Tax` و`Treasury` مرجعياتهما ومنافذهما والنسخ المتفائلة. ينسق `Data Import` مع مالكي العملاء والموردين والفواتير عبر منافذهم ولا يخزن الملف الخام. بدأ `Inventory` كسياق مستقل يملك المستودعات فقط في الشريحة الحالية دون أثر محاسبي. أصبح OpenAPI عقد JSON تنفيذيًا يولد جميع حراس أجسام الطلبات ومخططات الاستجابات ويمنع الانحراف آليًا؛ تبقى بقية عناصر إعادة الهيكلة تدريجية وفق حالة التنفيذ العامة.

## ترتيب مصادر القرار

عند التعارض يستخدم الترتيب التالي داخل نطاق الاختصاص:

1. ADR مقبول وأحدث زمنيًا.
2. عقد OpenAPI ومخطط قاعدة البيانات والـMigration للسلوك المنفذ، كل في نطاقه.
3. الضوابط المعمارية وخريطة السياقات في هذا المجلد.
4. وثائق المنتج وحالات الاستخدام.
5. تقرير التدقيق كمرجع تشخيصي.

لا يعالج أي تعارض بصمت داخل الكود. يجب تحديث المصدر الحاكم أو إنشاء ADR جديد.

## متى يجب تحديث هذه الوثائق؟

يجب تحديثها عند:

- إنشاء Bounded Context أو وحدة أعمال جديدة.
- نقل ملكية جدول أو Aggregate بين السياقات.
- إضافة حدث Domain أو Integration جديد.
- إضافة Broker أو Queue أو Worker جديد.
- تغيير حدود معاملة الترحيل أو العكس أو إغلاق الفترة.
- تغيير سياسة الأقفال أو Retry أو Isolation أو deadlines.
- إضافة نوع رمز مرجعي أو تغيير صيغته أو نطاق تفرده أو قابليته للتعديل.
- تغيير جسم طلب أو استجابة JSON أو رمز حالة معلن أو دلالة نقل BIGINT/DECIMAL.
- السماح باستثناء جديد للوصول عبر حدود السياقات.
