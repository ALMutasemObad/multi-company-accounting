الحالة الإجمالية والمنفذ مقابل المخطط والفجوات موجودة في
[وثيقة التسليم الحالية](../CURRENT_STATE_AND_NEXT_STEPS_AR.md).

حالة التنفيذ: يخدم Transactional Outbox البريد والآثار اللاحقة ذات المستهلكين المعروفين، ويملك `PostingEngine` دفتر الأستاذ، وتستخدم تسويات Treasury عناصر ذمم مملوكة لـAR/AP. اكتملت المطابقة البنكية والإقفال والتقارير وPOS ومحرك Approvals. ويملك Professional Project Delivery المشروع والفريق والجدار الأخلاقي والوقت وTimesheets المعتمدة وشروط فوترة المشروع، وينشئ ويرحل الفاتورة عبر Sales port دون نسخ حقائق Sales أو Ledger. نُفذت E1 وF1 وأساس HR وأصبحت ضمن baseline Staging `c1a5722`. نُفذت محليًا CRM-1 للـLead والفرصة والنشاط والتحويل عبر Sales Port، وعضوية Organization ومساحة مالك المجموعة بصلاحيات مستقلة بلا قوائم موحدة، وأول شريحة E2 كسياق Employee Expenses مستقل ينتهي عند `READY_FOR_PAYMENT` بلا دفع أو Ledger. يظل F2 شرطًا قبل أي تحويل من فرصة إلى قضية قانونية، وتنتظر الوحدات الثلاث بوابات المحركين وCI قبل الإصدار.

## ترتيب مصادر القرار

عند التعارض يستخدم الترتيب التالي داخل نطاق الاختصاص:

1. ADR مقبول وأحدث زمنيًا.
2. عقد OpenAPI ومخطط قاعدة البيانات والـMigration للسلوك المنفذ، كل في نطاقه.
3. الضوابط المعمارية وخريطة السياقات في هذا المجلد.
4. وثائق المنتج وحالات الاستخدام.
5. تقرير التدقيق كمرجع تشخيصي.

لا يعالج أي تعارض بصمت داخل الكود. يجب تحديث المصدر الحاكم أو إنشاء ADR جديد.

## متى يجب تحديث هذه الوثائق؟

يجب تحديثها عند:

- إنشاء Bounded Context أو وحدة أعمال جديدة.
- نقل ملكية جدول أو Aggregate بين السياقات.
- إضافة حدث Domain أو Integration جديد.
- إضافة Broker أو Queue أو Worker جديد.
- تغيير حدود معاملة الترحيل أو العكس أو إغلاق الفترة.
- تغيير سياسة الأقفال أو Retry أو Isolation أو deadlines.
- إضافة نوع رمز مرجعي أو تغيير صيغته أو نطاق تفرده أو قابليته للتعديل.
- تغيير جسم طلب أو استجابة JSON أو رمز حالة معلن أو دلالة نقل BIGINT/DECIMAL.
- السماح باستثناء جديد للوصول عبر حدود السياقات.
