# فهرس الحوكمة المعمارية

هذه المجلدات هي المرجع الحاكم لأي تغيير معماري أو إضافة مجال أعمال أو تعديل في الترحيل المحاسبي أو الأحداث.

## الوثائق الحاكمة

1. [الضوابط المعمارية](ARCHITECTURE_GUARDRAILS_AR.md): ما نحافظ عليه، وما يجب إصلاحه، والقواعد الإلزامية مستقبلًا.
2. [خريطة الـBounded Contexts](BOUNDED_CONTEXT_MAP_AR.md): مالك كل مفهوم واتجاهات الاعتماد المسموحة.
3. [ADR-003](ADR-003-domain-boundaries-and-eventing.md): القرار المعتمد لحدود المجالات والأحداث والـTransactional Outbox.
4. [ADR-004](ADR-004-pos-cash-sale-orchestration.md): اعتماد POS كمنسق رفيع للبيع النقدي من دون تكرار حقائق الفاتورة أو المخزون أو Ledger.
5. [خطة أول شريحة POS](POS_CASH_SALE_VERTICAL_SLICE_AR.md): النطاق ونموذج البيانات والمنافذ والعقود والصلاحيات والاختبارات والرجوع.
6. [سياسة رموز البيانات الرئيسية](MASTER_DATA_CODE_POLICY_AR.md): توليد الرموز المرجعية غير الدلالية، ثباتها، وعزلها وسلامتها تحت التزامن.
7. [سياسة التزامن والـDeadlock والـDeadlines](CONCURRENCY_DEADLOCK_DEADLINE_POLICY_AR.md): الأقفال وإعادة المحاولة والمهل والاختبارات الإلزامية.
8. [سياسة أمان استعادة كلمة المرور](PASSWORD_RESET_SECURITY_POLICY_AR.md): منع تعداد الحسابات، دورة الرمز، إلغاء الجلسات، ومتطلبات البريد.
9. [عناصر الذمم وعقد التسوية](AR_AP_SETTLEMENT_ITEMS_AR.md): الهوية المستقرة بين Treasury وAR/AP والـbackfill والتوافق والنشر.
10. [ملكية Tax وسياسة الحساب](TAX_CONTEXT_OWNERSHIP_AR.md): المالك الوحيد للنسب والحسابات والـquotes والتقريب والنسخ المتفائلة.
11. [ملكية Treasury وسياسة أدوات النقد](TREASURY_CONTEXT_OWNERSHIP_AR.md): المالك الوحيد للصناديق وطرق الدفع ومنفذ الحركات والنسخ المتفائلة.
12. [سياسة OpenAPI كعقد تنفيذي](OPENAPI_EXECUTABLE_CONTRACTS_AR.md): مصدر الحقيقة لأجسام JSON والتوليد والحراس وفحص الاستجابات وبوابات منع الانحراف.
13. [سياق استيراد البيانات](DATA_IMPORT_CONTEXT_AR.md): ملكية دفعة الاستيراد، الحدود الأمنية، المعاينة والاعتماد الذري، ومنافذ الأهداف.
14. [أساس سياق المخزون](INVENTORY_CONTEXT_FOUNDATION_AR.md): حدود شريحة المستودعات الحالية وخريطة التوسع إلى الأصناف والحركات والتكلفة.
15. [سياسة اعتماد الموديولات مفتوحة المصدر](OPEN_SOURCE_MODULE_ADOPTION_POLICY_AR.md): بوابة الاختيار والرخص والأمن وطريقة الربط وخطة التحديث والخروج.
16. [دراسة النواقص ودمج الموديولات مفتوحة المصدر](OPEN_SOURCE_MODULE_INTEGRATION_STUDY_AR.md): ترتيب الموديولات الناقصة، تقييم المرشحين، وخطة Prototype المطابقة البنكية.
17. [خطة تنفيذ المسار الهجين](HYBRID_MODULE_EXECUTION_PLAN_AR.md): المراحل والتسليمات وبوابات الانتقال والاختبارات والمخاطر بدءًا من المطابقة البنكية.
18. [سياسة عينات كشوف البنك](BANK_STATEMENT_FIXTURE_POLICY_AR.md): منع البيانات الحقيقية وضوابط العينات الاصطناعية للـParser.
19. [نتيجة Spike قارئ كشوف البنك](BANK_STATEMENT_PARSER_SPIKE_RESULT_AR.md): أدلة بوابة المرحلتين 0 و1 وقرار Go المقيد بطبقة القراءة.
20. [Backend المطابقة البنكية](BANK_RECONCILIATION_BACKEND_AR.md): ملكية البيانات والمنافذ وقواعد 1:1 وRBAC والتزامن والرجوع وحد Ledger.
21. [عقد الإقفال المالي الشهري والسنوي](FINANCIAL_CLOSE_WORKFLOW_AR.md): دورة التحضير والمراجعة والإقفال، قائمة الجاهزية، حزمة الإقفال، قيد نتيجة السنة والعكس.
22. [عقد قائمة التدفق النقدي بالطريقة غير المباشرة](INDIRECT_CASH_FLOW_REPORT_AR.md): مصادر الأرصدة، معادلة المطابقة، تصنيف الحسابات، وصلاحيات العرض والإدارة.
23. [عقد ملخص الضريبة المحايد](TAX_SUMMARY_REPORT_AR.md): أساس أحداث الترحيل والعكس، لقطات الضريبة، التجميع، وحد الفصل عن الإقرار الخاص بالدولة.
24. [عقد تقرير حركة مراكز التكلفة الفعلية](COST_CENTER_ACTIVITY_REPORT_AR.md): قراءة Ledger المقيدة بالشركة، وتجميع Decimal، والإجماليات والانتقال المقيد إلى كشف الأستاذ.
25. [قائمة مراجعة التغيير](CHANGE_REVIEW_CHECKLIST_AR.md): بوابة إلزامية للمراجعة قبل دمج أي تغيير ذي أثر معماري.

التقرير [ARCHITECTURE_AUDIT_DDD_EVENT_DRIVEN_AR.md](../ARCHITECTURE_AUDIT_DDD_EVENT_DRIVEN_AR.md) وثيقة تقييم وأدلة، وليس بديلًا عن القرارات الحاكمة أعلاه.

حالة التنفيذ: يخدم Transactional Outbox بريد التسجيل وبريد استعادة كلمة المرور وأثر اكتمال الاستيراد، ويملك `PostingEngine` دفتر الأستاذ، وتستخدم تسويات Treasury عناصر ذمم مملوكة لـAR/AP بدل معرفات Ledger، وتملك وحدتا `Tax` و`Treasury` مرجعياتهما ومنافذهما والنسخ المتفائلة. ينسق `Data Import` مع مالكي العملاء والموردين والفواتير عبر منافذهم ولا يخزن الملف الخام. يملك `Inventory` دفتر الحركة والتقييم ويفوض قيوده إلى `PostingEngine`. أصبح OpenAPI عقد JSON تنفيذيًا يولد جميع حراس أجسام الطلبات ومخططات الاستجابات ويمنع الانحراف آليًا. اكتملت المطابقة البنكية والإقفال المالي المراجع والتقارير الأساسية، ثم نفذت شريحة POS النقدية كمنسق يملك رابط المستندين فقط. لم يحدث نشر أو Push لهذه المراحل.

## ترتيب مصادر القرار

عند التعارض يستخدم الترتيب التالي داخل نطاق الاختصاص:

1. ADR مقبول وأحدث زمنيًا.
2. عقد OpenAPI ومخطط قاعدة البيانات والـMigration للسلوك المنفذ، كل في نطاقه.
3. الضوابط المعمارية وخريطة السياقات في هذا المجلد.
4. وثائق المنتج وحالات الاستخدام.
5. تقرير التدقيق كمرجع تشخيصي.

لا يعالج أي تعارض بصمت داخل الكود. يجب تحديث المصدر الحاكم أو إنشاء ADR جديد.

## متى يجب تحديث هذه الوثائق؟

يجب تحديثها عند:

- إنشاء Bounded Context أو وحدة أعمال جديدة.
- نقل ملكية جدول أو Aggregate بين السياقات.
- إضافة حدث Domain أو Integration جديد.
- إضافة Broker أو Queue أو Worker جديد.
- تغيير حدود معاملة الترحيل أو العكس أو إغلاق الفترة.
- تغيير سياسة الأقفال أو Retry أو Isolation أو deadlines.
- إضافة نوع رمز مرجعي أو تغيير صيغته أو نطاق تفرده أو قابليته للتعديل.
- تغيير جسم طلب أو استجابة JSON أو رمز حالة معلن أو دلالة نقل BIGINT/DECIMAL.
- السماح باستثناء جديد للوصول عبر حدود السياقات.
