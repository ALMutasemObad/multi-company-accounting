# شريحة عقود وأسعار وفوترة الخدمات المهنية

## حد الإغلاق

ينشئ مسؤول مخول عقد وقت ومواد لمشروع مهني، ويضيف أسعار ساعة مؤرخة لأعضاء المشروع. بعد اعتماد أسابيع العمل، يحدد فترة فوترة وتصنيف الإيراد والضريبة والفترة المالية، فينشئ النظام فاتورة Sales مرحلة واحدة ويربطها بلقطة مصدر لا تقبل التعديل.

## نموذج البيانات

### `ProfessionalServiceContract`

- معرف عام، `companyId`، `projectId`، عملة الشركة، مرجع خارجي اختياري، بداية/نهاية، وأيام استحقاق.
- `version` للتزامن، وعلاقات مركبة تمنع ربط مشروع أو عملة من شركة أخرى.
- لا يسمح بتداخل عقدين لنفس المشروع، ولا بإنشائه لمشروع غير `TIME_AND_MATERIALS`.

### `ProfessionalServiceRate`

- عقد وعضو مشروع، مبلغ ساعة `DECIMAL(19,4)`، بداية/نهاية، و`version`.
- لا يتداخل سعران للعضو نفسه داخل العقد، ويلزم أن يكون عضوًا نشطًا عند الإنشاء.
- يمنع إنهاء العقد بتاريخ يترك سعرًا مفتوحًا أو ممتدًا بعده؛ ينهي المسؤول الأسعار أولًا ثم العقد.
- السعر ليس راتبًا أو تكلفة موظف ولا يعرض عبر صلاحيات المشاريع العامة.

### `ProfessionalBillingRun` و`ProfessionalBillingSourceLine`

- التشغيل immutable ويربط المشروع والعقد وفاتورة Sales المرحلة ونطاق تواريخ المصدر ومنفذ العملية.
- السطر يخزن مرجع ونسخة الوقت، ومرجع ونسخة السعر، والدقائق وسعر الساعة المطبق فقط.
- كل `ProfessionalTimeEntry` يستخدم مرة واحدة على الأكثر. لا تُخزن الضريبة أو إجماليات الفاتورة أو الذمة أو القيد.

## حالات الاستخدام وOpenAPI

- قائمة/إنشاء/إنهاء عقد خدمة مؤرخ.
- قائمة/إنشاء/إنهاء سعر عضو مؤرخ.
- قائمة تشغيلات المشروع وتفاصيل التشغيل ومصادره.
- تنفيذ فوترة مشروع واحد بتاريخ بداية/نهاية، وفترة مالية، وتاريخ مستند، وسعر صرف، وحساب إيراد، ومركز تكلفة وضريبة اختياريين.
- كل أجسام JSON تمر عبر الحراس المولدة، وتخرج مبالغ DECIMAL كنصوص ومعرفات BIGINT كنصوص.

## سياسة الفوترة

- المشروع والعقد `TIME_AND_MATERIALS` والنطاق داخل مدة العقد.
- الإدخال billable، داخل Timesheet `APPROVED`، ونسخته الحالية هي التي تعتمدها اللقطة.
- لكل إدخال سعر عضو وحيد فعال في تاريخ العمل.
- لا يقبل النطاق الخالي أو أكثر من 200 إدخال في الشريحة الأولى.
- كمية سطر Sales هي الساعات من الدقائق بدقة ست منازل، وسعر الوحدة هو سعر الساعة؛ Sales يحسب التقريب والضريبة والإجماليات.
- تاريخ الاستحقاق يساوي تاريخ المستند زائد أيام العقد.

## العزل والتزامن والتدقيق

- كل Query مقيد بـ`companyId` وكل علاقة عابرة للشركة مركبة.
- التنفيذ Idempotent؛ المفتاح والجسم نفسيهما يعيدان النتيجة، وإعادة المفتاح بجسم مختلف ترفض.
- قفل المشروع يسلسل إنشاء/إنهاء العقود والأسعار وأوامر الفوترة، ويسبق إنشاء مستند Sales بعد قفل الفترة المالية.
- الفاتورة والترحيل ولقطة المصدر وAudit وIdempotency في معاملة واحدة؛ فشل أي خطوة يلغي الجميع.
- الحارس المعماري يمنع خدمة الفوترة المهنية من الكتابة المباشرة في SalesInvoice/Tax/Ledger/AR.

## الواجهة والترجمات

تضاف لوحة فوترة داخل صفحة المشروع المختار: العقد الفعال، أسعار الأعضاء، نموذج إنشاء عقد/سعر، ونموذج فوترة الوقت المعتمد. تظهر الفاتورة الناتجة برقمها وحالتها وإجماليها من Sales Query Port، مع العربية والإنجليزية والهندية والأردية.

## مسار الترحيل والعكس

- يطبق Migration 54 على قاعدة فارغة وكترقية من 53، ويهيئ الصلاحيات للدور النظامي.
- ينجح rollback قبل الاستخدام فقط، ويرفض بوضوح عند وجود عقد أو سعر أو تشغيل أو سطر مصدر.
- بعد الاستخدام يكون الرجوع الآمن بإخفاء الواجهة وتعطيل الأوامر مع الاحتفاظ بالتاريخ، ثم forward migration.

## مصفوفة الاختبار

- عقد صحيح، رفض غير T&M، ورفض تداخل العقود أو شركة/عملة غير صحيحة.
- سعر عضو صحيح، رفض غير العضو والتداخل والقيمة غير الموجبة.
- وقت مفتوح/منتظر/غير billable/مفوتر سابقًا لا يدخل الفاتورة.
- أسعار مختلفة حسب العضو والتاريخ ولقطة ثابتة بعد تغير السعر اللاحق.
- طلب متزامن ينتج فاتورة وقيدًا وتشغيلًا واحدًا، ومفتاح مختلف لا يفوتر المصدر مرتين.
- فشل Sales أو الفترة أو الضريبة يلغي لقطة المصدر بالكامل.
- عزل شركتين، صلاحيات الأسعار والفوترة، OpenAPI، الواجهة والترجمات، قاعدة فارغة، ترقية، ورفض rollback بعد البيانات.
