# حالة تنفيذ النظام المحاسبي متعدد الشركات

آخر تحديث: 21 أغسطس 2026

## ملخص تنفيذي

- البنية: Modular Monolith داخل npm workspaces.
- الخادم: Express وTypeScript وPrisma 7.9.1.
- الواجهة: React وVite بواجهة عربية وإنجليزية تشغيلية للوحة التحكم والتقارير والعملاء والسندات والسنوات والفترات والقيود اليومية ودليل الحسابات ومراكز التكلفة والخزينة وطرق الدفع، مع RTL/LTR والتجاوب.
- قاعدة التطوير: MariaDB 10.4 عبر XAMPP.
- الترحيلات الحالية: 27؛ طُبقت السلسلة كاملة من الصفر وترقية الإصدار السابق على MariaDB 10.4 معزولة، وتتحقق CI منها على MariaDB 10.11 وMySQL 8.4.
- حزمة التحقق: 156 تحققًا آليًا في 48 ملفًا؛ نجح 118 اختبار API فعليًا على قاعدة معزولة، و20 للواجهة، و17 للبنية التحتية، ورحلة E2E كاملة.
- الحالة: فحص TypeScript وبناء الإنتاج والترحيلات والنسخ والاستعادة المحلية وE2E ناجحة؛ يلزم نجاح Workflow البعيد المحسن قبل نشر Artifact.
- الحوكمة المعمارية: اعتُمدت ضوابط DDD وحدود الـBounded Contexts وADR-003 للأحداث والـTransactional Outbox، مع قواعد انتقالية تمنع زيادة الترابط الحالي دون الادعاء بأن إعادة الهيكلة نُفذت برمجيًا.

## ضوابط معمارية مطبقة

- كل المبالغ المالية `DECIMAL` وتنتقل في API كنصوص.
- كل البيانات التشغيلية مقيدة بالشركة في الاستعلامات والعلاقات المركبة.
- المستندات تستخدم `DRAFT / POSTED / CANCELLED / REVERSED`.
- التعديل للمسودة فقط؛ التصحيح بعد الترحيل يتم بالعكس.
- العمليات الحساسة تستخدم CSRF وRBAC وOptimistic Version وIdempotency.
- الفجوات في تسلسل المستندات مقبولة ومدققة لأن الرقم يحجز عند إنشاء المسودة.
- البيانات الحساسة لا تعاد بصورتها الخام في استجابات API.
