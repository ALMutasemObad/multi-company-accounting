| المرحلة | ميزانية انتظار العميل | التعافي |
|---|---:|---|

| CSRF مع طلب الدخول أو التسجيل أو الاستعادة | 15 ثانية للمحاولة كلها، لا لكل خطوة | إيقاف الانتظار، ورسالة مترجمة، وإرسال يدوي فقط |

هذه ميزانيات UX وليست SLO أو إثبات إصلاح أداء الاستضافة.

- `api.ts` يقبل `timeoutMs` اختياريًا ويؤلف إشارة المستدعي مع مهلة تشمل استهلاك جسم
  الرد، وينظف المؤقتات والمستمعين في النجاح والفشل والإلغاء. `RequestError` يفرق
  المهلة والإلغاء والنقل والرد غير القابل للقراءة؛ يبقى `ApiError` محتفظًا بالحالة
  والرمز والسبب، وتبقى credentials وCSRF وIdempotency headers. لا تتغير التنزيلات.
- `useAuthAction` يمنع النقر المزدوج تزامنيًا، ويلغي العمل عند مغادرة الشاشة، ويحجب
  نتائج المحاولات القديمة. لا تعود نتيجة CSRF المتأخرة لتستبدل رمز محاولة أحدث.
- لا Retry تلقائي لأي POST أو كلمة مرور، ولا حفظ كلمات المرور لإعادة الإرسال.
  أزيلت حلقة إعادة POST التحقق السابقة عند `IN_PROGRESS`، مع منع مضاعفته في StrictMode
  أو عند تغيير اللغة. النقر اليدوي الجديد هو محاولة جديدة وليس استئنافًا مضمونًا.
- لا ينتظر الانتقال للتسجيل/الاستعادة/العودة طلب CSRF. يتجدد PRE_AUTH داخل المحاولة
  الصريحة قبل POST، ويمنع فشله أو إلغاؤه إرسال كلمة المرور أو نموذج الكتابة.
- انتهاء انتظار POST أو إلغاؤه لا يثبت عدم تنفيذه. تعرض الرسائل احتمال وصول الطلب؛
  يوصى بفحص البريد قبل إعادة طلب الرابط، أو تجربة كلمة المرور الجديدة بعد تغيير
  غير مؤكد، أو فحص جلسة الدخول للقراءة فقط. لا يزعم الإلغاء التراجع عن معاملة الخادم.
- عرض العربية والإنجليزية والأردية والهندية، مع role=alert وتركيز الخطأ ولوحة مفاتيح،
  ومقاسين أساسيين 26px للعناوين و16px للنصوص داخل شاشات المصادقة فقط.
- بقيت روابط الخطط العامة و`preferredSubscriptionPlan` ونية اختيار الباقة كما هي.

## قيد CSRF الواجب الحفاظ عليه عند التكامل

`GET /auth/csrf` يصدر PRE_AUTH جديدًا ويستبدل cookie؛ ليس منفذ استرجاع CSRF لجلسة
مصادق عليها. لا يستدعى أثناء تعافي shell بعد نجاح login الكامل. إذا ضاع جسم نجاح
`POST /auth/login`، قد تصل cookie دون رمز CSRF الجديد؛ فحص `/auth/me` هنا **قراءة فقط**
ولا يفتح المساحة أو يرسل `/auth/context`. إن وجد جلسة، يوضح لزوم دخول يدوي جديد
لاستكمال التحقق الآمن. لا توجد استعادة مضمونة دون كلمة مرور لهذه الحالة في العقد الحالي.

إذا أعاد تحميل shell حالة 401، يعاد نموذج الدخول دون إعادة POST أو مسح CSRF تلقائيًا.
رفض 403 لا يثبت إبطال الجلسة: يبقى السياق غير مفعل والرمز الصالح محفوظًا، ويستطيع
المستخدم اختيار نشاط مسموح صراحة. اختبر الرفض ثم النجاح مع الرمز نفسه، كما اختبر
انتهاء الجلسة بعد نجاح login. الخادم يبقى صاحب إنفاذ RBAC وعزل الشركات؛ لا تجاوز محلي.

node node_modules/typescript/bin/tsc -p apps/web/tsconfig.json --pretty false

node node_modules/@playwright/test/cli.js test --config playwright.track-b.config.ts
node scripts/generate-openapi-guards.mjs --check
node scripts/check-web-i18n.mjs
node scripts/check-web-ui.mjs

Vite يشتق جذر النسخة من موضع config ويتيح مجلدها وخطوط @fontsource الفعلية فقط، وليس
مصدر نسخة التكامل. `TRACK_B_PUBLIC_REGRESSION=1` يختار ملف اختبارات A لأغراض التكامل؛
الجولة النهائية الثمانية استخدمت `--grep 'anonymous responsive catalog'` دون تشغيل
اختبار الكتالوج القديم. ينصح بانتظار تحرير مساحة القرص قبل جولة شاملة أخرى.
