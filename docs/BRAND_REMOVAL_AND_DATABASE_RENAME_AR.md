# إزالة الاسم القديم وإعادة تسمية قاعدة Staging

## نطاق التنظيف

- نصوص المنتج ورسائل التسجيل واستعادة كلمة المرور.
- Fixtures وبيانات العرض والاختبارات والوثائق والأمثلة.
- أسماء Schema وقواعد الاختبار وأسرار الاتصال الخاصة بالبيئة المنشورة.
- أي بيانات Demo مملوكة للمنتج بعد جردها.

لا ينفذ تحديث شامل لكل عمود نصي في كل جدول؛ قد تكون الكلمة جزءًا من بيانات أدخلها
المستخدم أو مستند تاريخي. يفحص كل تطابق بمالكه، وتصحح بيانات Demo فقط. الحقائق
المحاسبية واللقطات المؤرشفة لا يعاد كتابتها لأجل تغيير علامة.

## الوضع المكتشف محليًا

ملفات Git والأمثلة القياسية تستخدم الاسم المحايد `mcap_finance`. ملف البيئة المحلي
غير المتعقب كان يشير إلى اسم تطوير قديم، ولا يثبت اسم قاعدة Staging لأن قيمة
`DATABASE_URL` البعيدة سر خارج المستودع.

## بوابة عدم الرجوع

يحتوي فحص البنية على اختبار يمسح الملفات المتعقبة وغير المتجاهلة ويمنع عودة الاسم
القديم بصيغ العربية/الأردية واللاتينية والهندية، مع عدم اعتبار الكلمة العربية العادية
التي تعني «إلى جانب» علامة تجارية.

قبل أول إطلاق حي يجب أن يثبت سجل الإصدار:

1. نجاح فحص المستودع.
2. جرد اسم Schema في Staging ونسخة احتياطية قابلة للاستعادة.
3. تشغيل Staging على الاسم المحايد ونجاح health/readiness والبوابات.
4. عدم وجود الاسم في APP_NAME أو VITE_APP_NAME أو مرسل البريد أو ملفات PDF الجديدة.
5. مسح بيانات Demo المملوكة للمنتج دون تعديل سجلات أعمال تاريخية غير مصنفة.
