## تجربة الاستخدام والقياس

القياس من `PosPage.tsx` عند الأساس؛ لا أزمنة تشغيل متجر مقاسة ولا ادعاء نسبة تسريع.

| الجزء | قبل | بعد |
|---|---|---|
| سياق العملية | 10 حقول ظاهرة، إضافة إلى الملاحظات | نفس10 حقول صريحة داخل مجموعة قابلة للطي، والملاحظات في السلة؛ لا حذف للتحقق |
| اختيار الصنف | picker داخل كل سطر أو المسح، بلا كتالوج بيع | بحث بصفحات خادمية أو مسح؛ نقرة/مسح واحد يضيف الصنف الحقيقي وملفه المهيأ |
| السطر | 6 حقول: الصنف، الكمية، السعر، الخصم، حساب الإيراد، الضريبة | هوية ثابتة للصنف وحقلا كمية/سعر؛ الخصم والحساب والضريبة ضمن تفاصيل قابلة للفتح |
| ملف ناقص أو عملة مختلفة | لا مصدر سعر بيع موثوق | سعر فارغ ورسالة صريحة وتفاصيل محاسبية مفتوحة؛ يختار المستخدم سعرًا ومراجع صحيحة |

retail هو الوضع الافتراضي، وtiles يعرض نفس أصناف API ونفس السلة، لا أصناف أو
أسعار صورية في المنتج. ترتيب الكاشير: مراجعة السياق، بحث/مسح، مراجعة السلة، إتمام.
مقاسا الخط داخل النطاق16px و20px؛ عناصر اللمس44px على الأقل، مع keyboard focus
وRTL/LTR. منطقة المنتجات قابلة للتمرير دون ضغط محتوى البطاقات. السجل أسفل
العملية وقابل للطي. مهارة المتصفح وجهت الفحص البصري؛ كشف فحص الصورة انكماش
صفوف الشبكة الذي لم يكشفه تحقق عرض الصفحة وحده، فأضيف اختبار احتواء البطاقات.

## عقد R2 ونقطة القراءة

العقد النهائي المرجعي: `docs/architecture/SALES_ITEM_SELLING_PROFILE_R2_AR.md`
من مسار R2، مطابق لقارئ `apps/web/src/pos-experience-catalog.ts`:

- `GET /sales/catalog?page=1&pageSize=24&search=...` يعيد `{data,meta}`.
  حجم الصفحة المحلي24؛ الصفحة1..10000؛ البحث حتى100 محرف بلا control characters.
  debounce250ms، AbortController وepoch ضد الرد القديم، timeout10s، لا جلب الكل.
- `GET /sales/catalog/items/{inventoryItemId}` يعيد `{data:row}` بعد scanner resolve؛
  يرفض القارئ اختلاف هوية الصنف. تحول `inventoryItemId` إلى `id` فقط عند دخول
  التحويل المشترك للمسح، ولا parser باركود جديد.
- `sellingProfile` قابل لـnull، و`unitPrice` نص fixed4، و`currencyCode` قابل لـnull؛
  لا تخمين رمز عملة بديل. الحساب والضريبة وversion تؤخذ من الملف المعتمد.
- الصفر سعر صريح وصالح. `isReady=false` لا يطبق سعرًا تلقائيًا. `isReady` أهلية
  تهيئة المراجع فقط، لا رصيد مخزون أو فترة مفتوحة أو ضمان Checkout.
- اختلاف `currencyId` يمنع التطبيق التلقائي ويظهر تعارضًا. تغيير عملة السلة
  يلغي الطلبات المعلقة ويفرغ الأسعار لمراجعة صريحة؛ لا تحويل سعر تلقائي.
- القراءة تتطلب `sales_catalog.view` الفعالة وحق إتمام POS في هذه الواجهة؛
  لا إضافة صلاحيات مراجع عامة. محرر ملف البيع وكتابته يملكهما R2 ويركبهما R0.

السعر/الحساب/الضريبة افتراضات ظاهرة قابلة للمراجعة وليست سياسة منع override جديدة.
يحمل Checkout حقول السطر الصريحة وفق عقد POS القائم، ويعيد الخادم تحقق المراجع
والمخزون والفترة والتسعير والترحيل. لا محرك حساب/ضريبة موازٍ ولا كتابة مباشرة
لمجال آخر ولا network I/O داخل معاملة جديدة من R1.

## Barcode Impact والتزامن

- أُبقي `InventoryBarcodeScanner` وInventory resolve والتحويل
  `applyResolvedBarcodeToLines` بلا تعديل؛ النقر والمسح يمران بنفس `addPosItem`.
- حافظنا على FIFO وleading zeros وعدم تحويل قيمة الباركود إلى رقم، وحد50 سطرًا،
  والزيادة الدقيقة للصنف المتكرر؛ المسح المتكرر لا يعيد تسعير السطر.
- بعد resolve يوجد انتظار مستقل لجلب ملف البيع. Checkout ممنوع أثناء pending
  scanner **أو** pending lookup، مع حارس فوري يقرأ refs لا حالة العرض فقط.
  «بيع جديد» لا يتاح قبل انقضاء الاثنين أيضًا.
- كل تعديل يدوي أو حذف للسطر يبطل token طلبه؛ تغيير العملة يبطل كل الطلبات.
  تغيير المستخدم/النشاط/الصلاحيات/الموديولات يعيد تركيب الشاشة ويلغي القراءات
  والمسح. الرد المتأخر لا يكتب فوق اختيار أحدث أو يدخل نشاطًا آخر.
- تغيير السعر/الحساب/الضريبة يدويًا ظاهر كمصدر يدوي؛ غياب ملف أو فشل جلبه لا
  يحول إلى صفر. لا كاميرا أو إعداد جهاز جديد في هذه الدفعة.

اختبارات FIFO والباركود هنا محاكاة إدخال لوحة مفاتيح/شبكة فقط؛ ليست قبول قارئ
USB/Bluetooth حقيقي أو كاميرا أو طابعة.

## دقة Decimal

`pos-experience-money.ts` يحافظ على النص المالي: مبالغ4 منازل (حد15 رقمًا صحيحًا)،
كميات6 (حد13 رقمًا صحيحًا)، ومعدل صرف8 (حد11 رقمًا صحيحًا). لا `Number` أو
`parseFloat` لمسار المبالغ أو عرض إجمالي الخادم. القياسات والزمن وأرقام الصفحات
ليست أموالًا.

الحساب العرضي قبل الضريبة يستخدم BigInt scaled وROUND_HALF_UP عند4 منازل،
ويرفض الصيغة غير الصالحة أو الدقة الزائدة والخصم الذي يتجاوز قيمة السطر. لا Tax
Engine في الواجهة؛ الملخص مصرح بأنه قبل الضريبة وليس المبلغ النهائي للتحصيل.
الإجمالي النهائي يعرض من استجابة الخادم كنص دقيق. يغطي الاختبار مبلغًا أكبر من
حد الدقة الآمنة لـJavaScript وأجزاء0.1 والتقريب الحدّي والسعر0.

## Checkout: فقد الاستجابة ومنع التكرار

`pos-experience-checkout.ts` مخزن ذاكرة داخل وثيقة SPA، مقيد بالمستخدم والنشاط:

1. قبل الإرسال، قفل متزامن وsnapshot للسياق والسلة وbody نصي ثابت وIdempotency-Key.
   يمنع النقر المزدوج أو submit متزامنًا قبل render جديد.
2. استجابة الشبكة المفقودة/الإلغاء/5xx/408/Idempotency in-progress أو mismatch،
   وكذلك success ناقص أو غير POSTED، تعني نتيجة مجهولة. لا تنظيف سلة أو مفتاح جديد.
3. إعادة المحاولة فعل يدوي فقط، بنفس body/key تمامًا. لا replay تلقائي. إذا كانت
   المحاولة مجهولة سابقًا لا يفكها رفض أعمال لاحق. الرفض المؤكد الأول فقط يفك
   القفل مع إبقاء البنود للمراجعة.
4. النجاح لا يعتمد HTTP وحده؛ يلزم هوية POS وهوية/رقم وحالة POSTED للفاتورة
   والقبض وإجمالي fixed4. يبقى النجاح والسلة مقفلين حتى «بيع جديد» الصريح.
5. remount والتنقل داخل SPA والعودة لنفس المستخدم/النشاط يحتفظ بالمحاولة، وتظل
   المحاولات الأخرى معزولة. يوجد beforeunload warning ما دامت محاولة غير مكتملة
   في الذاكرة حتى عند مغادرة موديول POS.

نافذة retry المحلية المحافظة23h من **original createdAt**، معتمدة من R0 تحت
الافتراضي الحالي24h في Executor (POS بلا override). ليست ضمان احتفاظ خادمي أو
SLO. `>=23h` يمنع الإرسال، وكذلك الساعة غير الصالحة أو رجوعها، ويظل القفل
وbody/key كما هما؛ لا تمديد للنافذة عند retry ولا «بيع جديد» بديل.
اختُبر الحد تمامًا وبعده بـ1ms ورجوع الساعة بعد انقضائه، وNaN، وثبات createdAt.

حد معروف: الذاكرة لا تنجو من reload/إغلاق المتصفح أو تبويب جديد؛ التحذير لا
يضمن منع الإغلاق. لا localStorage للأموال ولا Offline. يلزم لاحقًا عقد إيصال
استرجاع/استعلام خادمي دائم للمحاولة المجهولة، خصوصًا بعد23h أو فقد الوثيقة؛ لا
تدّعي هذه الشريحة معالجة ذلك، ولا يجوز تكرار العملية غير المحسومة بمفتاح جديد.

روابط النجاح `#sales` و`#receipts` فقط حسب الصلاحيات، وبنص صريح أنها تفتح
**القائمة**. لا query/deep-link غير منفذ ولا ادعاء طباعة أو إيصال مكتمل؛ عقد
عرض المستند المفرد يقرره R0 لاحقًا.

## Contextual Defaults وعزل التفضيلات

المحفوظ في localStorage هو `retail|tiles` فقط، بمفتاح مقيد بالمستخدم والنشاط.
لا أسعار أو حسابات أو عميل أو مستودع أو صندوق أو سلة مالية في التخزين. فشل
التخزين يعيد retail بأمان. تغيير النشاط لا يستعير سياق نشاط آخر.

العملة الأساسية فقط تأتي من `isBase` الخادمي وتظهر صراحة؛ لا اختيار أول عنصر
قائمة كافتراض محاسبي. الفترة تظل اختيارًا صريحًا، ولا ندّعي اشتقاق الفترة من
التاريخ قبل عقد خادمي لذلك. تاريخ البداية حسب timezone النشاط وبالتقويم
الميلادي، ومعدل الصرف ظاهر؛ عند اختيار عملة غير أساسية يفرغ حتى يحدده المستخدم.
الصندوق/المستودع/العميل/طريقة الدفع لا تؤخذ من آخر بيع أو تخزين صامت.

## إعادة التشغيل والربط لدى R0

من نسخة D المخصصة فقط، استخدم runtime المعطى في PATH وTEMP/TMP إلى `tmp/agent`.
الـcache محدد في configs تحت `apps/web/node_modules/.cache-track-r1` المحلي؛ لا
كتابة عبر junction الاعتماديات. الأوامر لا تحتاج تثبيتًا أو generate:

```text
node node_modules/vitest/vitest.mjs run --config vitest.track-r1.config.ts
node node_modules/typescript/bin/tsc -p apps/web/tsconfig.json --noEmit
node node_modules/typescript/bin/tsc -p tsconfig.track-r1.json --noEmit
node scripts/check-web-i18n.mjs
node scripts/check-web-ui.mjs
node scripts/generate-openapi-guards.mjs --check
node node_modules/vite/bin/vite.js build --config vite.track-r1.config.ts --configLoader runner
```

أمر subset6 إذا احتاج R0 إعادته لاحقًا بعد تنسيق الموارد (ليس أمر تشغيل تلقائي):

```text
node node_modules/@playwright/test/cli.js test --config playwright.track-r1.config.ts --grep-invert "four-language|typography" --output test-results/track-r1-functional-integrated
```

Harness منفصل يستورد الصفحة الفعلية/providers ويعلن `LOCAL TEST FIXTURES · NO
REAL CHECKOUT`. خادم fixture بلا DB وبلا تحصيل، bind127.0.0.1 فقط؛ لا fixture
في production import. المنافذ3140/4190، workers1، retries0، video/trace off،
strictPort وreuseExistingServer=false. كل الخدمات والمتصفح أُغلقت عند التسليم.

بوابات باقية لدى R0 وليست محسومة هنا:

- ربط خادم/ترحيل R2 ومحرره المستقل داخل Inventory، ومراجعة العقد والحراس
  بعد الجمع الفعلي؛ لم تُنسخ تغييرات R2 إلى R1.

- قبول قارئ فعلي وطابعة ومراجعة إيصال العميل والربط التفصيلي للمستندات؛
  استرجاع دائم للمحاولة المجهولة قبل أي ادعاء تعافٍ تشغيلي كامل.

لم يحدث install/ci/prune/update أو Prisma generate أو تنزيل/حذف، ولا تعديل في
نسخة أخرى أو push/PR/merge/deploy/استضافة/رسائل عميل أو تحصيل حقيقي.
