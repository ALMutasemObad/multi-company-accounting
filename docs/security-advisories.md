# سياسة تنبيهات الاعتماديات

## مراجعة npm audit في 4 سبتمبر 2026

فُحص `package-lock.json` بـnpm 12.0.2. كانت النتيجة الأولية أربع عقد متأثرة:
عقدتان High وعقدتان Moderate. يوضح الجدول الوصول الفعلي والقرار:

| العقدة | المسار والنطاق | قابلية الاستغلال في هذا النظام | القرار |
|---|---|---|---|
| `fast-uri@3.1.5` | غير مباشر عبر `ajv` ثم Prisma CLI؛ تطوير/اختياري | أخطاء تطبيع URI قد تغيّر المضيف عند استخدام URI غير موثوق كحد أمني. لا يستورد API التشغيلي Prisma CLI ولا يمرر URI عميل إلى هذا المسار | رُفع قفل الاعتماد إلى `3.1.7`؛ يغلق النطاق `<3.1.6` |
| `qs@6.15.3` | غير مباشر عبر Express و`body-parser`؛ إنتاج | مدخل شبكي مصمم قد يتجاوز حد المصفوفة أو يسبب استهلاك موارد في محلل query/form. المسار قابل للوصول نظريًا من HTTP حتى مع بقاء حدود الجسم والمهلة دفاعًا إضافيًا | رُفع قفل الاعتماد إلى `6.16.0` واختُبر عقد Express والبناء |
| `mysql2@3.15.3` | غير مباشر وثابت داخل `prisma@7.9.1`؛ تطوير/اختياري | خفض auth plugin يحتاج خادم قاعدة خبيثًا أو اتصالًا موجّهًا إليه؛ وضغط البروتوكول غير مفعّل في إعداد التطبيق. التشغيل يستخدم `@prisma/adapter-mariadb` و`mariadb`، لا `mysql2` | مؤجل؛ `npm audit fix --force` يقترح خفض Prisma رئيسيًا إلى 6.19.3. لا يعتمد override قبل بوابتي migration على المحركين |
| `prisma@7.9.1` | Dev dependency مباشر، موسوم Moderate بسبب `mysql2` | الأثر تابع للبند السابق ولا يدخل Artifact التشغيل بعد `npm prune --omit=dev --omit=optional` | راقب إصدار Prisma يرفع `mysql2` إلى إصدار يتجاوز `3.23.0`، ثم نفذ fresh/upgrade على المحركين |

بعد الترقية: `npm audit --omit=dev --omit=optional` يعيد صفر تنبيهات، و
`npm audit --audit-level=critical` ينجح. يبقى التدقيق الكامل يعيد عقدتين
(`mysql2` High و`prisma` Moderate) في أدوات التطوير. تغلق المتابعة عندما يحدّث Prisma
تبعيته أو يثبت override متوافقًا عبر توليد العميل وfresh migration وupgrade migration
وكل اختبارات قاعدة البيانات على MariaDB 10.11 وMySQL 8.4.

## CVE-2026-40345 / GHSA-ggr8-5vv4-36mx

الحالة: مغلق في القفل الحالي عبر `overrides.deepmerge-ts=8.0.1` واختبار يمنع التراجع.

اعتمد Prisma CLI 7.9.1 بصورة غير مباشرة على إصدار متأثر من `deepmerge-ts`.
الإصدارات الأقل من 8.0.0 قد تستنفد مكدس Node عند دمج رسمين كائنيين دائريين
صُمما لهذا الغرض. يحسم override الحالي الإصدار إلى 8.0.1، ولا يستورد API التشغيلي
Prisma CLI أو `@prisma/config` ولا يستقبل إعداد Prisma من طلبات المستخدمين.

الضوابط المطبقة:

- Prisma CLI موجود في `devDependencies` ويستخدم داخل CI والترحيلات الإدارية فقط.
- تمنع CI أي تنبيه Critical في شجرة البناء.
- تُحذف اعتماديات التطوير والاعتماديات الاختيارية قبل اختبار وتشميع Artifact الإنتاج.
- تمنع CI أي تنبيه High أو Critical في شجرة التشغيل المنقاة؛ النتيجة الحالية صفر.
- لا يُشغّل `prisma.config.ts` من مدخلات أو ملفات يرفعها العميل.
- لا يُستخدم إصلاح آلي يخفض Prisma إلى إصدار رئيسي أقدم لأنه قد يكسر المخطط والمحول.

يعاد تقييم override عند ترقية Prisma لاحقًا، ولا يحذف إلا إذا بقي الإصدار المحلول
`>=8.0.0` ونجحت بوابات الاعتماديات والبناء وقواعد البيانات.

## سكربتات التثبيت المسموح بها

يحتوي `package.json` على قائمة `allowScripts` مثبتة بالإصدار لأربع حزم فقط: Argon2، ومحرك Prisma، وPrisma CLI، وesbuild. هذه السكربتات مطلوبة للبناء أو للمكوّن الأصلي الخاص بكلمات المرور، ولا يُسمح تلقائيًا لنسخة أحدث بتشغيل سكربت قبل مراجعتها وتحديث القفل والموافقة معًا.

ثُبّت مدير الحزم على `npm@12.0.2` لأن هذه السياسة وأمر فحصها جزء من npm 12. تثبّت CI الإصدار نفسه قبل `npm ci`، ثم تفشل إذا أعاد `npm install-scripts ls --json` أي سكربت تثبيت غير موجود في القائمة المعتمدة.

## المراقبة الدورية

لا يقتصر اكتشاف التنبيهات الجديدة على وجود Push أو Pull Request. يشغّل
`dependency-security-monitor.yml` يوميًا على `main`، ويمكن تشغيله يدويًا، ويعيد بناء
شجرة `package-lock.json` المثبتة ثم:

1. يفشل عند ظهور سكربت تثبيت غير معتمد.
2. يمنع أي تنبيه Critical في شجرة البناء الكاملة.
3. يحذف اعتماديات التطوير والاختيارية.
4. يمنع أي تنبيه High أو Critical في شجرة الإنتاج المنقاة.

يعمل الـWorkflow بصلاحية `contents: read` فقط، ولا يقرأ أسرارًا ولا يرفع Artifacts.
كما تقيد إعدادات المستودع التنفيذ بإجراءات GitHub-owned المثبتة ببصمة SHA كاملة.
