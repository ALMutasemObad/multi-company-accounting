# إطلاق الوحدات الثلاث لجميع الشركات

## المشكلة

نجاح دمج ونشر الكود لا يفعّل الوحدات تلقائيًا: ترحيلات الإضافة أنشأتها غير نشطة،
كما أن نسخ الخطط المنشورة غير قابلة للتعديل ولا تنتقل نسختها الجديدة تلقائيًا إلى
اشتراكات الشركات القائمة. لذلك لم تظهر الوحدات في التنقل بعد النشر الأول.

## القرار

إطلاق `إدارة المشاريع` العامة (`GENERAL_PROJECTS`) و`إدارة الخدمات`
(`SERVICE_CATALOG`) ومسير الرواتب المحدود (`PAYROLL`) كمنح منصة مجانية عامة
للشركات ذات الاشتراك، الحالية والجديدة، عبر إسقاط الاستحقاق الفعّال. لا يُعدل هذا
المسار أي نسخة خطة أو رسوم أو حصص أو وحدة أخرى، ولا يكتب استحقاقات بأثر رجعي في
سجل اشتراك كل شركة.

تظل صلاحيات RBAC وسياسة خصوصية الرواتب حاجزين مستقلين. وتُحل اعتماديات كل وحدة
قبل عرضها: إدارة المشاريع والرواتب تتطلبان الموارد البشرية، والرواتب تتطلب كذلك
الموافقات. إذا غابت متطلبات شركة ما، تفشل الإتاحة لهذه الوحدة مغلقًا بدل تجاوز
الاعتمادية. كتالوج الخدمات مستقل عن إدارة المشاريع.

## التنفيذ

- يفعّل ترحيل المنصة الوحدات الثلاث فقط.
- يضيف الترحيل كذلك تعريفات صلاحيات كتالوج الخدمات المفقودة إلى أدوار
  `ADMINISTRATOR` القائمة؛ تهيئة الشركات الجديدة كانت تضيفها مسبقًا، أما الشركات
  الموجودة فلم يكن لها ترحيل مماثل، ولذلك كانت واجهة الكتالوج مخفية حتى مع تفعيل الوحدة.
- تضيف سياسة منصة صريحة قائمة الأكواد المجانية الثلاثة إلى قراءة الاستحقاقات
  الفعّالة لكل شركة ذات اشتراك، مع فحص التفعيل واعتماديات Prisma.
- تستخدم الشركة الجديدة القراءة نفسها فور إنشاء اشتراكها؛ لا تتغير باقة البداية
  أو سجل استحقاقاتها.
- لا يمس التراجع بيانات المشاريع أو الخدمات أو الرواتب؛ يعطل الإتاحة فقط.

## القبول

يجب اجتياز اختبارات السياسة وقراءة الاستحقاقات واختبارات قاعدة البيانات والترحيل
والعزل، ثم التحقق على Staging من ظهور القوائم الثلاث لحساب يملك الصلاحيات، ومن
بقاء تفاصيل راتب الموظف للمالك فقط. لا يعد نجاح CI أو `/ready` وحده إثباتًا
لظهور الواجهة أو تشغيل المسار، ولا يثبت Staging أن Production نُشر.

## الحالة

قيد التنفيذ. نشر الكود السابق أثبت سلامة الخدمة لكنه لم يثبت تفعيل الوحدات أو ظهور
القوائم؛ لا يُعدّ الإطلاق الوظيفي مكتملًا حتى اجتياز اختبارات الترحيل والتحقق الحي.
يحمل الترحيل رقم `20261009000000` حتى يأتي بعد أحدث ترحيل موجود (`20261008030000`)
ولا يصل إلى قاعدة الاستضافة بأثر رجعي.

## التحقق المحلي

- اختبارات API المركزة: 51 ناجحًا، واختبار قاعدة بيانات واحد متجاوز لعدم توفر
  MySQL محليًا.
- اختبارات تنقل الواجهة: 10 ناجحة.
- `npm run typecheck --workspace @mcap/api`: ناجح.
- لم تُشغّل بعد اختبارات MariaDB/MySQL أو تحقق قائمة التنقل على Staging؛ يلزم
  نجاح CI واتصال المتصفح قبل اعتبار الإطلاق الوظيفي مكتملًا.
