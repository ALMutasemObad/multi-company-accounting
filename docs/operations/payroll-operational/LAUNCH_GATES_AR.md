# مسير الرواتب — بوابات التشغيل في السعودية

التاريخ: 2026-10-05. الحالة: قرار نطاق وخصوصية من المالك مع تنفيذ محلي أولي، وليس اعتمادًا قانونيًا أو إذنًا لتفعيل الرواتب أو تحويل الأموال.

## ما نملكه الآن

تحديث 5 أكتوبر 2026: أصبحت الشريحة المحلية تحفظ اتفاقيات الأجر المؤرخة والدورات ولقطات الحساب وتاريخها مشفرة، مع API وواجهة «مسير الرواتب» واعتماد فعلي عبر محرك الموافقات. نجحت دورة متصفح متصلة بقاعدة MariaDB بحسابي المالك والمُعد: اتفاقية، إنشاء شهر، احتساب، إرسال، اعتماد، وحجب المبالغ عن المُعد. لا تزال هذه نتيجة محلية، وليست نشرًا أو اعتمادًا للسياسة. لا قيد محاسبي أو دفع أو ملف مدد.

تُحجب المجاميع أيضًا عن المُعد: مجموع دورة بموظف واحد يكشف راتبه. يرى الحالة والعدد فقط. لا يُخزّن نص حر لرفض الرواتب في صندوق الموافقات العام؛ يُسجّل سبب عام، وتبقى لقطات الحساب السابقة مشفرة حتى بعد الرفض وإعادة الحساب.

التشغيل المحلي يحتاج `PAYROLL_ENABLED=true` و`PAYROLL_KEY_RING` (قاموس مفاتيح Base64، كل مفتاح 32 بايت) و`PAYROLL_ACTIVE_KEY_ID` و`PAYROLL_FINGERPRINT_KEY_ID`. مفاتيح الاختبار لا تستخدم خارج قاعدة الاختبار. يجب ثبات مفتاح بصمة الأوامر أثناء تدوير مفتاح التشفير، والاحتفاظ بمفاتيح قراءة اللقطات القديمة. في الإنتاج يشترط الخادم `PAYROLL_POLICY_REVIEWED=true`؛ لا يجوز تعيينه قبل مراجعة فعلية. الوحدة تُرحّل معطّلة ولا تُمنح استحقاقًا تلقائيًا.

## حدود شريحة التشغيل الآمنة

### إجراء استعادة المفتاح قبل التفعيل

هذا إجراء تشغيل مطلوب، وليس شهادة بأن نسخة الإنتاج احتُفظ بها أو استُعيدت:

1. يحفظ المسؤول نسخة مشفرة من حلقة المفاتيح خارج قاعدة البيانات، بصلاحية مستقلة وسجل وصول؛ لا توضع المفاتيح في Git أو دليل الاختبار أو المحادثة. تسجل معرفات المفاتيح ومَن يملك استعادتها دون قيمها.
2. تُستعاد نسخة قاعدة اختبار معزولة ومعها المفاتيح المعتمدة من مخزن الأسرار. لا تُفعّل الوحدة للمستخدمين ولا يُغيّر العلم `PAYROLL_POLICY_REVIEWED` لإجراء التجربة.
3. يثبت المسؤول فك لقطة تاريخية بمالك مخوّل، ورفض قراءتها دون المفتاح أو بمفتاح بديل يحمل المعرف نفسه، وبقاء التفاصيل محجوبة عن المُعد. بعد تدوير المفتاح النشط تبقى قراءة اللقطات القديمة ممكنة؛ لا يُحذف مفتاح قديم لمجرد تغيير المفتاح النشط.
4. يُحتفظ بمفتاح بصمة الأوامر نفسه كي لا تتغير نتيجة إعادة أمر معلق. تدويره يحتاج إجراء مستقل؛ لا يُعامل كتدوير مفتاح التشفير النشط.
5. يسجل تاريخ التجربة ونسخة التطبيق ونتائجها وهوية المسؤول وموقع النسخة الاحتياطية المعتمد، دون بيانات موظفين أو أسرار. لا تُغلق بوابة الاستعادة إلا بتجربة بيئة النشر الفعلية.

تحقق محلي 2026-10-05: اختبار مصطنع أثبت رفض المفتاح المفقود أو المستبدل، ثم نجاح استعادة الغلاف بالمفتاح الأصلي وثبات بصمة الأمر. واختبار مستقل أثبت ثبات بصمة اللقطة عند إعادة ترتيب خصائص JSON وتغيرها عند العبث بالنص المشفر. لا تعادل هذه الاختبارات استعادة قاعدة إنتاج أو اعتماد المختص.

### الحدود الوظيفية

1. تبدأ الشريحة بعقود أجر ثابتة مؤرخة ومدخلات استحقاق موجبة فقط، بعملة الشركة، وفترة كاملة غير مجزأة. أي فترة توظيف جزئية أو إنهاء أثناء الدورة أو تعديل أجر بأثر رجعي يوقف الحساب ويحتاج معالجة بشرية موثقة؛ لا يُخترع يوم عمل أو قاعدة تقسيم.
2. تُحظر الاستقطاعات، السلف، الغرامات، التأمينات، الضرائب، الغياب، التأخير، الساعات الإضافية ومكافأة نهاية الخدمة الآلية حتى تُعتمد سياسة سعودية مؤرخة وتصنيف دليل الإثبات لكل حالة. لا تتحول نقاط التحفيز أو بصمة الحضور مباشرة إلى مبلغ راتب. يوضح نظام العمل السعودي قيود الحسم والموافقة الخطية والاستثناءات؛ مجرد إدخال مبلغ يدوي لا يثبت مشروعيته. المصدر: [وزارة الموارد البشرية — شروط العمل وظروفه](https://www.hrsd.gov.sa/%D8%B4%D8%B1%D9%88%D8%B7-%D8%A7%D9%84%D8%B9%D9%85%D9%84-%D9%88%D8%B8%D8%B1%D9%88%D9%81%D9%87).
3. نسبة التأمين الاجتماعي لا تُثبّت في الكود؛ انطباق النظام الجديد يتغير بحسب سجل اشتراك الشخص وتاريخ السريان. لا تُحسب تلقائيًا في هذه الشريحة. المصدر: [التأمينات الاجتماعية — المشمولون بالنظام الجديد](https://awareness.gosi.gov.sa/businessJourney.html).
4. الاعتماد يفصل منشئ المسير عن معتمده. لا يعني الاعتماد الصرف، ولا يعني القيد المحاسبي وصول المبلغ للموظف. لا يُنشأ ملف حماية أجور أو تحويل بنكي في هذه الشريحة؛ خدمة رفع الملف لها متطلبات ومطابقة مستقلة. المصدر: [وزارة الموارد البشرية — رفع ملف حماية الأجور](https://www.hrsd.gov.sa/ministry-services/services/%D8%B1%D9%81%D8%B9-%D9%85%D9%84%D9%81-%D8%AD%D9%85%D8%A7%D9%8A%D8%A9-%D8%A7%D9%84%D8%A3%D8%AC%D9%88%D8%B1).
5. تظل بيانات الأجر منفصلة عن بيانات HR غير المالية وعن صندوق الموافقات العام. لا تُكتب الرواتب في السجلات أو Telemetry أو سجل التدقيق العام، ولا يُتاح تنزيل CSV أو PDF أو حفظ نسخة في المتصفح في المرحلة الأولى.

## قرار المالك في 5 أكتوبر 2026

- تفاصيل أجر كل موظف للمالك وحده. المُعدّ المخوّل يشاهد الحالة وعدد الموظفين فقط، ولا يحصل على قائمة أفراد أو أسطر الأجر أو مجاميع تسمح باستنتاج أجر فرد. المالك يدير اتفاقات الأجر ويعتمد دورة أعدها شخص آخر؛ لا يعتمد أحد دورة أعدها بنفسه. الحجب في الخادم، وليس إخفاء أعمدة في الواجهة فحسب.
- الإصدار الأول للاستحقاقات الثابتة فقط، دون خصومات أو تحويلات بنكية أو ملف «مدد». نواة الحساب العامة قادرة على تمثيل الخصومات، لكن مدخل التشغيل المحافظ يرفضها صراحةً حتى سياسة مستقلة لاحقة.
- وافق المالك مبدئيًا على تشفير مبالغ الأجور في قاعدة البيانات بمفاتيح خارجها واحتفاظ مقترح لعشر سنوات. هذا ليس اعتمادًا نهائيًا لمدة الاحتفاظ أو آلية المفتاح؛ يشترط مراجعة مختص قبل إطلاق مخزن الرواتب أو النشر.
- أضيفت محليًا بوابة حساب ترفض فترة توظيف أو اتفاق أجر لا يغطيان كامل الدورة، وترفض الخصم، وتنتج ملخصًا لا يحوي معرفات الموظفين أو أسطرهم. أضيفت قواعد انتقال الدورة التي تشترط بصمة اللقطة والنسخة وتمنع اعتماد المُعدّ لدورته أو اعتماد غير المالك. نجحت 24 حالة اختبار مع فحص أنواع API؛ هذه قواعد مجال فقط، لا تخزين ولا API ولا واجهة ولا موافقة فعلية أو ترحيل بعد.
- أضيف غلاف تشفير تجريبي `AES-256-GCM` لمبلغ السطر الفردي بمفتاح يُمرره مالك خارجي، وبيانات تحقق مرتبطة بالشركة والموظف والسطر والحقل والنسخة؛ تفشل القراءة عند تبديل القيمة عبر أي منها أو تغيير المفتاح. لا ينشئ الغلاف مخزن مفاتيح أو سياسة تدوير/استرداد أو ترحيل قاعدة، ولا يكفي وحده لحماية بقية بيانات الموظف.
- بعد الإضافة نجح فحص أنواع API المصدر والاختبارات، و27 اختبارًا موجّهًا للرواتب، وحزمة API المحلية كاملة: 1655 ناجحًا و219 متجاوزًا من 1874. الاختبارات المتجاوزة، ومنها ما يتطلب قاعدة مفعلة، ليست دليل قبول للرواتب التشغيلية.

## قرارات قبل ترحيل قاعدة الرواتب أو عرضها

الفقرات التاريخية أعلاه التي تصف النواة وحدها سبقت تنفيذ الشريحة المحلية. الترحيلات الأربعة الجديدة اختُبرت على قاعدة معزولة فقط. المتبقي للإطلاق: مراجعة المختص المطلوبة من المالك، سياسة المفاتيح والنسخ الاحتياطية والاستعادة، قبول الاختبارات الشاملة وخطة التفعيل للمسارات الثلاثة معًا. الربط المحاسبي والمدفوعات خارج إصدار الاستحقاقات المحدود المعتمد.

- اعتماد مالك سياسة الرواتب السعودية ومراجعة دورية مؤرخة للقواعد؛ هذا المستند لا يحل محل رأي مختص موارد بشرية/نظام عمل.
- تنفيذ قرار المالك أعلاه بصلاحيات مستقلة وحد خادم ينقح رد المُعدّ؛ لا تكفي صلاحية HR أو الموافقات العامة وحدها.
- تحويل الموافقة المبدئية إلى سياسة مكتوبة ومراجَعة للتشفير والنسخ الاحتياطية والاحتفاظ والحذف والتصدير واسترداد المفتاح. هذه بيانات مالية شخصية، ولا يجوز إطلاق مخزنها قبل مراجعة مختص.
- اعتماد ملف حسابات الأجور والالتزامات والصافي وترتيب أقفال الترحيل مع `PostingEngine`؛ يجب إثبات دقة العملات حتى ثماني منازل عبر المسار المحاسبي.
- تحديد التعامل مع فترة جزئية، وعودة المسير المرفوض، والتصحيح بعد الاعتماد، والفروقات، وتاريخ الاستحقاق. حتى ذلك الحين يرفض النظام تلك الحالات بدل تقديرها.
- اختيار هل النقل إلى البنك/«مدد» مطلوب في إصدار لاحق؛ ليس لازمًا لحساب ومراجعة المسير، ويحتاج قرارًا وعقدًا منفصلين.

## بوابة القبول الدنيا

لا تُسمى الميزة تشغيلية ولا تُنشر حتى توجد: ADR مقبول، سياسة خصوصية نافذة، ترحيل آمن مع حارس رجوع، صلاحيات مستقلة، واجهة محدودة، عزل شركتين، اختبار تزامن وإعادة طلب، موافقة Maker/Checker، واختبار دورة فعلية على قاعدة ومتصفح مع توثيق عدم وجود دفع أو خصم آلي. انظر التصميم التفصيلي في `docs/architecture/PAYROLL_FOUNDATION_SLICE_AR.md`؛ هو مقترح لا إعلان إنجاز.
