# GPM-1 — سجل إدارة المشاريع العامة

الحالة: مرشح محلي غير مدمج وغير منشور. لا تفعيل للوحدة في الترحيل (`GENERAL_PROJECTS.is_active = FALSE`) ولا استحقاق ضمن باقات قائمة؛ يلزم اختبار قاعدة بيانات معزولة وقرار تفعيل مستقل قبل إتاحتها للمستخدمين. لا يمنح هذا المستند إذن دفع أو دمج أو نشر.

## ما نُفذ

- نموذج `GeneralProject` و`GeneralProjectMember` مستقل للشركة، وقيود مركبة تمنع وصل عميل أو موظف أو عضو من شركة أخرى، وترحيل إضافي لا يمس بيانات `professional_*`.
- رقم `GPR-######` من تسلسل مشترك محكوم بالمعاملة، وعميل اختياري، ومدير أول من موظفي الموارد البشرية النشطين، وإسناد أعضاء وتاريخ إلغائهم.
- قائمة وبحث وحقل حالة/أولوية ونطاق `MINE`، تفصيل المشروع وأعضائه، إنشاء/تعديل/انتقال الحالة وإسناد/إلغاء إسناد، مع `version` و`Idempotency-Key` لجميع أوامر الكتابة وAudit append.
- صلاحيتا `general_projects.view/manage` ووحدة اشتراك منفصلة عن `PROFESSIONAL_PROJECTS`. واجهة `#generalProjects` تعرض «إدارة المشاريع» فقط عند وجود الوحدة والصلاحية.
- قائمة خيارات جميع العملاء تتطلب `customers.view` من Sales؛ عند غيابها يبقى إنشاء مشروع بلا عميل متاحًا، ولا تكشف واجهة الخيارات كتالوج العملاء الكامل.
- سياسة انتقالات المشروع العامة منفصلة عن خطة المراحل/المهام المؤجلة لـGPM-2؛ إكمال مشروع بلا مراحل/مهام موجودة مقبول في GPM-1 فقط. لا توجد فوترة أو قضايا أو ربط بالمهنة في هذا السجل.

## ما تم اختباره محليًا

- `prisma validate` و`prisma:generate` نجحا على Schema الجديد؛ لم يتصل الأمر بقاعدة بيانات فعلية.
- `typecheck` لواجهتي API وWeb و`build` للواجهة نجحت.
- `contracts:check` نجح، و`check-web-i18n.mjs` نجح للغات الأربع، و`architecture-boundaries.mjs` أبلغ صفر انتهاكات.
- اختبارات API الشاملة بعد تصحيح فحص الوحدة وتكافؤ المسارات: 1588 ناجحة و208 متجاوزة بشرط البيئة، بلا إخفاق. بعد حصر صلاحيات قائمتَي العملاء/الموظفين وإعادة توليد الحراس، نجحت 42 حالة API موجهة و`typecheck`؛ لم تُعد الحزمة الشاملة بعد هذا التعديل الصغير. اختبارا تنقل Web نجحا. 3 اختبارات تكامل السجل ضمن المتجاوزة لأنها تتطلب `RUN_DB_TESTS=true` و`DATABASE_URL`.

## المتبقي قبل التفعيل

1. تشغيل الترحيل واختبارات التكامل الثلاثة على MySQL/MariaDB معزولة، بما في ذلك التراجع الآمن، ثم تشغيل فحص الاستجابة والعزل عبر HTTP. لا تتوفر خدمة MySQL محلية أو `DATABASE_URL` في الجلسة الحالية.
2. مراجعة UX في متصفح محلي على قاعدة اختبار حقيقية، ثم معالجة السباقات/الأخطاء المكتشفة. فحص `typecheck` لا يثبت جودة التفاعل المرئي.
3. فصل واجهة «إدارة الخدمات المهنية» ككتالوج أصناف/خدمات في مهمة Service Catalog مستقلة. شاشة `professionalProjects` الموروثة موجودة في `main` ولم تُنقل بياناتها أو تُحذف ضمن GPM-1.
4. تنفيذ GPM-2 للمراحل والمهام والاعتماديات، وربط شرط إكمال المشروع بحقائقها قبل تفعيلها.
5. طلب إذن جديد لأي push/PR/دمج/نشر. نجاح محلي لا يعني وصول التغيير إلى Staging أو الإنتاج.

تسلسل الرجوع: احتفظ بالوحدة معطلة، ولا تنفذ `rollback.sql` إلا إذا أثبت الفحص عدم وجود مشاريع أو أعضاء أو سجلات إعادة أو استحقاقات؛ وإلا عالج بترحيل تصحيحي دون حذف البيانات.
