# SC-1A — كتالوج الخدمات المستقل (عمل جارٍ)

## المنفذ محليًا

- أُضيف نموذج التصنيفات والعروض وبدائل الخدمة، مع مفاتيح شركة مركبة للروابط الاختيارية والفهرسة، دون روابط إلى مشروع أو عميل أو فاتورة أو صنف مخزون.
- ترحيل توسعي للجداول الثلاثة فقط؛ لا ينشط `SERVICE_CATALOG` ولا يمنح استحقاقًا لأي شركة. التراجع التشغيلي يحتفظ بالبيانات.
- سياسة دورة الحالة ونافذة التوفر النصف مفتوحة وقفل وحدة التسعير بعد أول تنشيط. عولجت حالة البداية المفتوحة (`availableFrom = null`) بحيث لا يعاد تفسير ماضيها بعد التنشيط.
- حجز رمز `SVC-######` من تسلسل الشركة، وتعريف صلاحيات `services.*` وعزلها عن `sales_catalog.*` وعن صلاحيات المشاريع؛ تبقى غير فعالة دون استحقاق الوحدة.
- نُفذ مسار API للتصنيفات فقط: قائمة محدودة وتفاصيل وإنشاء وتعديل وانتقال حالة؛ أوامر الكتابة مع CSRF والصلاحية ومفتاح إعادة المحاولة والنسخة والتدقيق في المعاملة. عقد OpenAPI مولّد ومطابق للمسارات.
- أُضيفت قائمة وتفاصيل وإنشاء وتعديل عروض الخدمة برمز خادمي، مع إسناد تصنيف نشط من الشركة نفسها. مسارات الإدارة تتطلب `services.manage`؛ تبقى `services.view` لاختيار الخدمة المنقح لاحقًا، لا لقراءة التصنيفات المتقاعدة أو المسودات.
- راجعت الملاحظة الأمنية المستقلة: أضيفت نسختا السجل وأسماء الحقول المتغيرة المنقحة إلى التدقيق، وقُصرت قراءات الإدارة على صلاحية الإدارة. ويقفل إسناد التصنيف صفه لئلا يتقاعد أثناء الإنشاء.
- أُضيفت بدائل الخدمة: قائمة محدودة، إنشاء وتعديل، وانتقال حالة. يقفل الأمر العرض الأب، ويثبت وقت أول تنشيط، ويمنع تغيير وحدة التسعير بعده أو إعادة كتابة توفر ماضٍ وفق تاريخ الشركة المحلي. تنشيط العرض يتطلب بديلًا غير متقاعد.
- أُضيفت صفحة مستقلة `#services` بعنوان «إدارة الخدمات» لعرض تصنيفات وعروض وبدائل أي نوع من الخدمات وإنشائها وتغيير حالتها، منفصلة عن صفحة المشاريع وكتالوج المخزون. تبقى مخفية ما لم توجد صلاحية `services.manage` واستحقاق `SERVICE_CATALOG` الصريح، والوحدة لا تزال غير نشطة.
- أصبحت مراجع حساب الإيراد وضريبة المخرجات الافتراضية اختيارية في أوامر إنشاء البديل وتعديله. يفحص محوّلا Accounting وTax الجاهزية داخل الشركة في المعاملة نفسها؛ حساب الإيراد يجب أن يكون نشطًا، قابلًا للترحيل، من فئة `REVENUE` وورقة شجرية، والضريبة تخضع لسياسة `OUTPUT` لدى مالكها. الرفض 422، و`null` يمسح المرجع، وغياب الحقل في PATCH يبقيه، والتدقيق يسجل أسماء الحقول المتغيرة.
- أُضيف تعديل الأسماء والتصنيف والتوفر من واجهة الإدارة مع `expectedVersion`. يمكن البحث في التصنيفات النشطة عند اختيار تصنيف للعرض حتى لو لم تكن في صفحة قائمة التصنيفات؛ يحتفظ التعديل بالتصنيف السابق دون إعادة التحقق منه إذا لم يتغير.
- أُضيف اختيار حساب الإيراد وضريبة المخرجات في نموذج بديل الخدمة. يقرأ مسارا `reference-options` الجديدان قوائم مؤهلة ومحدودة من محوّلي Accounting وTax المالكين، ويكتفيان بصلاحية `services.manage` في الشركة بدل كشف قوائم الحسابات أو فواتير المبيعات الأوسع. لا يغيّر نص البحث المرجع المحدد، ولا يرسَل تغيير أو مسح إلا بعد توفر الخيارات واختيار صريح؛ يتحقق الخادم من الجاهزية مجددًا داخل معاملة الكتابة.
- أُضيف `GET /service-catalog/selection-options` بصلاحية `services.view`: يعيد بدائل الخدمات النشطة ذات العرض النشط داخل الشركة فقط، مع نافذة توفر نصف مفتوحة بحسب تاريخ الشركة المحلي، وبحث وترقيم محدودين. الاستجابة منقحة ولا تكشف المسودات أو مراجع الحساب والضريبة؛ لا تعني ربط الخدمات بمشروع أو فاتورة.
- أصبحت شاشة إدارة الخدمات تتيح تحرير وصف التصنيف والعرض الاختياري وعرضه في القائمة، من قواميس اللغات الأربع؛ حدود الوصف 1000 حرف مطابقة للعقد.

## الأدلة والحدود

- Prisma validate وPrisma Client generate: ناجحان باستخدام عنوان قاعدة شكلي للتحقق فقط، دون اتصال فعلي.
- اختبارات API المركزة بعد إضافة المراجع: 47 ناجحة في ستة ملفات (العقد المولّد، تطابق المسارات، HTTP، السياسة، المخطط، محولات المراجع)؛ اختبارات الاستحقاق كانت ناجحة في الجولة السابقة ولم تُعد ضمن هذا العدد. فحص أنواع API وWeb: ناجحان في جولاتهما، وأعيد فحص API الآن. `contracts:check`: ناجح.
- اختبارات التنقل/الاستحقاق للواجهة: 11 ناجحة؛ `i18n:check` و`ui:check` وبناء Web: ناجحة. لا فحص بصري في متصفح حقيقي.
- بعد تعديل الواجهة: فحص أنواع API وWeb، بناء API وWeb، `architecture-debt:check`، و`i18n:check` و`ui:check` ناجحة. اختبار محولات المراجع 3/3، واختبارات الواجهة المركزة 11/11. لا يُعد ذلك بديلًا عن اختبار قاعدة أو متصفح.
- بعد إضافة اختيارات المراجع: نجح اختبار الواجهة الموجّه 8/8، وفحص أنواع Web و`i18n:check` و`ui:check` والبناء، ثم 841 اختبار Web ناجحًا و35 متجاوزًا. لم تُختبر رحلة الاختيار متصلة بقاعدة حقيقية.
- بعد نقل القراءة إلى مسارين منقّحين: نجحت 47 حالة API موجهة في خمسة ملفات، وفحص أنواع مصدر API واختباراته و`contracts:check` (426 عملية و213 جسم طلب و2750 جسم استجابة) وفحص حدود المعمارية بلا مخالفة أو تحذير. نجحت 841 حالة Web و35 متجاوزة، مع فحص الأنواع والبناء والترجمة والواجهة. لم يجر اختبار قاعدة أو متصفح متصل.
- بعد إضافة خيارات اختيار الخدمات: نجحت 41 حالة API مركزة في ملفات المسار والعقد وتطابق المسارات، مع فحص أنواع المصدر والاختبارات و`contracts:check` (427 عملية و213 جسم طلب و2754 جسم استجابة). تحقق اختبار وحدة من تاريخ `Asia/Riyadh` وحدود استعلام التوفر والعزل، لكنه استخدم Prisma مُحاكى لا قاعدة حقيقية. نجح فحص حدود المعمارية؛ لا اختبار DB أو متصفح.
- بدأت حزمة API الكاملة لكن اختبار جرد OpenAPI فشل أولًا بسبب عدد العمليات القديم؛ عُدّل ثم نجحت الحزمة المركزة. التشغيل الشامل لم يتقدم بعد ذلك وتوقف يدويًا؛ لا يُسجّل نجاحًا شاملًا.
- لم يشغّل الترحيل أو اختبار تكامل على MySQL/MariaDB؛ لا خدمة على المنفذ المحلي 3306 وقت الفحص.
- API التصنيفات والعروض والبدائل ومراجعها الاختيارية موجود، ومعه مسارا خيارات الحساب والضريبة المنقحان. لم تُختبر هذه المسارات على قاعدة ومتصفح حقيقيين، ولا CI، ولا PR، ولا نشر. هذا ليس نظام كتالوج مكتملًا.

## المتبقي ضمن الشريحة

1. تجربة `selection-options` ومساري المراجع على قاعدة حقيقية مع بيانات مسودة/غير نشطة وحدود التوفر وعزل الشركات؛ التنفيذ المحلي لا يكفي لإثبات استعلام MariaDB.
2. QA RTL/LTR والهاتف ولوحة المفاتيح على رحلة متصلة؛ اختبار احتفاظ النموذج بالمراجع عند البحث وتعذر تحميل الخيارات.
3. اختبارات تكامل على MySQL/MariaDB لقواعد العزل والتزامن والتراجع ثم فحص متصفح قبل أي قرار تفعيل.

دفاتر الأسعار والتسعير المؤرخ `SC-1B` خارج هذه الشريحة، ولا تُربط الخدمة بالمشاريع العامة.
