# مرشح محلي: تتبع إخفاق إنشاء شركة المجموعة

## المنجز

بُني هذا المرشح من `origin/main` عند `381dfde` وجمع فحص أهلية عملة خطة البداية وتشخيص إخفاقات `503` الآمن واختبارات HTTP، ثم سد فجوة معرّف الطلب بين الخادم والعقد والواجهة. تلتقط الواجهة `X-Request-ID` الآمن من الاستجابة، أو `requestId` من جسم الخطأ عند غياب الترويسة، وتعرضه بجانب رسالة تعذر تحميل خيارات الشركة أو إنشائها. يُزال الرقم عند إعادة المحاولة أو نجاح الطلب أو بدء شركة أخرى. لا تُعرض للمالك أسباب الخادم الداخلية أو بيانات حساسة، ولا تتغير سياسة مفتاح التكرار.

صار عقد OpenAPI يقبل معرّفات الطلب الآمنة المسموح بها في `requestLogger`، ومنها UUID، بطول 8–128 حرفًا من الحروف الإنجليزية والأرقام والنقطة والشرطة والشرطة السفلية. الحراس المولدة محدثة، ورسائل الواجهة مترجمة في العربية والإنجليزية والأردية والهندية.

## دليل التحقق المحلي

- `111` اختبار API مركز ناجح في الفحص دون قاعدة. تشمل رفض معرف غير آمن، وفحص خيارات العملة، وتسجيل `503` دون اسم الشركة أو رقم هاتفها أو جسم الطلب. يثبت اختبار HTTP بمنافذ مُحاكية أن مجموعة القيم المصوّرة تقبلها الخدمة إذا كانت باقة البداية بعملة `AED`، وتصدر `503` وسبب `PLAN_NOT_ELIGIBLE` إذا كانت بعملة `SAR`.
- أُنشئت قاعدة اختبار جديدة ومعزولة على `E:` وشُغّلت عليها الهجرات الـ`86` كلها ثم نجحت `11/11` حالة تكامل لإنشاء شركة المجموعة على MariaDB `10.4.32`. الحالة الجديدة تستخدم `YE` و`AED` و`Asia/Riyadh` ونشاط التصنيع وقالب الخدمات مع قاعدة فعلية: تفشل بباقة `SAR`، ولا تترك شركة أو سجل تكرار بعد rollback، ثم تنجح بالمفتاح نفسه وباقة `AED` وتنتج ملف الشركة والاشتراك الصحيحين. هذه نسخة أقدم من نسختي MariaDB `10.11` وMySQL `8.4` المستهدفتين؛ لا تحل محلهما.
- `5` اختبارات وحدة لعميل API و`8` حالات متصفح مُحاكية لتأسيس الشركة ناجحة، بما فيها إظهار رقم التتبع وإزالته عند إعادة المحاولة.
- حزمة الواجهة العامة: `834` ناجحة و`35` متجاوزة. نجح فحص أنواع API والواجهة وبناؤهما، و`contracts:check` و`i18n:check`.
- لم يُشغّل CI بعيد أو تحقق على البيئة التي أنتجت صورة البلاغ؛ بيانات الشركات والاشتراكات الناتجة اصطناعية داخل قاعدة الاختبار المعزولة فقط. لم تُختبر النسختان المستهدفتان لقاعدة البيانات.

## حدّ النتيجة والخطوة التالية

هذا تحسين تشخيص وتجربة إخفاق ومنع اختيار عملة لا تقبلها باقة البداية، مع إثبات محلي للرجوع وإعادة المحاولة بالقيم المصوّرة. لا يثبت سبب الخطأ في الخادم ولا إصلاحه هناك؛ يبقى البلاغ P0 مفتوحًا. يحتاج مسؤول البيئة إلى ربط المحاولة المصوّرة أو سجل محفوظ بمعرّف طلبها بقراءة مخوّلة، والتحقق هل `PLATFORM_SUBSCRIPTION_START_PLAN_VERSION_ID` مهيأ وما عملة إصداره وحالته. إن كان الإعداد غائبًا أو غير مؤهل فلا يكفي إصلاح الواجهة: يلزم قرار تجاري/تشغيلي لإصدار بداية معتمد بدل اختراع خطة أو تسعير ضمن الكود. لا يُغيَّر كتالوج أو خطة حية ولا تُكرَّر محاولة حيّة بمفتاح جديد استنادًا إلى التخمين.

المرشح محلي وغير مدمج؛ لم يحدث push أو PR أو نشر، ولا ينقل نجاح Staging سابقًا إلى هذا التغيير.
