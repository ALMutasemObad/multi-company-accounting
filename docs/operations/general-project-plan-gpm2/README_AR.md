# إدارة المشاريع — شريحة الخطة GPM-2

## المنفذ محليًا حتى الآن

- أضيفت جداول مستقلة للمراحل والمهام وإسنادات أعضاء المشروع، مع مفاتيح مركبة تمنع ربط مهمة بمرحلة أو عضو من مشروع أو شركة أخرى، ونسخ لكل سجل وترتيب داخل المرحلة/المشروع.
- أضيفت صلاحية `general_projects.progress` دون تفعيل وحدة `GENERAL_PROJECTS` أو منحها اشتراكًا. ترحيل التراجع يرفض إسقاط الجداول إذا وجدت بيانات أو سجلات إعادة لأوامر الخطة.
- أصبح أمر إكمال المشروع يقرأ حالات المراحل والمهام الفعلية داخل المعاملة، ويرفض الإكمال إذا بقي أي عمل مفتوح. كانت شريحة السجل السابقة تمرر قائمتين فارغتين لأنها لم تكن تملك جداول خطة.
- أضيفت قراءة المراحل وإنشاؤها وتغيير حالتها بعقد OpenAPI وحراسة صلاحية الإدارة وCSRF ومفتاح إعادة المحاولة ونسخة الخطة ونسخة المرحلة. يظهر ذلك في صفحة «إدارة المشاريع» مع مفاتيح ترجمة في القواميس الأربع.
- حُرست حدود تواريخ المرحلة داخل حدود المشروع، ويُرفض تضييق حدود المشروع إذا أصبحت مرحلة موجودة خارجه. نُقل ترحيل الخطة إلى اسم يرتّب تنفيذه بعد ترحيل سجل المشاريع الذي يعتمد عليه.

## دليل التحقق وحدوده

- نجح `prisma validate` وتوليد Prisma Client باستخدام عنوان قاعدة شكلي بلا اتصال فعلي، وفحص أنواع API واختباراته.
- أضيف اختبار تكامل لإكمال المشروع مع مهمة ومرحلة مفتوحتين؛ لم يُشغّل لأن MySQL/MariaDB المحلي غير متاح على `127.0.0.1:3306`.
- نجحت 103 حالات موجهة للعقد والسياسة والملاحة والحدود HTTP. نجحت حزمة API الكاملة بـ1619 اختبارًا مع 210 متجاوزة، وحزمة الواجهة من إعدادها الصحيح بـ841 اختبارًا مع 35 متجاوزة. نجح فحص أنواع API والواجهة وفحص القواميس الأربع وتوليد العقد. أُضيف اختبار تكامل للمراحل والتزامن والعزل والتواريخ لكنه لم يُشغّل لغياب قاعدة محلية على `127.0.0.1:3306`.
- لم تنفذ بعد أوامر إدارة المهام والإسنادات واعتماديات GPM-3 أو واجهتها. لذلك فهذه شريحة مراحل غير مفعلة أو منشورة، وليست نظام تخطيط مكتملًا.

## البوابة التالية

تنفيذ API المهام وإسناد المسؤولين بـRBAC وCSRF وIdempotency و`planVersion`، ثم واجهتها واعتماديات المهام. بعد ذلك يلزم تشغيل الترحيل والترقية والرجوع المحروس واختبارات العزل والتزامن على قاعدة فعلية ومتصفح، قبل تفعيل الوحدة أو نشرها.
