# إدارة المشاريع — شريحة الخطة GPM-2

## المنفذ محليًا حتى الآن

- أضيفت جداول مستقلة للمراحل والمهام وإسنادات أعضاء المشروع، مع مفاتيح مركبة تمنع ربط مهمة بمرحلة أو عضو من مشروع أو شركة أخرى، ونسخ لكل سجل وترتيب داخل المرحلة/المشروع.
- أضيفت صلاحية `general_projects.progress` دون تفعيل وحدة `GENERAL_PROJECTS` أو منحها اشتراكًا. ترحيل التراجع يرفض إسقاط الجداول إذا وجدت بيانات أو سجلات إعادة لأوامر الخطة.
- أصبح أمر إكمال المشروع يقرأ حالات المراحل والمهام الفعلية داخل المعاملة، ويرفض الإكمال إذا بقي أي عمل مفتوح. كانت شريحة السجل السابقة تمرر قائمتين فارغتين لأنها لم تكن تملك جداول خطة.

## دليل التحقق وحدوده

- نجح `prisma validate` وتوليد Prisma Client باستخدام عنوان قاعدة شكلي بلا اتصال فعلي، وفحص أنواع API واختباراته.
- نجحت 10 اختبارات سياسة ومخطط موجهة. أضيف اختبار تكامل لإكمال المشروع مع مهمة ومرحلة مفتوحتين؛ لم يُشغّل لأن MySQL/MariaDB المحلي غير متاح على `127.0.0.1:3306`، وهو ضمن أربع حالات DB متجاوزة حاليًا.
- لم تنفذ بعد أوامر إدارة المراحل والمهام والإسنادات أو واجهتها أو اعتماديات GPM-3. لذلك فهذه بنية بيانات وحارس إكمال، وليست ميزة تخطيط تشغيلية أو منشورة.

## البوابة التالية

تنفيذ API محدود للمراحل والمهام وإسناد المسؤولين بـRBAC وCSRF وIdempotency و`planVersion`، ثم عقد OpenAPI والواجهة. بعد ذلك يلزم تشغيل الترحيل والترقية والرجوع المحروس واختبارات العزل والتزامن على قاعدة فعلية ومتصفح، قبل طلب تفعيل الوحدة أو نشرها.
