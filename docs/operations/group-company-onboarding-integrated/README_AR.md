# مرشح محلي مجمّع لخيارات وتشخيص إنشاء شركة المجموعة

## النطاق والحادثة

أُنشئ هذا الفرع من `origin/main` عند `381dfde`، ثم أُعيد تطبيق مرشح فحص عملة البداية (`03ab61b` ← `116f143`) ومرشح التشخيص الآمن (`14ce947` ← `9be7071`). الأصلان محفوظان في الأرشيف غير المدمج، وليس فيهما تغيير منشور. أبلغ المالك بصورة عن رسالة «تعذر تجهيز الشركة وفق إعدادات البداية الحالية» عند اختيار اليمن و`AED` و`Asia/Riyadh` ونشاط إنتاج وتصنيع وقالب خدمات مهنية. لا تكشف الصورة إعداد خطة البداية في الخادم أو حالة الطلب الأول؛ لذلك لا يجوز نسبة الحادثة إلى العملة أو أي خيار آخر استنادًا إليها وحدها.

يجعل مسار الخيارات عملة خطة البداية المؤهلة وحدها قابلة للاختيار، ويفشل مغلقًا بـ`503` إن غاب إعداد الخطة أو أهلية إصدارها أو العملة النشطة المطابقة. يظل فحص الأهلية النهائي داخل معاملة الإنشاء، لأن الخيارات قراءة لحظية. عند `503` المعروف يسجل الموجّه رمز السبب الخادمي ومعرّف الطلب دون اسم الشركة أو الهاتف أو جسم الطلب أو مفتاح التكرار، ويعيد للعميل رمزًا عامًا ومعرّف الطلب. لا يتغير عقد طلب الإنشاء أو سلوك مفتاح التكرار أو بيانات شركة قائمة.

## التحقق المحلي

- اختبارات مركزة على الفرع المجمّع: `108` ناجحة و`10` اختبارات تكامل متجاوزة لأنها تتطلب MariaDB. تشمل أربع حالات HTTP جديدة تمر عبر الموجّه وخدمة الخيارات الفعلية بمنافذ قاعدة مُحاكية: إخفاء `AED` عندما تكون عملة البداية `SAR`، الحفاظ على بقية الخيارات المستقلة، فشل إعداد الخطة أو غياب عملتها من الكتالوج مع معرّف طلب وسبب آمن، ورفض غير المالك قبل قراءة الخطة أو الكتالوج. بيانات اليمن والنشاط والقالب في الاختبار اصطناعية وليست بيانات كتالوج حية.
- نجح فحص أنواع API واختباراتها، وبناء API، و`contracts:check` مع `199` حارس طلب و`2607` حارس استجابة محدثة، واختبار تكافؤ مسارات OpenAPI (`1/1`).
- لا خدمة MariaDB/MySQL أو Docker محلية متاحة؛ لم تُشغّل اختبارات المعاملة والـrollback والتزامن على قاعدة حقيقية، ولم تُقرأ سجلات البيئة التي أنتجت الصورة، ولم يُجر إنشاء شركة حقيقية أو تحقق Staging أو CI بعيد.

## مراجعة المعمارية والحدود

تظل عضوية المنظمة لدى Identity، والشركة والعملة لدى Tenant، وأهلية خطة البداية لدى Platform Subscriptions؛ خدمة التأسيس منسق يقرأ عبر المنافذ ولا يضيف مالك كتابة جديدًا. لا جدول أو ترحيل أو حدث أو Ledger أو اتصال شبكي داخل المعاملة. لا يبدل الفحص الأولي قفل المعاملة أو إعادة التحقق عند الإنشاء. لا أثر باركود لهذه الشريحة.

يبقى بلاغ الصورة P0 مفتوحًا حتى يربط المسؤول، بقراءة مخوّلة، محاولة جديدة أو سجلًا متاحًا بمعرّف طلبها ويحدد رمز الاستجابة وسبب الخادم، ثم يتحقق على قاعدة معزولة من أثر واحد ونتيجة إعادة الطلب بالمفتاح نفسه. لا تُكرر محاولة حية بمفتاح جديد لمجرد ظهور الرسالة، ولا تُعدَل خطة أو كتالوج حي بغير تكليف.

هناك فجوة عقد عامة سابقة: `Problem.requestId` موصوف في OpenAPI بصيغة UUID، بينما `requestLogger` يقبل أيضًا معرفات آمنة غير UUID من `X-Request-ID`. لم تُعدّل ملفات العقد المشتركة لأنها مملوكة حاليًا لمهمة الجرد النشطة؛ يلزم تنسيق تصحيح الوصف أو سياسة المعرّف قبل الدمج البعيد. نجاح `contracts:check` لا يثبت تطابق هذا الحقل الدلالي.

لا push أو PR أو دمج في `main` أو نشر لهذا المرشح. نجاح الاختبارات المحلية لا يثبت سبب الحادثة المصوّرة ولا إصلاحها في البيئة الحية.
