# تشخيص خطأ تهيئة شركة المجموعة

## الفجوة

يعيد موجّه المنظمة `503 COMPANY_SETUP_UNAVAILABLE` للأسباب المعروفة من سياسة خطة البداية أو تهيئة الشركة، وكان يعالج الخطأ قبل بلوغه معالج الأخطاء العام. سجل HTTP يضم معرّف الطلب والحالة فقط؛ لذلك لا يكشف للعمليات إن كان سبب `503` غياب إعداد الخطة أو عدم أهليتها أو فشل تهيئة آخر. صورة المالك لا تحتوي معرّف الطلب أو سجل الخادم، فلا تثبت سبب الحادثة.

## التغيير المحلي

- عند `503` المعروف فقط، يسجل الموجّه حدث `group_company_setup_unavailable` مع `requestId`، اسم العملية، مصدر الخطأ، ورمز السبب المحصور في تعداد الخادم. لا يسجل اسم الشركة أو الهاتف أو جسم الطلب أو مفتاح التكرار أو خطة الاشتراك ومعرّفها.
- يعيد جسم المشكلة `requestId` نفسه الموجود في ترويسة `X-Request-ID` ليسهل على الدعم ربط البلاغ بالسجل. يبقى رمز العميل عامًا؛ لا يُكشف سبب أهلية الخطة للمتصفح. لا يتغير سلوك مفتاح التكرار أو عدد محاولات الإنشاء.
- تبقى أخطاء `409` الخاصة بالمفتاح خارج سجل فشل التهيئة. الأخطاء غير المتوقعة تصل إلى المعالج العام القائم.

## حدود الإثبات

الاختبارات المحلية تثبت شكل الاستجابة والسجل الصناعي وعدم تسرب حقول حساسة فيه. لا توجد في الصورة وسيلة لمطابقة طلب سابق بالحدث الجديد بأثر رجعي، ولم تُقرأ سجلات بيئة حية أو تُنشأ شركة حقيقية. يلزم اختبار رحلة متصلة بقاعدة معزولة قبل اعتماد النشر، ثم ربط بلاغ جديد بمعرّف طلبه بأذونات قراءة تشغيلية مناسبة. لا دفع أو نشر من هذه المهمة.
