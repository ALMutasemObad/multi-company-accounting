# نواة معاينة حساب مسير الرواتب — مرشح محلي

تنفذ `calculatePayroll` حساب مبالغ ثابتة مؤرخة يدخلها نطاق Payroll لاحقًا؛ تجمع الاستحقاقات والاستقطاعات بدقة العملة (0–8 منازل) وتنتج صافيًا وبصمة لقطة حتمية. لا تخزن رواتب ولا تنشئ مسيرًا تشغيليًا أو اعتمادًا أو قيدًا أو ملف دفع. يمنع اعتبارها حاسبة استحقاقات نظامية أو خدمة جاهزة للإنتاج.

لا تستنتج خصمًا من الحضور أو الغياب، ولا تحسب التأمينات أو العمل الإضافي أو الإجازات أو نهاية الخدمة. بيانات الإدخال يجب أن تأتي مستقبلًا من اتفاقات تعويض مصرح بها ومكونات ذات ملكية وصلاحيات، لا من العميل مباشرة. البصمة ليست إذن دفع أو ترحيل.

## قيد الإطلاق السعودي

- لا تُحوَّل سجلات البصمة أو ملاحظة المشرف إلى خصم آلي؛ يجب إثبات السند النظامي/التعاقدي وموافقة العامل حيث تلزم، ومراجعة حدود الحسم قبل اعتماد سطر الاستقطاع. راجع [شروط العمل وظروفه — وزارة الموارد البشرية](https://www.hrsd.gov.sa/%D8%B4%D8%B1%D9%88%D8%B7-%D8%A7%D9%84%D8%B9%D9%85%D9%84-%D9%88%D8%B8%D8%B1%D9%88%D9%81%D9%87).
- لا تُثبَّت نسبة تأمينات واحدة في المحرك: تختلف القواعد بحسب انطباق النظام القديم أو الجديد وتاريخ الالتحاق؛ يلزم محرك سياسة مؤرخ وبيانات أهلية موثقة. راجع [المشمولين في النظام الجديد — التأمينات الاجتماعية](https://awareness.gosi.gov.sa/businessJourney.html).
- إنشاء لقطة حسابية أو قيد مستحقات لا يساوي صرف الأجر أو الامتثال لحماية الأجور؛ ملف الأجور والتسويات يخضعان لمسار «مدد» مستقل. راجع [رفع ملف حماية الأجور — وزارة الموارد البشرية](https://www.hrsd.gov.sa/ministry-services/services/%D8%B1%D9%81%D8%B9-%D9%85%D9%84%D9%81-%D8%AD%D9%85%D8%A7%D9%8A%D8%A9-%D8%A7%D9%84%D8%A3%D8%AC%D9%88%D8%B1).

قبل Migration/واجهة تشغيلية يلزم إغلاق البوابات السبع في `docs/architecture/PAYROLL_FOUNDATION_SLICE_AR.md`: ADR الملكية والترحيل، سياسة دولة مؤرخة، الخصوصية والاحتفاظ، ملف الحسابات، التجزئة والتصحيحات، مراجعة build/adopt، وقرار الدفع البنكي المنفصل. عند التطبيق لا تُرحّل قيود الرواتب إلا عبر Core Accounting PostingEngine، ويختبر التزامن على MySQL وMariaDB.

وضع هذا المرشح: كود واختبارات وحدة محلية فقط، غير مدمج وغير منشور. نظام إدارة المشاريع العامة لا يعتمد عليه.
