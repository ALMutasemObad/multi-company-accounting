## الدليل والفجوات المغلقة

على الأساس، فشل اختبار الهاتف `review is required before any subscription POST`
كما هو متوقع: زر النموذج كان ينفذ POST مباشرة دون عرض مراجعة. أكد فحص المصدر
توليد مفتاح جديد داخل كل submit ووجود await load داخل try الأمر نفسه.
اختبار baseline الأحمر شُغل قبل تعديل شيفرة الصفحة، لا بعده.

الشيفرة الآن:

- مراجعة منفصلة، ثم مربع إقرار وزر تأكيد صريح. تغيير الخطة/الإضافات أو إعادة
  الكتالوج يبطل المراجعة. بصمة المراجعة تشمل تعريف الخطة والاختيارات ونسخة
  الاشتراك؛ فحص متزامن آخر قبل الإرسال يمنع إرسال مراجعة قديمة.
- رسوم الأساس والوحدات الاختيارية وأسعار المستخدم/الموظف/المستند والعملة
  والدورة ونسبة الضريبة معروضة منفصلة من قيم الكتالوج النصية الدقيقة.
  `null` غير مهيأ ولا يعني مجانيًا. لا مجموع أو خصم أو proration أو مبلغ
  ضريبة أو سعر نهائي مستنتج؛ الخادم مصدر القرار والحساب والسريان.
- هوية المحاولة والجسم ونسخة الاشتراك immutable، وجميع أجزاء المراجعة منفصلة
  عن كائن الكتالوج ومجمدة. يرسل الجسم فقط targetPlanVersionId وoptionalModuleIds
  وsubscriptionVersion، دون أسعار أو ضرائب محسوبة من العميل.
- قفل ref متزامن قبل render يمنع النقر المزدوج. timeout20s صريح لهذا الطلب
  فقط عبر API القائم، وزر إيقاف انتظار. لا يعتبر أي منهما rollback للخادم.
- انقطاع الشبكة وفقد body وtimeout/cancel و5xx وIDEMPOTENCY_IN_PROGRESS أو
  IDEMPOTENCY_MISMATCH نتائج غير مؤكدة. لا تكرار تلقائي؛ إعادة الإرسال اليدوية
  الواضحة تستعمل هوية وجسم المحاولة نفسيهما، حتى بعد GET بنسخة اشتراك أحدث.
- تعارض409 النهائي مختلف عن الرفض4xx، ويطلب قراءة الحالة ومراجعة جديدة؛ لا
  إعادة إرسال تلقائية أو تبديل نسخة/مفتاح صامت. 429 رفض قابل للمراجعة لا retry.
- POST المقبول ثم GET الفاشل يبقى قبولًا معروفًا، مع زر GET-only؛ لا يظهر زر
  إعادة POST. القبول لا يسمى تطبيقًا فوريًا؛ pending يبقى بانتظار موافقة،
  وتعرض pending وscheduled منفصلين عند وجودهما معًا.
- قراءات snapshot/catalog بمهلة12s وجيل وإلغاء؛ لا تظهر استجابة شركة مختلفة
  إذا حملت الاستجابة هوية company. تبديل النشاط/المستخدم/صلاحية الإدارة يعيد
  تركيب الجسم المعزول، ويلغي انتظار القراءة/الكتابة ويهمل النتيجة المتأخرة.
- محاولات غير محسومة محفوظة في Map داخل الذاكرة فقط، scoped بـactor+company،
  ولا تضيع عند التنقل داخل التطبيق ثم الرجوع. لا localStorage/sessionStorage
  جديد ولا CSRF/PRE_AUTH refresh. يبقى API المشترك وحده ناقل CSRF الحالي.
- لا تختفي نية الخطة المفقودة لصالح خطة بديلة، ولا استرجاع ضمني من صفحة أخرى.
  pagination باقية100 خطة و20 تاريخًا لكل طلب؛ لا تحميل كل الصفحات. اختيار
  الاعتماديات وإزالة التابعين باقٍ، وتغير تعريف الخطة يمسح الإضافات القديمة
  حتى لا تُرسل IDs لم تعد المراجعة تعرضها.
- ترجمة النصوص الجديدة للعربية والإنجليزية والأردية والهندية، RTL/LTR،
  تأكيد بلوحة المفاتيح، وأزرار بارتفاع44px وتفاف على الهاتف. عنوان المراجعة
  يأخذ التركيز مع هامش تمرير عن الشريط العلوي المثبت.

كان الاختبار يضغط زر GET ثم ينتهي قبل قراءة الرد. أضيف انتظار صريح لاكتمال

الدرج المشترك الذي يبقى مفتوحًا بعد التبديل؛ عولج الاختبار بإغلاق زر scrim
عبر لوحة المفاتيح. لم يُعدل App أو CSS مشترك.

المصفوفة الأولى غطت الأربع لغات لكل من المراجعة/القيم الدقيقة/الإقرار،
نجاحpending، فقد الشبكة مع replay يدوي ثابت، نجاحPOST ثم فشلGET،409، وإلغاء
الانتظار مع استجابة متأخرة. غطت أيضًا timeout/remount، التفضيل المفقود،
الاعتماديات، والصلاحيات. الاختبارات الحالية تحتوي60 حالة متصفح متاحة لإعادة
التحقق، لكن **لم تشغل الستون مجتمعة على النسخة النهائية** بسبب قرار الموارد
من المنسق؛ لا يُدّعى60/60 أو مصفوفة نهائية كاملة.

التقطت الجولة الأولى8 صور للمراجعة، وفُحصت العربية390 بصريًا: النص والأسعار
كاملة بلا تمدد أفقي، مع تداخل الشريط المثبت في أعلى لقطة العنصر. أعقب ذلك
تحسين focus/scroll-margin. مجلد output المحلي يُعاد استعماله من Playwright؛
لا تعد الصور القديمة مخرجات نهائية محفوظة ولا تدعي تحققًا بصريًا شاملًا
للنسخة النهائية. تعطلت صور الفشل/video/trace في إعداد D النهائي.

## الموارد وإعادة التحقق

استُخدم Node من المسار المحدد في عقد الأربعة، واعتماديات junction للقراءة
فقط. لا install/ci/prune/update أو prisma generate أو نسخة dependencies.
المنافذ3134/4184، strictPort، reuseExistingServer:false وworker1 وretries0.
الكاش محلي `apps/web/node_modules/.cache-track-d`، وليس داخل junction.

انخفض C إلى نحو351MiB أثناء الجولة الأولى؛ أُبلغ المنسق ولم تُحذف أو تُنقل
ملفات ولم توقف عمليات الآخرين. بعد إذنه، عُيّن TEMP/TMP لعملية الاختبار
الأخيرة فقط إلى مجلد `track-d-temp` الذي أنشأه على D؛ ومخرجات آخر نجاح تحت
`track-d-results/business-switch-final` في مسار الآثار الذي حدده المنسق.
هذا override تشغيلي وليس مسارًا مثبتًا في إعدادات المستودع.

## القيود وقرار الدمج

- Map ليس تخزينًا دائمًا: إغلاق/إعادة تحميل المتصفح يفقد الهوية. يحذر العرض
  من ذلك صراحةً ويطلب مراجعة السجل مع المسؤول قبل محاولة جديدة عند فقدها.
  لا endpoint مؤكد لاسترجاع نتيجة محاولة بهويتها في العقد الحالي؛ GET الحالة
  وحده لا يُزعم أنه يحسم نجاح طلب غير معروف، لذلك لا يمسح uncertain.
-20s/12s ميزانيتا انتظار UI، ليستاSLO أو دليل إلغاء Query/Transaction فعلي.
- نتائج fixtures وطلبات Playwright لا تثبت معاملةDB أو دفعًا أو بريدًا حقيقيًا.
  لا اختباراتMariaDB10.11/MySQL8.4 ولا build كامل جديد في D؛ تبقى بوابات
  الإصدار وصلاحيات الدمج/النشر منفصلة.
- لم تُضف تبعية أو SDK أو كتاباتLedger/Prisma أو أحداث/Outbox أو قواعد مالية
  جديدة. المالك Platform Subscriptions & Entitlements باقٍ، وRBAC وcompany
  isolation وCSRF وidempotency وoptimistic version تُحكم خادميًا.
- Barcode Impact: غير منطبق؛ لا صنف أو بنود مستند أو طباعة/تصدير في هذه الشريحة.

يلزم للمنسق إعادة مصفوفة D المتاحة كاملة على commit التكامل عندما تسمح
الموارد، وفحص بصري نهائي للأربع لغات بعد دمج D/E، ثم بوابات الإصدار المعتادة.
