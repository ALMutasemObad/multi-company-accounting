# أربعة وكلاء — أمان دورة الاشتراك وقابليتها للقياس

طلب المستخدم بدء مهمة كبيرة بعد إغلاق العمل الحالي وتوزيعها على أربعة وكلاء.
أُغلق التكامل المحلي السابق عند `a7b1b4f`، على شيفرة `bfdc1d1` اجتازت260 فحص
متصفح و523 API و116 Web و55 Infra. بوابتا MariaDB10.11/MySQL8.4 لم تُشغلا؛
الإغلاق المحلي ليس إذن دمج أو نشر. طُلب إذن PR مسودة لتشغيل CI ولم يصل بعد.

المهمة الجديدة: إكمال أمان الاستخدام التشغيلي للاشتراكات من مراجعة التغيير إلى
تعافي الدفع عند الانقطاع، مع تقليل كلفة القراءة وإضافة قياس قابل للإعادة.
لا أسعار جديدة أو تحصيل حقيقي أو تغيير سياسة تجربة/تجديد/فوترة أو CRM.

الحد المتاح أربعة وكلاء شاملًا المنسق؛ يعمل المنسق في المسار G وثلاثة وكلاء
بالتوازي في D/E/F. لا وكلاء إضافيون أو محادثات أخرى ضمن هذه الدفعة.
فرع المنسق `feat/subscription-operational-readiness` في نسخة
`project-public-subscription-plans`؛ بقي الفرع السابق ثابتًا عند تسليمه المستقل.

## D — مراجعة صريحة وتغيير قابل للتعافي

- ثبّت بالاختبار الفجوة: التغيير الحالي يرسلPOST مباشرة ويولد مفتاحًا جديدًا لكل
  محاولة، ولا يفرق بين نجاح الأمر وفشل GET الذي يليه. لا توسع المجال بلا دليل.
- أضف مراجعة/تأكيدًا صريحًا للخطة المختارة والإضافات والدورة والعملة والرسوم
  والضريبة كقيم منفصلة دقيقة. لا مجموع/خصم/proration أو التزام سعر مخترع؛
  الخادم مصدر الحساب والقبول النهائي. أي تغيير بالاختيار/نسخته يبطل المراجعة.
- احتفظ بهوية محاولة واحدة والجسم/النسخة الأصليين عند نتيجة غير مؤكدة؛ لا تعِد
  POST تلقائيًا. إن أتحت تكرارًا يدويًا فليكن للمحاولة نفسها وبالمفتاح نفسه،
  ولا تعِد توليده سرًا. افصل رفض الأعمال والتعارض عن انقطاع الشبكة.
- مهلة/إلغاء انتظار opt-in، منع مزدوج متزامن قبل render، تجاهل الاستجابات
  المتأخرة بعد unmount/تغير النشاط. نجاحPOST ثم فشل reload يعيد GET فقط.
- حافظ على اختيار الكتالوج المفقود والصفحات المحدودة والتبعيات والـCSRF/RBAC.
  لا تتجاهل pending/scheduled ولا تفترض التطبيق النهائي من حالة غير مؤكدة.
- أربع لغات، RTL/LTR، لوحة مفاتيح، لمس،390/1440، واختبارات طلبات وتأخر/409/500
  ونجاح/reload ونية الباقة. لا تعديل للوحة الدفع أو للاستهلاك أو العميل المشترك.

## E — تعافي الدفع وفصل مركز الفوترة

- ابدأ من المكون المفصول؛ لا تعدل CompanySubscriptionPage أو payment helpers
  المشتركة. افحصcheckout/cancel/retry القائمة وحدد عيوب السباق/الانتظار بالأدلة.
- أوقف ازدواج الأوامر بهوية محاولة ثابتة حسب النشاط/المورد/الأمر والجسم/النسخة؛
  لا replay تلقائي، ولا مفتاح جديد لمحاولة مجهولة المصير. التعارض يطلب مراجعة
  أحدث حالة، لا كتابة صامتة. لا تفترض الفشل يعني عدم التحصيل.
- افصل نجاح الأمر عن فشل تحديث القوائم؛ أتح قراءة تعافٍ دون إعادة الدفع أو
  الإلغاء. لا تفتح checkout من استجابة متأخرة بعد المغادرة أو تخص نشاطًا سابقًا.
- قراءات القوائم بمهلة وإلغاء وعزل الجيل، وصفحات خادمية موجودة، دون تحميل الكل.
  لا إلغاء جلسة مصرفية/دفعة حقيقية من الاختبار؛ fixtures ومزود development فقط.
- لا تغير قبولURL أو مزود/مفاتيح دفع/استرداد/ثقةwebhook. أي فجوة خادم ترفع
  للمنسق قبل الكتابة. الاختبارات تشمل فقدbody، نجاح ثم فشلreload،429،409،تغير
  النشاط،النقر المزدوج،الأربع لغات و390/1440. لا بيانات بطاقات أو سر في التخزين.

## F — قراءة الاستهلاك دون عدّ غير مستخدم

- الدليل الحالي: companyUsage يحسب users/employees/documents وAudit operations،
  بينما GETusage لا يعرض الرابع. افصل Port قراءة ضيقًا للحصص الثلاث دون نسخ
  تعريف العدادات؛ يجب أن يعيد billing.companyUsage نتائجها الأربعة نفسها.
- أبقِ تعريف المستخدم النشط/الموظفACTIVE أوON_LEAVE/postedAt gte-lt مطابقًا
  حرفيًا. لا تحويل الفترة الإحصائية إلى دورة مؤكدة ولا تغييرDecimal/رسوم/حظر.
- حافظ على lookup وجود الشركة والعزل والخطة الأحدث المعتمدة والإسقاط المحدود.
  لا cache حصة حساس أو array من السجلات أو جدول عدادات بديل.
- أضف اختبارات تمنع استعلامaudit غير المستعمل فيusage وتثبت عدم تغيّر مسار
  الفوترة، والعزل والأعداد الكبيرة وحدودالفترة. افحص عدم بدء قراءات إضافية بعد
  انتهاء مهلة/انقطاع الطلب في المحول ضمن قدرات البنية القائمة، دون ادعاء إلغاء
  Query في DB لمجرد انتهاءPromise.
- تجنب تعديل واجهة Port قائمة بما يكسر بقيةmock factories؛ قدم Port جديدًا
  ضيقًا أو عقدًا متوافقًا بالتنسيق. لا تغييرOpenAPI مطلوب مبدئيًا.
- دوّن عدد الاستعلامات قبل/بعد وحدود القياس. اختباراتcount وهمية ليست benchmark
  DB ممثلًا، ونجاح المحلي لا يغني عن10.11/8.4.

قرار تنسيق إضافي: مُنح F ملكية محدودة لـ`subscription-usage-plan-adapter.ts`
لوضع فحص request deadline/disconnect قبل lookup وبين lookup وfindFirst فقط،
مع اختبارات تثبت عدم بدء الاستعلام التالي. لا تغيير إسقاط الخطة أو ترتيبها أو
دلالة الفترة. المنفذ الجديد المعتمد `PlatformCompanyQuotaUsageQueryPort` مستقل
عن `PlatformAnalyticsQueryPort` القديم. يعدّ الاختبار استدعاءات Prisma المنطقية،
ولا يسميها SQL statements مقاسة أو نسبة تحسن سرعة.

## G — القياس والتكامل

- أداة قياس قراءة محدودة قابلة للإعادة للمسارات العامة/اشتراك النشاط، آمنة
  افتراضيًا: loopback فقط، GETallowlist، حدطلب/تزامن/مدة، إيقاف عندpressure،
  لا cookies أوtoken أوpayload أوquery حساس في التقرير. لا حمل على الاستضافة.
- تقرير latency/توزيعالأخطاء/الحجم والإعدادات، واختبارات إحصائية وسلامة للأداة.
  لا SLO أو سعةPool نهائية مخترعة، ولا نسبة سرعة محسوبة من fixture.
- مراجعة جميع التسليمات، ربط الرحلة واختبارات CI الحالية، وموازنة الموارد.
  أي عقد مشترك/generated أو app/server أو main locale يغير مركزيًا فقط.

## التسليم

وسلمcommits محلية صغيرة وhandoff تتضمن الأوامر والأرقام والحدود. لا Push/PR/
Merge/Deploy من الوكلاء. لا تغييرات استضافة أو بريد أو دفعات حقيقية. تبقى
بوابتاDB وتفويضالإصدار منفصلين عن نجاحالاختبارات المحلية.
