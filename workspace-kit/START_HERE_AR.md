# ابدأ من هنا — إدارة النظام المالي

## المرجع المعتمد

مصدر الكود المقبول هو `main` في مستودع `ALMutasemObad/multi-company-accounting`.
نسخته المحلية المرجعية الوحيدة هي مجلد `project`؛ يبقى نظيفًا على `main` ولا تستخدمه لتنفيذ مهام متوازية.
`WORKSPACE.json` هو سجل المسارات والمهام والإصدار المتحقق منه. `COORDINATION_STATUS_AR.md` عرض مولّد منه، وليس سجلًا ثانيًا مستقلًا.
لا تعتبر أي مجلد باسم موجة أو أي مستند تسليم تاريخي مصدرًا أحدث لمجرد اسمه.

## أين يوجد كل شيء؟

| المكان | وظيفته |
|---|---|
| `project` | النسخة المرجعية من main |
| `.worktrees` | ثلاث مهام تنفيذ نشطة كحد أقصى، لكل مهمة فرع مستقل |
| `tools/workspace` | أدوات الفحص وبدء المهام وإغلاقها ودليل CI |
| `business-documents` | العروض والتقارير، منفصلة عن الكود |
| `_workspace_archive` | المسارات القديمة على C، والتسليمات التاريخية، ونسخة Git الاحتياطية |
| مسار أرشيف D المسجل في `WORKSPACE.json` | المسارات القديمة الموجودة أصلًا على D |

مجلد Git الحقيقي يبقى داخل `project/.git`؛ لا تنقله أو تحذفه. الأرشيف يشترك معه في التاريخ، لذلك نقل الأرشيف وحده إلى جهاز آخر لا يصنع مستودعًا مستقلًا.

## بداية أي جلسة

من هذا المجلد، في PowerShell:

```powershell
. ./tools/workspace/Enter-Workspace.ps1
./tools/workspace/Workspace.ps1 -Action Check -Refresh
```

إذا فشل الفحص، عالج السبب قبل التنفيذ. لا تستخدم reset أو الحذف لتجاوز فشله.
Git موجود بالفعل ضمن أدوات الجهاز؛ الملف الأول يضيف مساره للجلسة الحالية فقط، دون تغيير إعدادات مشاريع أخرى.
يتطلب المشروع Node وفق `package.json` ونسخة npm المثبتة فيه. غياب npm عن جلسة ما لا يبرر استخدام مدير حزم مختلف أو مشاركة Prisma المولّد من فرع آخر.

## إسناد مهمة وتنفيذها

1. يحدد المدير الأولوية والمسؤول ونطاق الملفات ومعيار القبول؛ المهمة الواحدة نتيجة صغيرة قابلة للعرض والاختبار.
2. ابدأ من main المتحقق منه بالأداة، لا بنسخ مجلد سابق:

```powershell
./tools/workspace/Workspace.ps1 -Action Start -Refresh -Id crm-next -Owner 'مسؤول CRM' -Priority P1 -Scope 'apps/web/src/crm' -Acceptance 'رحلة مستخدم محددة مع اختبار العزل والواجهة'
```

هذا مثال فقط، وليس إسنادًا قائمًا. ترفض الأداة تجاوز ثلاث مهام أو تداخل نطاقات الملفات المعلنة أو وجود worktree غير مسجل.
الالتزام بالنطاق أثناء تعديل الملفات مسؤولية المراجعة؛ الأداة لا تمنع محررًا خارجيًا من الكتابة في ملف.
لكل مهمة تثبيت اعتماد مستقل من ملف القفل؛ يسمح بمخزن تنزيلات مشترك، ولا يسمح بوصلات `node_modules` مشتركة بين المهام النشطة.
لا تثبّت اعتمادًا لمهمة توثيقية لا تحتاج تشغيل التطبيق.

3. تسجل المهمة الالتزام النهائي وأوامر الاختبار ونتائجها والقيود الباقية. بعد حفظ الملفات في commit ونظافة الفرع، استخدم `Workspace.ps1 -Action MarkReady -Id اسم-المهمة` لتسجيل الالتزام وحالة انتظار المراجعة. نجاح واجهة تجريبية لا يثبت تكامل قاعدة البيانات.
4. يراجع المدير النتيجة والفروق، ويسلسل تعديل العقد والترحيلات وملف القفل، ثم يطلب إذن النشر إن كان مطلوبًا. لا تمنح هذه القواعد إذن push أو PR أو نشر.
5. بعد قبول النتيجة أو قرار إيقافها، أغلق المهمة بالأداة. الإغلاق يحفظ كل الملفات ويصنفها `archived-unmerged`؛ لا يزعم دمجها:

```powershell
./tools/workspace/Workspace.ps1 -Action Close -Id crm-next
./tools/workspace/Render-Status.ps1
```

عند تغير main: تحقق من النشر والالتزام وCI، ثم حدّث النسخة المرجعية بـfast-forward فقط وحدث سجل `WORKSPACE.json` تحت إدارة واحدة. أعد توليد التقرير وشغل الفحص. لا تحدّث الالتزام المنشور تلقائيًا بمجرد fetch.

## ما حُفظ وكيف نستعيده؟

- `inventory-before.json` يسجل كل المسارات الأصلية والجديدة والفروع والرؤوس وحالات Git وبصمات الملفات المعدلة وغير المتتبعة.
- `repository-before.bundle` نسخة متحقق منها من تاريخ Git والفروع. **لا يتضمن الملفات غير المحفوظة أو المتجاهلة**؛ هذه باقية داخل المجلدات المؤرشفة. الملفان غير المتتبعين اللذان كانا في `project` محفوظان في `_workspace_archive/uncommitted/project`.
- تبقى أدلة الاختبار والاعتمادات والملفات المحلية داخل الأرشيف. لا تُرفع حزمة الأرشيف أو ملفات البيئة إلى GitHub.
- للاستعادة: حدد الفرع/الملف من الجرد، أنشئ مهمة جديدة من main، ثم قارن واستورد التغيير المطلوب مع اختباره. لا تستأنف المهمة القديمة في مسارها المنقول ولا تنسخ بيئتها التشغيلية.
- المساحات القديمة مقفلة لدى Git لمنع نقلها أو إزالتها بالخطأ؛ القفل لا يمنع محرر الملفات من الكتابة. المراجعة مطلوبة قبل أي تغيير فيها.
- فحص سلامة النقل: `./tools/workspace/Contain-Workspace.ps1 -Action Verify`.

## الأولويات التالية

1. إتمام مراجعة حزمة تصحيح وثائق الحالة محليًا؛ لا تخلطها بإصدار ميزات أو نشر تلقائي.
2. فرز التغييرات القديمة غير المدمجة بمقارنتها بـmain؛ لا تدمجها جماعيًا ولا تفترض أن الفرع النظيف مدمج.
3. قبل موجة ميزات جديدة: اختيار نتائج المستخدم ذات الأولوية، وإسناد ثلاث مهام على الأكثر بمعايير قبول محددة.
4. لاحقًا: تقليل حجم الاعتماد والأرشيف بعد إثبات قابلية الاستعادة، وأتمتة تحديث سجل الإصدار من CI مع مراجعة الدليل. لم ننفذ حذفًا لاستعادة مساحة القرص في هذه الجولة.

الفجوات الوظيفية مثل الرواتب والأصول الثابتة والتجميع المالي وفحص التعارضات تبقى خطط منتج مستقلة، وليست أعطال تنظيم تُحل بنقل المجلدات.
